# Как внести вклад

Проект принимает изменения кода и справочных материалов отдельно. Код проходит технические проверки, а статья — ещё и редакторскую проверку источников, семантической связи с нодой и лицензии.

## Подготовка окружения

Нужны Python 3.10+ и Node.js 20.19+.

```text
npm ci
python tools/catalog.py ci
npm run typecheck
npm run test -- --run
npm run build
```

Не смешивайте в одном pull request массовую перегенерацию каталога, рефакторинг интерфейса и редактуру статей: такой diff трудно проверить и безопасно откатить.

## Правка статьи

1. Используйте канонический `node_id` из инвентаря ComfyUI. Видимое имя подходит для заголовка, но не для ключа связи.
2. Укажите проверенный источник поведения ноды и версию или commit ComfyUI, по которым написан текст.
3. Объясните назначение, входы, выходы, типичные связи и ограничения. Не выдавайте наблюдение за гарантированный контракт.
4. Для переименованной или удалённой ноды добавьте статус, алиас или преемника. Не переносите статью на похожую ноду только по совпадению названия.
5. У каждого стороннего workflow, изображения и фрагмента текста должны быть автор, исходный URL и лицензия, разрешающая включение в CC BY-SA-каталог.
6. Запустите `python tools/catalog.py validate`, затем `python tools/catalog.py build` и `python tools/catalog.py build --check`.

Новый материал начинает с `status: "draft"` и `editorial.state: "in_review"`. Автоматическая сверка схем, источников и стиля не считается человеческим утверждением. Только указанный человек-рецензент после повторной проверки может поставить `editorial.state: "approved"`, записать своё имя и перевести статью в `active`; для рецепта действует то же правило.

Текст пишется по-русски, простыми предложениями и с точной терминологией ComfyUI. Оставляйте английские идентификаторы там, где пользователь увидит их в интерфейсе или JSON. Не копируйте официальную документацию большими фрагментами; перескажите проверенный смысл и дайте ссылку на источник.

## Обновление инвентаря ComfyUI

Зафиксируйте ответ `/object_info` из чистой контрольной установки ComfyUI и запишите точную версию источника. Не используйте личный рабочий профиль: список custom nodes может содержать приватные названия.

Сначала сравните снимки:

```text
python tools/catalog.py diff --before old-object-info.json --after new-object-info.json
```

После этого вручную классифицируйте изменения:

- новая нода — создать новую запись и, при готовности, статью;
- изменившаяся сигнатура — проверить примеры и описание портов;
- переименование — сохранить старый идентификатор как алиас только при доказанной связи;
- удаление — отметить устаревание, но не удалять историю без причины;
- замена — связать преемника и объяснить миграцию.

Nightly workflow поднимает чистую стабильную версию ComfyUI без custom nodes, читает локальные `/object_info`, `/api/node_replacements` и `/system_stats`, а затем формирует diff и отчёт покрытия. Отчёт сохраняется как временный артефакт GitHub Actions. Задача не коммитит снимки, не меняет статьи и не публикует пакет; сбой тяжёлой upstream-проверки не блокирует обычный CI.

## Изменения интерфейса

Сохраните работу в пределах frontend API ComfyUI. Не меняйте глобальные прототипы без обратимого cleanup, не перехватывайте очередь и не создавайте серверные маршруты для клиентской функции.

Для каждого изменения проверьте:

- пункт контекстного меню у ноды с известной статьёй;
- fallback у неизвестной и удалённой ноды;
- поиск с русским и английским запросом;
- клавиатурный фокус, закрытие диалога и читаемость узкого окна;
- очистку Markdown и блокировку опасных ссылок;
- отсутствие сетевых запросов при обычном просмотре.

## Pull request

В описании укажите, что изменилось, как это проверялось, версию ComfyUI и источники контента. Для визуальных изменений приложите снимок интерфейса. Для изменения каталога перечислите затронутые `node_id` и поясните миграцию алиасов.

Не включайте токены Registry, cookies, локальные пути, дампы workflow пользователей и необработанные снимки приватной установки. Об уязвимости сообщайте по процедуре из [SECURITY.md](SECURITY.md), а не через публичный issue.
