# MarkdownNote: форматированная памятка в workflow

`MarkdownNote` хранит пояснение прямо на холсте и показывает его с форматированием. В заметке можно сделать заголовки, списки, ссылки, таблицы и блоки кода. Такой текст удобно оставлять рядом с загрузчиками моделей, группой параметров или необязательной веткой графа.

Нода не передаёт данные и не выполняется на сервере. У неё нет входов и выходов. При сохранении workflow frontend записывает текст в `widgets_values`, поэтому памятка открывается вместе с графом.

## Чем MarkdownNote отличается от Note

`MarkdownNote` отображает разметку, а `Note` оставляет текст обычным. Строка `**модель обязательна**` станет полужирной в MarkdownNote, но останется строкой со звёздочками в Note. Для короткого предупреждения без оформления достаточно Note; для инструкции со структурой лучше MarkdownNote.

В classic canvas обе ноды регистрирует расширение `Comfy.NoteNode`. Для MarkdownNote оно создаёт виджет `MARKDOWN`, включает сохранение значений виджета и помечает ноду как виртуальную. В Nodes 2.0 тот же тип входит в `SYSTEM_NODE_DEFS`; Vue-виджет показывает отрендеренный текст, а по двойному щелчку переключается в редактор.

## Что происходит при запуске

Перед отправкой задания frontend обходит виртуальные ноды. Если у виртуальной ноды есть действие над графом, он вызывает его, а затем исключает саму ноду из API prompt. У MarkdownNote такого действия нет: её содержание влияет только на сохранённый workflow и вид холста.

Это различие полезно при диагностике. Если backend сообщает об ошибке генерации, текст MarkdownNote не мог изменить модель, conditioning или latent. И наоборот, удаление заметки не исправит исполняемую ветку — оно удалит только документацию.

## Реальные применения в официальных шаблонах

В wheel `comfyui-workflow-templates-json 0.1.42` MarkdownNote встречается в сотнях официальных шаблонов. В workflow `3d_hunyuan3d-v2.1` с ID `4125c6df-9bca-430d-8e85-7cff9cc592d4` нода № 15 содержит ссылку на checkpoint и дерево папок, куда его положить. Другие шаблоны используют MarkdownNote для таблиц разрешений, ссылок на руководства и пояснений к параметрам.

Это хороший ориентир для собственного графа: записывайте не общие пожелания, а сведения, без которых другой человек не воспроизведёт workflow. Например:

```markdown
## Перед запуском

- установите `model.safetensors` в `ComfyUI/models/checkpoints`;
- выберите модель в ноде-загрузчике;
- оставьте ширину кратной 64.
```

Пример «Оформить памятку для workflow» добавляет такую ноду в отдельный учебный workflow. В структурированном fragment сохранены роль и исходный Markdown; это описание состава примера, а не обещание вставить произвольный JSON прямо в текущий граф.

## Частая ошибка: ожидать исполняемый выход

MarkdownNote нельзя соединить с `STRING`-входом другой ноды. Текст заметки не является строковым выходом и не подставляется в prompt. Если нужен один редактируемый `STRING` для нескольких виджетов, используйте `PrimitiveNode` и подключите его к совместимым widget-входам.

Вторая типичная путаница — редактирование одного щелчка. В Nodes 2.0 одиночный щелчок выбирает ноду или область текста, а двойной открывает редактор. После потери фокуса виджет снова показывает отформатированный результат.

## Сериализация и переносимость

Сохранённая запись содержит обычные поля ноды — `id`, `type`, позицию, размер, свойства и `widgets_values`. Сам текст переносим вместе с workflow. Внешние ссылки из Markdown при открытии требуют сети, а локальный путь вроде `ComfyUI/models/checkpoints` остаётся лишь инструкцией: нода не скачивает и не перемещает файлы.

`MarkdownNote` отсутствует в `/object_info`, потому что этот endpoint описывает исполняемые серверные ноды. Nodes Wizard связывает статью с точным frontend-типом `MarkdownNote` из пакета `comfy-core` и не считает его удалённым из-за отсутствия в backend inventory.
