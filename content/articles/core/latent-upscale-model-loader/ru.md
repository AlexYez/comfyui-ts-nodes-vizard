# LatentUpscaleModelLoader: модель увеличения латента

## Назначение

Нода загружает отдельную модель пространственного увеличения латента и возвращает тип `LATENT_UPSCALE_MODEL`.

## Место в графе

Для Hunyuan Video 1.5 подключите выход к `HunyuanVideo15LatentUpscaleWithModel`. Тот же loader встречается в LTX-графах, но там модель потребляет другая нода.

## Вход

`model_name` выбирается из каталога `latent_upscale_models`. В чистом проверочном runtime список пуст, поскольку веса не установлены; после установки варианты появляются динамически.

## Выход

Выход — загруженный объект модели, а не `MODEL` диффузии. Он предназначен только для нод, принимающих `LATENT_UPSCALE_MODEL`.

## Как работает

Файл читается через safe loader вместе с metadata. Архитектура определяется по ключам state dict, после чего создаётся одна из двух Hunyuan-моделей либо общий LTX `LatentUpsampler`.

## Распознаваемые архитектуры

Ключ `blocks.0.block.0.conv.weight` выбирает Hunyuan 720p; `up.0.block.0.conv1.conv.weight` — Hunyuan 1080p. Ключ `post_upsample_res_blocks.0.conv2.bias` ведёт к конфигурации LTX из JSON metadata.

## Проверенный пример

В 18 официальных экземплярах loader используются Hunyuan 1080p и несколько поколений LTX x2-upscaler. Общий рецепт Wizard повторяет Hunyuan-файл как внешнее требование, не подставляя его при отсутствии.

## Ошибки и диагностика

Неизвестная структура не назначает `model`, что приводит к ошибке при возврате. Повреждённый config metadata ломает LTX-ветку. Ошибка пути означает, что файл отсутствует в зарегистрированном каталоге.

## Ограничения и производительность

Loader не проверяет совместимость модели с последующей нодой по имени. Большие веса занимают память после загрузки; LTX-ветка использует patcher с устройствами загрузки и offload.

## Совместимость и источники

Проверено по ComfyUI 0.32.0, frontend 1.48.7, исходнику, docs 0.5.9 и 18 официальным случаям 0.1.42. Реальные веса не загружались; человеческое утверждение ожидается.
