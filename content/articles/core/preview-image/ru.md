# Preview Image: временный просмотр результата

`PreviewImage` показывает `IMAGE` в интерфейсе после выполнения графа. Для этого нода сохраняет PNG во временный каталог ComfyUI и передаёт сведения о файле frontend. Тот же `IMAGE` возвращается через выход `images`, поэтому после preview цепочку можно продолжить.

## Назначение и границы

Preview нужен для визуальной проверки, а не для долговременного хранения результата. Файл относится к типу `temp`, и ComfyUI может очистить его независимо от workflow. Если изображение должно остаться как артефакт запуска, добавьте отдельный `SaveImage`.

## Когда она нужна

Ставьте `PreviewImage` в точку, где нужно увидеть промежуточный или финальный результат, но не требуется хранить его в папке `output`. Это удобно при подборе маски, проверке декодирования, сравнении этапов обработки и отладке длинного workflow.

Для результата, который должен сохраниться между очистками временных файлов и перезапусками, используйте `SaveImage`. `PreviewImage` не является надёжным архивом и не даёт управлять `filename_prefix`.

## Что нода делает на диске

`PreviewImage` наследует механизм `SaveImage`, но меняет каталог на временный, тип файла на `temp` и добавляет случайный суффикс к имени. PNG записывается с уровнем сжатия `1`. Это быстрее более плотного сжатия, но временные файлы могут занимать больше места.

Если метаданные не отключены настройкой запуска ComfyUI, базовый механизм сохранения добавляет в PNG prompt и дополнительные данные workflow. Это временный файл, но он всё равно существует на диске до очистки каталога.

## Имена временных файлов

Нода использует временный каталог и добавляет случайный суффикс к префиксу, чтобы параллельные preview не перезаписывали друг друга. Пользователь не управляет этим именем через вход ноды. Ссылку на созданный файл frontend получает из UI-результата выполнения.

## Вход и выход

`images` принимает один `IMAGE` или batch. Для каждого элемента batch создаётся отдельный preview-файл.

Выход `images` возвращает вход без пиксельного преобразования. Встроенная справка пакета 0.5.9 описывает `PreviewImage` как ноду без выходов, однако это не соответствует `/object_info` и реализации ComfyUI 0.32.0: сквозной выход `IMAGE` присутствует и доступен в графе.

## Проверочный пример

В рецепте «Проверка изображения через VAE» нода стоит после `VAEDecode`. Preview позволяет увидеть результат кодирования и обратного декодирования, не засоряя постоянный `output` диагностическими файлами.

Официальные шаблоны используют тот же приём. В `api_bria_image_outpainting` preview подключён после `ImagePadForOutpaint`, а в `api_openai_dall_e_2_inpaint` — после `OpenAIDalle2`. Нода отвечает только за показ полученного `IMAGE`; она не запускает дополнительную обработку изображения.

## Batch и порядок кадров

Каждый элемент входного batch сохраняется отдельным PNG с общим счётчиком. Интерфейс показывает получившийся список в порядке обработки. Preview не объединяет кадры в анимацию и не меняет их размер; для видео или анимированного файла нужна соответствующая media-нода.

## Частые ошибки

**Preview принимают за сохранение результата.** Файл находится во временном каталоге и может быть очищен. Всё, что нужно оставить, передайте в `SaveImage` или другой постоянный output.

**На вход подают `LATENT`.** `PreviewImage` работает с пикселями. После сэмплера сначала нужен `VAEDecode` с подходящим VAE.

**Ожидают, что нода ничего не пишет на диск.** Интерфейс показывает файл, созданный во временной директории. При чувствительных данных учитывайте жизненный цикл temp-каталога и метаданные PNG.

**Ставят preview в длинный batch и удивляются задержке.** Каждый элемент переводится на CPU и записывается отдельным PNG. Для частой отладки длинной последовательности сначала выберите один кадр или сократите batch.

## Производительность

Нода не меняет качество тензора, который идёт через выход, но создание preview требует преобразовать каждый кадр в 8-битное изображение и записать его на диск. На больших batch узким местом может стать файловая система, а не модель.
