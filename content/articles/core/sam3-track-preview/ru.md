# SAM3_TrackPreview

## Назначение
`SAM3_TrackPreview` создаёт временное MP4-превью треков: окрашивает области объектов, рисует их индексы и, если оценка ниже 1, показывает процент. Тензорного выхода нет.

## Место в графе
Подайте `SAM3_TRACK_DATA` и, при необходимости, исходные кадры. Это конечный интерфейсный выход для диагностики перед TrackToMask или SCAIL; его MP4 не следует принимать за исходное видео для дальнейшей обработки.

## Входы
`track_data` обязателен. `images` необязателен; без него фон будет чёрным. `opacity` принимает значения 0–1, по умолчанию 0,5. `fps` принимает значения 1–120, по умолчанию 24, и преобразуется в рациональную частоту с точностью 0,001.

## Выходы
Обычных выходов нет. Интерфейс получает `PreviewVideo` со `SavedResult` во временной папке. Имя имеет вид `sam3_track_preview_<8 hex>.mp4`; повторный запуск создаёт новый файл.

## Как работает
Упакованные маски распаковываются по кадрам и масштабируются методом ближайшего соседа. Первый истинный объект определяет цвет области пересечения. Наложение смешивается с фоном по `opacity`. Центр вычисляется по двоичной области, после чего растровый шрифт на GPU рисует номер и, при наличии, оценку.

## Параметры
Палитра содержит 12 цветов и циклически повторяется. Размер подписи растёт с высотой кадра, но ограничивается размером объекта. Поток H.264 использует yuv420p; перед кодированием PyAV кадры копируются с GPU на CPU в формате uint8.

## Проверенный пример
Фрагмент задаёт непрозрачность 0,5 и частоту 24 кадра в секунду, оставляя `images` необязательным. В 512 официальных JSON нет точных экземпляров `SAM3_TrackPreview`, поэтому пример основан на схеме времени выполнения и исходном коде, а не на официальном графе.

## Частые ошибки
Если `images` короче трека, недостающие кадры становятся чёрными. Если изображения заданы, их H/W заменяют `orig_size`. Нечётные размеры могут быть проблемными для кодировщика yuv420p; обёртка явно не выравнивает их.

## Ограничения и производительность
Каждый кадр распаковывается на GPU, затем полностью копируется на CPU и кодируется последовательно. Временное видео не содержит звука. PyAV с поддержкой H.264 должен быть доступен в окружении; настоящее кодирование при проверке не выполнялось.

## Совместимость и источники
Схема и отпечаток сверены с `/object_info` 0.32.0, отрисовка символов, наложение и кодирование — с `nodes_sam3.py`, справка — с embedded-docs 0.5.9. Человеческое утверждение ещё не получено.
