# wanBlockSwap

## Назначение
Deprecated нода существует для перехвата одноимённой custom-ноды в старых workflow и намеренно ничего не делает.
## Место в графе
Если она уже есть в импортированном графе, MODEL проходит дальше. Добавлять её в новый workflow бессмысленно.
## Вход
Единственный вход — `MODEL`; параметры block count, device или offload отсутствуют.
## Выход
Возвращается тот же объект модели, не clone и не patch.
## Причина
Комментарий исходника называет сторонние native block-swap реализации нестабильными и конфликтующими с memory management ComfyUI.
## Поведение
`execute` состоит только из `NodeOutput(model)`. Никакие блоки не перемещаются, параметры модели не меняются, память не освобождается и callback не регистрируется. На выходе находится тот же объект, поэтому нода не образует даже отдельную конфигурацию patcher.
## Deprecated статус
Runtime явно выставляет `deprecated=true`. Formal replacement API для этой заглушки не требуется: штатная замена — удалить её.
## Старые workflow
Сохранение no-op идентификатора позволяет открыть старый граф без сообщения о неизвестной ноде, но прежний ожидаемый эффект block swap исчезает. Если такой граф больше не должен оставаться совместимым со старой установкой, ноду можно удалить и напрямую соединить вход с выходом.
## Ограничения
Статья не рекомендует сторонние аналоги. Для нехватки памяти следует использовать встроенные механизмы ComfyUI и разбирать конкретную конфигурацию.
## Совместимость и источники
Проверено по ComfyUI 0.32.0, `/object_info`, `nodes_nop.py` и workflow 0.1.42. Во всех 512 JSON, 496 корневых графах и 272 подграфах точный `wanBlockSwap` не встречается. Возврат того же объекта модели закреплён исходником. Нода остаётся архивной заглушкой; человеческое утверждение статьи ожидается.
