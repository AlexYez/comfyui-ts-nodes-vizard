# CLIPMergeSimple: смешать веса двух CLIP

## Что делает нода

`CLIPMergeSimple` клонирует `clip1`, получает патчи всех параметров `clip2` и регистрирует для общих ключей взвешенное сочетание. В ComfyUI 0.32.0 формула равна `ratio × clip1 + (1 − ratio) × clip2`. Параметр `ratio` задаёт долю первого входа, хотя встроенная справка 0.5.9 описывает его как долю второго.

Выход сохраняет устройство обёртки, tokenizer, настройки токенизации и структуру `clip1`. Из второго входа берутся только веса с совпавшими ключами. Параметры, чьи имена заканчиваются на `.position_ids` или `.logit_scale`, пропускаются и остаются от `clip1`.

Нода не изменяет входы на месте и не записывает новый checkpoint. Она возвращает CLIP-обёртку с отложенными патчами; объединённые веса рассчитываются при загрузке энкодера для кодирования текста или сохранения.

## Когда использовать и когда не использовать

Используйте ноду для контролируемого эксперимента с двумя архитектурно совместимыми text encoders: одинаковыми наборами слоёв, формами параметров и tokenizer-семантикой. Начинать безопаснее с моделей одного семейства, где одна получена fine-tune из другой.

Не смешивайте CLIP-L, CLIP-G, T5, UMT5 и другие разные архитектуры только потому, что ComfyUI показывает тип `CLIP`. Выход наследует структуру первого объекта, а несовпадающие ключи второго не создают недостающие модули. Совпавшее имя с другой формой вызовет предупреждение о shape mismatch и не даст ожидаемого среднего веса.

Для переноса обученной разности между родственными моделями уместнее пара `CLIPMergeSubtract → CLIPMergeAdd`. Для изменения выбранного последнего слоя используйте `CLIPSetLastLayer`: он меняет режим encode, а не веса.

## Короткий рецепт подключения

1. Загрузите два совместимых `CLIP`; зафиксируйте, какой из них должен задавать tokenizer и структуру, — это `clip1`.
2. Подайте вторую модель в `clip2`.
3. Для сочетания 70% первого и 30% второго задайте `ratio = 0.70`.
4. Соедините выход с `CLIPTextEncode` и сравните один prompt с исходными `clip1` и `clip2`.
5. Не меняйте одновременно seed, prompt, sampler и основную diffusion model, если оцениваете вклад merge.

Fragment «Смешать два совместимых CLIP с явным коэффициентом» содержит только `CLIPMergeSimple` с `ratio = 0.70` и двумя внешними входами. Полного workflow и имён checkpoint в нём нет.

## Входы, выходы и параметры

`clip1` и `clip2` принимают `CLIP`. `ratio` — `FLOAT` от `0` до `1`, default `1`, шаг интерфейса `0.01`. Выход — один `CLIP`, не list-output.

Для каждого неслужебного ключа `clip2` нода вызывает `add_patches` с `strength_patch = 1 − ratio` и `strength_model = ratio`. Model patcher сначала умножает текущий вес клона на `strength_model`, затем добавляет вес второго encoder с `strength_patch`. Отсюда следует точная ориентация коэффициента.

При `ratio = 1` общие веса остаются от `clip1`. При `ratio = 0` общие веса берутся из `clip2`, но tokenizer, структура, несовпавшие ключи, `.position_ids` и `.logit_scale` всё равно остаются от `clip1`; результат не равен полному клону второго объекта.

`ratio = 0.5` даёт среднее только для совместимых общих параметров. Ключи, существующие лишь во втором encoder, не добавляются, потому что patcher принимает patch только для параметра, уже имеющегося в модели первого входа.

## Типовые связки

Обычная исследовательская цепочка: два совместимых loader-выхода → `CLIPMergeSimple` → `CLIPTextEncode`. Основная `MODEL` и `VAE` при этом могут оставаться от первого checkpoint, но смысл такой комбинации нужно проверять на конкретной серии моделей.

`CheckpointLoaderSimple` удобен, когда оба checkpoint содержат CLIP. Для отдельных text encoder файлов используют `CLIPLoader` или совместимый multi-loader. Если loader возвращает составной объект с несколькими encoder, merge проходит по всем совпавшим ключам внутри него.

Выход можно подать в `CLIPSetLastLayer`, а затем в encode. Обратный порядок тоже технически возможен, но clone берёт `layer_idx` из `clip1`; фиксируйте порядок в тесте, чтобы не принять смену слоя за эффект весов.

## Практический пример

Полный просмотр 512 JSON-файлов официального пакета 0.1.42, включая `definitions.subgraphs[*].nodes`, не нашёл `CLIPMergeSimple`. Поэтому recipe основан на pinned source и не выдан за официальный workflow-case.

Exact-source probe передал фиктивные веса `clip1 = [2, 4]`, `clip2 = [10, 20]` и `ratio = 0.25`. Node зарегистрировал коэффициенты `strength_model = 0.25`, `strength_patch = 0.75`; точная функция `calculate_weight` вернула `[8, 16]`. Это `0.25 × clip1 + 0.75 × clip2`.

Та же проба включила ключи `encoder.position_ids` и `encoder.logit_scale`: для них `add_patches` не вызывался. Клон сохранил tokenizer первого входа. Весовые вычисления выполнены на маленьких tensors без реального text encoder; качество conditioning не оценивалось.

## Частые ошибки и способы проверки

**Ориентация ratio взята из embedded docs.** В документации 0.5.9 крайние значения перевёрнуты относительно кода. Проверьте контрольные точки: `1` означает первый encoder, `0` — веса второго на общих ключах внутри оболочки первого.

**`ratio = 0` не повторил `clip2`.** Tokenizer, модельная структура, служебные и несовпавшие параметры остаются от `clip1`. Для точного второго encoder используйте сам `clip2`.

**Появилось предупреждение `SHAPE MISMATCH`.** Модели имеют одноимённый параметр разной формы. Patcher уже успевает умножить вес `clip1` на `ratio`, но не добавляет несовместимый вес `clip2`; это не полный пропуск операции. При `ratio = 0` такой параметр обнулится. Выберите архитектурно совместимую пару.

**Результат почти не изменился.** Сравните список совпавших ключей и убедитесь, что входы действительно разные. Fine-tune с малыми изменениями может давать близкое conditioning даже при заметной смене ratio.

**Prompt разбирается как у первого encoder.** Это штатно: output наследует tokenizer `clip1`. Смешивание весов не объединяет словари токенов двух моделей.

**После нескольких merge трудно понять итоговую формулу.** Каждый новый patch накладывается поверх уже существующих patches. Сведите эксперимент к одной ноде и только затем собирайте цепочку.

## Производительность и внутреннее поведение

При создании графа нода клонирует wrapper, а не делает немедленную полную копию всех materialized weights. `get_key_patches` всё же проходит по state dict второго encoder и собирает записи для каждого ключа; число операций линейно по числу параметров.

Сами смешанные tensors рассчитываются во время применения patches. Для encode могут одновременно понадобиться базовые веса первого encoder, данные второго и промежуточный tensor. Пиковая память зависит от offload, dtype и того, остаются ли оба исходных CLIP нужными другим ветвям.

`ratio = 1` математически оставляет common weights первого входа, но нода всё равно обходит ключи и регистрирует patches с нулевой добавкой. Если нужен чистый bypass без служебной работы, подключите `clip1` напрямую.

Клон имеет собственный список патчей, поэтому последующие изменения выхода не переписывают входную обёртку. При этом `CLIP.clone` оставляет общими базовую модель и токенизатор; результат нельзя считать независимой глубокой копией.

## Совместимость, изменения и устаревание

Статья проверена для ComfyUI `0.32.0`, frontend `1.48.7`, модуль `comfy_extras.nodes_model_merging`. Runtime fingerprint: `sha256:c6392619decb6af5d630f950f6e29a92fcc79e4a5cf76a58552753f0a9f6758c`.

Нода не помечена как deprecated, experimental или API node. В Node Replacement API 0.32.0 записи для неё нет. Формула зависит от порядка аргументов `add_patches`; изменение patcher semantics потребует повторной проверки.

English и Russian embedded docs 0.5.9 указывают формулу `(1 − ratio) × clip1 + ratio × clip2`, но код передаёт коэффициенты в противоположных ролях. В этой статье приоритет отдан exact implementation и выполненной функции `calculate_weight`.

## Связанные ноды и источники

`CLIPMergeAdd` складывает два набора общих весов без усреднения. `CLIPMergeSubtract` строит масштабированную разность. `CLIPLoader` и `CheckpointLoaderSimple` дают входные объекты, а `CLIPTextEncode` позволяет сравнить результат на одинаковых токенах.
