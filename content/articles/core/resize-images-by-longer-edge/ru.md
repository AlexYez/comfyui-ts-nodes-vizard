# Resize Images by Longer Edge: устаревшее масштабирование

## Что делает нода

`ResizeImagesByLongerEdge` меняет размер изображения так, чтобы его большая сторона стала равна `longer_edge`. Вторая сторона вычисляется пропорционально, без crop и padding.

Класс, display name и английская embedded docs помечают ноду как deprecated. Для нового графа ComfyUI зарегистрировал замену `ImageScaleToMaxDimension`; старая нода нужна прежде всего для чтения и проверки унаследованных workflow.

## Когда использовать

Оставляйте ноду в существующем графе, если требуется воспроизвести прежний Pillow Lanczos результат перед миграцией. Для новой схемы используйте `ImageScaleToMaxDimension` с `upscale_method = lanczos`.

Масштабирование по длинной стороне удобно для ограничения максимального размера без изменения пропорций: landscape `1600 × 900` при цели `1024` станет примерно `1024 × 576`.

Нода не создаёт точную ширину и высоту одновременно. Для фиксированного canvas нужны `ImageScale` или `ResizeAndPadImage` в зависимости от того, допустим ли crop/padding.

## Входы и выход

`images` принимает `IMAGE` batch. `longer_edge` — целое `1…8192`, по умолчанию `1024`.

Выход `images` сохраняет число кадров и channels. У landscape длинной стороной считается ширина, у portrait — высота. Для квадрата срабатывает ветка высоты, но обе стороны всё равно получают одинаковое целевое значение.

Runtime ComfyUI 0.32.0 выставляет `experimental: true`. Из-за ошибки общего schema-builder поле `deprecated` в `/object_info` остаётся false, хотя класс задаёт `is_deprecated = True` и display name содержит `(DEPRECATED)`.

## Как вычисляется размер

Если `width > height`, новый размер равен `longer_edge × int(height × longer_edge / width)`. Иначе высота равна `longer_edge`, а ширина — `int(width × longer_edge / height)`.

Вторая сторона усекается через `int`, а не округляется к ближайшему числу. Изображение `8 × 4` при цели `6` стало `6 × 3`; portrait `4 × 8` — `3 × 6`.

При экстремальном соотношении сторон и маленькой цели вычисленная короткая сторона может стать нулём. Тест `8 × 1` с `longer_edge = 1` завершился ошибкой Pillow `height and width must be > 0`.

## Интерполяция и точность

Код переводит каждый кадр в Pillow `uint8` и вызывает `Image.resize(..., Image.Resampling.LANCZOS)`. Результат возвращается как CPU `float32` в диапазоне `0…1`.

Значения входа перед resize ограничиваются диапазоном `0…1` и квантуются до 8 бит. Даже если размеры не меняются, преобразование через Pillow не сохраняет исходный float побитово.

RGB и RGBA поддерживаются. Одноканальный IMAGE с shape `[B, H, W, 1]` не поддерживается helper и вызывает ошибку `Image.fromarray`.

## Обработка batch

Общий `ImageProcessingNode` запускает `_process` покадрово. Внутри этой конкретной реализации есть ещё один цикл по первому измерению, но при обычном batch внешний dispatcher передаёт туда по одному кадру.

Все элементы IMAGE batch имеют общую исходную геометрию, поэтому получают одинаковую выходную форму и соединяются обратно без дополнительного выравнивания.

Результат создаётся на CPU. Если вход находился на GPU, происходит синхронный перенос через `.cpu().numpy()`.

## Проверенный пример и миграция

Рецепт Wizard подключает внешний IMAGE к старой ноде с `longer_edge = 1024` и показывает результат. Он предназначен для сравнения перед миграцией, а не как рекомендация добавлять deprecated-ноду в новый граф.

Официальный Node Replacement API задаёт точное соответствие: `images → image`, `longer_edge → largest_size`, `upscale_method = lanczos`; выход `0` остаётся выходом `0`. Поэтому автоматическая замена должна привести к `ImageScaleToMaxDimension`.

В official workflow templates JSON 0.1.42 старая нода не встречается. Backend-метод исполнен на landscape, portrait, RGBA и экстремальном aspect ratio; полный fragment в интерфейсе ещё не запускался.

## Частые ошибки

**Нода не выглядит deprecated по runtime-флагу.** Это расхождение версии 0.32.0: marker потерян в base schema, но display name, класс и Replacement API однозначны.

**Короткая сторона отличается на пиксель от расчёта.** Код использует `int`, то есть усечение.

**Получена нулевая сторона и ошибка.** Не используйте слишком маленький longer_edge для экстремально узкого изображения.

**Изменилась точность цвета.** Pillow-путь работает через uint8 и clamp.

**Ожидалось увеличение canvas без масштабирования.** Нода меняет все пиксели; для padding нужна другая операция.

## Ограничения и производительность

Pillow Lanczos выполняется на CPU отдельно для каждого кадра. При большом video batch возникают повторные tensor↔NumPy преобразования и временные изображения.

Параметра выбора фильтра нет. Нельзя получить nearest, bilinear или area, не заменив ноду. Современная замена предоставляет выбор метода и остаётся совместимой с автоматическим mapping.

Старую ноду следует сохранять лишь на время проверки миграции. После сравнения размеров и нескольких характерных кадров лучше оставить в workflow только replacement.
