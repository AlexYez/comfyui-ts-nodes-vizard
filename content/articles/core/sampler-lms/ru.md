# SamplerLMS: Linear Multistep для custom sampling

`SamplerLMS` создаёт объект `SAMPLER` для функции `sample_lms`. Единственный параметр `order` ограничивает, сколько последних производных может участвовать в многошаговом обновлении. Модель, расписание и latent подключаются к выполняющей sampling-ноде отдельно.

## LMS здесь означает Linear Multistep

Pinned-код называет функцию коэффициентов `linear_multistep_coeff` и хранит историю производных. Это Linear Multistep method, а не Least Mean Squares. Embedded docs 0.5.9 расшифровывает сокращение неверно, поэтому статья опирается на реализацию.

Алгоритм интегрирует производную по последовательным уровням sigma. Он не решает задачу статистической регрессии и не минимизирует средний квадрат ошибки.

## Нода только настраивает объект SAMPLER

Метод вызывает `ksampler("lms", {"order": order})`. Выход можно подключить к `SamplerCustom` или `SamplerCustomAdvanced`; до этого момента модель не вычисляется.

`order` помечен как advanced, по умолчанию равен 4 и имеет runtime-диапазон 1–100. Нода не принимает `SIGMAS`, поэтому при создании объекта не знает фактическое число переходов.

## order — верхняя граница доступной истории

На каждом шаге LMS добавляет текущую производную в список `ds` и оставляет не больше `order` элементов. Фактический порядок задаётся как `min(i + 1, order)`.

На первом шаге доступна одна производная, на втором — две. Даже при `order = 100` алгоритм не использует сто точек, пока в расписании и истории их нет.

## Производная строится из x и denoised

После вызова модели функция вычисляет `d = (x - denoised) / sigma` с расширением размерности sigma под tensor. Эта производная описывает движение по текущему интервалу шумовой шкалы.

LMS хранит именно `d`, а не предыдущие latents или denoised tensors. При достижении лимита самая старая производная удаляется.

## Коэффициенты зависят от реальных SIGMAS

Для каждого доступного элемента истории `linear_multistep_coeff` строит базис Лагранжа и численно интегрирует его от текущей sigma до следующей. Затем sampler складывает производные с полученными весами.

Поэтому неровное, повторяющееся или неубывающее расписание меняет коэффициенты. `SamplerLMS` не проверяет качество `SIGMAS`; это ответственность scheduler и sigma-утилит перед запуском.

## Финальный переход возвращает denoised напрямую

Если следующая sigma равна 0, функция не вычисляет LMS-коэффициенты и присваивает `x = denoised`. История производных для этого терминального перехода не используется.

Расписание без завершающего нуля пойдёт по обычной многошаговой ветке до конца. Такое отличие стоит учитывать при ручной сборке `SIGMAS`.

## Больший order не означает больше sampling steps

`order` не меняет длину `SIGMAS` и число вызовов модели. Он лишь повышает максимально допустимую длину истории в тех шагах, где она уже накоплена.

Число 100 в runtime — техническая верхняя граница, а не рекомендуемое значение. Чем выше фактический порядок, тем больше коэффициентов нужно интегрировать; универсального правила «выше — качественнее» исходник не задаёт.

При единице список содержит только текущую производную, а `cur_order` всегда равен 1. Метод остаётся в LMS-функции, но не смешивает прошлые производные.

Значение по умолчанию 4 позволяет постепенно перейти от первого к четвёртому порядку. На коротком расписании верхняя ступень может вообще не понадобиться.

## Component pipeline отделяет sampler от scheduler

`SamplerLMS.SAMPLER` подключают к `SamplerCustomAdvanced.sampler`. Рядом нужны независимые `NOISE`, `GUIDER`, `SIGMAS` и `LATENT`. Scheduler определяет точки интегрирования, а LMS — способ перехода между ними.

Если выбрать `lms` через обычный `KSampler` или `KSamplerSelect`, используется стандартный sampler без отдельного widget для custom `order`. Эта нода нужна именно для явной настройки порядка.

## В official templates exact-нода отсутствует

Полный recursive census wheel 0.1.42 охватил 512 JSON, 496 root и 272 subgraph. Ни одного `SamplerLMS` не найдено; строка `lms` также не встретилась как значение `KSamplerSelect` в pinned-наборе.

Следовательно, fragment использует runtime default и source-level совместимость портов. Он не выдаётся за официальный пример и не переносит настройки из чужого sampler.

## Fragment и probe имеют узкие границы

Recipe соединяет `SamplerLMS` с `SamplerCustomAdvanced`, оставляя все остальные входы внешними. `order = 4` взят из runtime default, а не из workflow wheel.

Exact execute-метод проверен с подставной фабрикой: он запросил sampler `lms` и передал выбранный `order` без изменений. Полный численный LMS проход требует модели и SciPy-интегратора и не выполнялся; `exampleExecuted=false`. Редактор пока не проверил материал вручную.
