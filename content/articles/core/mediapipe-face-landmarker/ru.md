# MediaPipeFaceLandmarker: найти лица, ориентиры и blendshape-коэффициенты

## Что делает нода

`MediaPipeFaceLandmarker` принимает пакет `IMAGE` и локальную модель MediaPipe. Для каждого кадра она сначала находит лица BlazeFace, затем вычисляет FaceMesh v2 и 52 мимических blendshape-коэффициента.

Результат состоит из двух выходов: структурированного `FACE_LANDMARKS` и списка рамок `BOUNDING_BOX`. В закреплённом исходнике сетка содержит 478 ориентиров, а не 468, как утверждает embedded docs 0.5.9.

## Место в графе

Перед нодой нужен `LoadMediaPipeFaceLandmarker`; к `image` подключается обычный `IMAGE` или пакет кадров. После неё `face_landmarks` можно передать в `MediaPipeFaceMeshVisualize` или `MediaPipeFaceMask`, а `bboxes` — в ноду с входом `BOUNDING_BOX`.

Для видео сначала должен появиться пакет `IMAGE`. Официальный Video blueprint получает кадры через `GetVideoComponents` и подаёт их детектору; сама нода не читает контейнер `VIDEO` и не хранит временную ось отдельно.

## Входы

- `face_detection_model: FACE_DETECTION_MODEL` — контейнер двух полных моделей `FaceLandmarker`: у каждой свои detector, mesh и blendshape-модули, а топология и каноническая геометрия хранятся во внешнем контейнере.
- `image: IMAGE` — пакет в форме `[B, H, W, C]`; используются первые три канала.
- `detector_variant: COMBO` — `short`, `full` или `both`; по умолчанию `short`.
- `num_faces: INT` — максимум лиц на кадр, от 0 до 16 в UI, по умолчанию 1. Значение 0 снимает ограничение.
- `min_confidence: FLOAT` — порог оценки BlazeFace от 0 до 1, по умолчанию 0.5.
- `missing_frame_fallback: COMBO` — `empty`, `previous` или `interpolate`, по умолчанию `empty`.

`min_confidence` фильтрует `score` детектора. Это не порог для `presence` FaceMesh и не минимальная уверенность blendshape-блока.

## Выходы

`face_landmarks: FACE_LANDMARKS` — словарь с `frames`, `image_size` и `connection_sets`. Каждый кадр содержит список лиц. У лица есть рамка по крайним точкам сетки, `landmarks_xy` размером `478 × 2` в пикселях, `landmarks_3d` размером `478 × 3`, 52 blendshape-значения, исходный logit `presence`, `score` детектора и матрица преобразования `4 × 4`.

`bboxes: BOUNDING_BOX` — список на каждый кадр. Каждая запись содержит `x`, `y`, `width`, `height`, метку `face` и `score`. Рамка вычисляется по 478 ориентирам после FaceMesh, а не копирует прямоугольник BlazeFace.

Координаты не обрезаются по границам изображения. На частично видимом лице точки и рамка могут выходить за холст.

## Как работает внутри

Изображение переводится в uint8 RGB. Пакет обрабатывается порциями по 16 кадров. Для выбранного варианта последовательно выполняются детектор, crop/warp, FaceMesh и blendshape-блок; обнаруженные лица из пакета собираются для следующих стадий.

`both` выполняет полный проход `short`, затем полный проход `full`. Для каждого кадра остаётся вариант с большим числом лиц; при равенстве выбирается `short`. Это не объединение двух списков и не выбор по средней уверенности.

После детекции `_fill_missing_frames` применяет выбранный режим восстановления пропусков. Затем для каждого итогового лица рассчитываются каноническое преобразование и bbox. Геометрия использует fp64 SVD; вырожденный набор опорных точек отклоняется.

## Настройки

`short` рассчитан на близкие лица и обычно быстрее. `full` предназначен для более дальних или мелких лиц. Это назначение взято из tooltip исходника; конкретная точность зависит от изображения и весов.

`both` полезен, когда заранее неизвестен масштаб лиц, но почти удваивает всю детекционную работу: код запускает обе полные ветви, включая mesh и blendshapes. При нескольких лицах результат всё равно целиком берётся из одной ветви для каждого кадра.

`empty` сохраняет пустой кадр. `previous` копирует последнюю успешную детекцию вперёд, но не заполняет пустые кадры до первого лица. `interpolate` заполняет края ближайшим успешным кадром, а середину линейно интерполирует. Лица сопоставляются жадно по расстоянию между центрами bbox; несопоставленные лица при разном количестве отбрасываются.

## Пример подключения

В `recipe.mediapipe-face-mask` внешний `IMAGE` входит в `MediaPipeFaceLandmarker` с `full`, `num_faces = 0`, `min_confidence = 0.5`, `missing_frame_fallback = empty`; `face_landmarks` затем идёт в маску. Эти настройки и связка подтверждены официальными Image и Video blueprint 0.32.0.

Второй фрагмент использует `short`, ограничение не более одного лица и чёрный холст визуализатора. Эта часть выведена из исходника: `MediaPipeFaceMeshVisualize` отсутствует в обоих blueprint.

В wheel с workflow-шаблонами 0.1.42 нет ни одной MediaPipe-ноды: нулевой результат получен по 496 корневым графам, всем 272 subgraph, индексам и строковым значениям. Изолированная проверка покрывает порции по 16 кадров, выбор `both`, восстановление пропусков, bbox и матрицу на подставном детекторе; настоящие веса, сеть и GPU не использовались.

## Частые ошибки

**Выход пустой на всех кадрах.** Проверьте модель, изображение, вариант детектора и `min_confidence`. Слишком высокий порог отсекает результаты BlazeFace.

**При `both` ожидались лица из двух списков.** Нода выбирает один список на кадр по количеству лиц. При равенстве всегда побеждает `short`.

**`previous` не заполнил начало видео.** До первой успешной детекции копировать нечего; начальные кадры остаются пустыми.

**При `interpolate` лицо перескочило на другого человека.** Сопоставление жадное и опирается только на центры bbox. Оно не отслеживает личность, перекрытие или пересечение траекторий.

**Интерполированные `score` выглядят уверенно.** Эти числа синтетические: код линейно смешивает `score`, `presence`, blendshapes и координаты. Они не означают повторный расчёт модели.

**BBox выходит за изображение.** Координаты ориентиров не обрезаются; следующая нода должна уметь обработать отрицательные или слишком большие значения.

## Ограничения и производительность

Размер порции жёстко равен 16. `both` выполняет две полные ветви, поэтому время и переносы модели возрастают. Число лиц влияет на FaceMesh и blendshape-обработку; `num_faces = 0` может быть заметно дороже на многолюдном кадре.

`image` преобразуется в CPU NumPy uint8, а отрисовка и маска в следующих нодах тоже используют CPU/Pillow. Альфа-канал игнорируется. Значения вне диапазона 0…1 ограничиваются при переводе.

Восстановление пропусков сглаживает последовательность, но не заменяет трекинг. При разном числе лиц часть траекторий пропадает. Для нулевых ширины или высоты геометрия делит на размер изображения; такой некорректный набор данных не защищён отдельной проверкой.

Полный фрагмент не запускался с настоящими весами. Проверено только исполнение выделенной логики с синтетическим детектором и геометрией.
