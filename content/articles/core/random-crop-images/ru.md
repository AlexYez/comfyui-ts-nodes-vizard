# Crop Image (Random): воспроизводимое случайное окно

## Что делает нода

`RandomCropImages` выбирает положение прямоугольного окна по `seed` и вырезает его из каждого кадра. Размер окна задают `width` и `height`.

Случайность влияет только на координаты. Нода не поворачивает изображение, не меняет цвет и не масштабирует crop. Если окно по оси не помещается, оно прижимается к границам и фактический размер по этой оси становится размером входа.

## Когда использовать

Нода подходит для воспроизводимой пространственной аугментации: из одного кадра можно получать разные участки, меняя seed, а при повторе того же seed возвращаться к прежнему окну.

Она также полезна, когда нужно выбрать один случайный участок большого texture или фотографии. Для гарантированного объекта в кадре требуется управляемый bounding box или `ImageCropV2`; random crop не анализирует содержимое.

Это экспериментальная dataset-нода. Для производственного графа фиксируйте версию ComfyUI и сохраняйте seed вместе с workflow.

## Входы и параметры

`images` — `IMAGE` batch. Базовый класс запускает `_process` отдельно для каждого кадра.

`width` и `height` принимают значения `1…8192`, по умолчанию `512`. `seed` принимает `0…18446744073709551615`, по умолчанию `0`.

Параметры runtime обязательны, даже если frontend рисует их как виджеты с default. Seed сначала вычисляется по модулю `2^32 − 1`, поэтому разные 64-битные значения могут вести к одной последовательности NumPy.

## Выход и границы

Выход `images` сохраняет batch и число каналов. Если запрошенное окно помещается, его форма равна `height × width`.

Максимальная левая координата равна `input_width − width`, но не меньше нуля; верхняя рассчитывается аналогично. `np.random.randint` выбирает целое из диапазона от нуля до максимума включительно.

Когда width больше входной ширины, `left = 0`, а правая граница ограничивается входом. Нода не добавляет пустые пиксели и не увеличивает canvas.

## Как seed задаёт положение

Перед выбором координат код вызывает `np.random.seed(seed % (2**32 − 1))`. Затем отдельно получает `left` и `top` из глобального генератора NumPy.

Из-за сброса генератора внутри `_process` каждый кадр batch с одинаковой геометрией получает одинаковые координаты. В synthetic batch из двух кадров seed `42` выбрал начало `(2, 0)` у обоих.

Повторный запуск с seed `42` дал побитово тот же crop. Seed `42 + (2^32 − 1)` тоже дал тот же результат из-за операции modulo. Значение `2^32 − 1` эквивалентно нулю.

## Pillow и точность данных

Каждый кадр переводится в Pillow через CPU `uint8`: значения умножаются на `255`, ограничиваются и усекаются до целого. После crop результат возвращается как CPU `float32`, разделённый на `255`.

Это означает 8-битную квантизацию даже для чистой обрезки. RGB и RGBA проходят, а shape с одним последним каналом не поддерживается используемым `Image.fromarray`.

Вызов также меняет состояние глобального NumPy RNG. Если другой Python-код в том же процессе полагается на этот генератор без собственного объекта `Generator`, результат может зависеть от исполнения ноды.

## Проверенный пример

Рецепт «Получить воспроизводимый случайный crop» принимает IMAGE, использует `512 × 512` и seed `42`, затем показывает выход. Смените seed для другого положения и верните прежний для повторения.

Official workflow templates JSON 0.1.42 не содержит `RandomCropImages`. Рецепт является минимальной проверенной по schema конфигурацией, а не официальным training workflow.

Backend-метод исполнен на двухкадровом RGB, повторном seed, seed-коллизии modulo и RGBA. Полный fragment в интерфейсе ещё не исполнялся.

## Частые ошибки

**Разные кадры video получили один участок.** В каждом `_process` NumPy RNG сбрасывается тем же seed. Для меняющегося окна нужен отдельный seed на кадр или другая нода.

**Большой crop не дополнился до размера.** Нода ограничивает окно входными границами, padding не делает.

**Два разных seed дали один crop.** Возможны modulo-коллизии и обычное совпадение координат, особенно когда вариантов мало.

**Потерялась float-точность.** Pillow-путь переводит данные в 8 бит.

**Случайный участок не содержит объект.** Содержимое изображения не анализируется; используйте bbox-aware crop.

## Ограничения и производительность

Batch обрабатывается Python-циклом с переносом на CPU и двумя NumPy random draws на кадр. Для большого датасета это проще, но медленнее tensor-based augmentation на GPU.

Одинаковая геометрия IMAGE batch означает одинаковое число возможных координат. При crop почти размером с вход случайных положений мало; seed не гарантирует визуально разный результат.

Если случайность должна быть независимой от глобального NumPy state или различаться по кадрам, этот точный контракт не подходит без дополнительной логики.
