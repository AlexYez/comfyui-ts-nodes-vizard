# StripWhitespace: устаревшая обрезка пробелов по краям

## Что делает нода

`StripWhitespace` вызывает Python-метод `str.strip()` без аргументов для одной строки. Он удаляет пробельные символы в начале и конце, но не меняет пробелы, табуляцию или переводы строк внутри текста.

Под «пробельными» здесь понимаются символы, которые Python распознаёт как whitespace. Это шире обычного пробела: точный прогон удалил также неразрывный пробел `U+00A0` и em space `U+2003` по краям.

Общий `TextProcessingNode` кладёт очищенную строку в дополнительный список. В runtime-схеме выход `STRING` при этом имеет `output_is_list = null`.

## Когда использовать и когда не использовать

Старый граф с `StripWhitespace` можно сохранить, если его результат уже учтён в следующих шагах. Для новой схемы исходник рекомендует `StringTrim`, подписанный как `Trim Text`, с режимом `Both`.

Обрезка полезна перед точным сравнением, склейкой или проверкой пустой строки, когда отступы по краям не несут смысла. Внутреннее форматирование остаётся нетронутым.

Нода не сворачивает несколько пробелов в один, не удаляет всю пунктуацию и не нормализует Unicode. Для этих задач нужны отдельные операции.

## Короткий рецепт подключения

1. Передайте одну строку в `texts`.
2. Посмотрите результат в представлении, где видны краевые пробелы и тип значения.
3. Отдельно проверьте строки, состоящие только из whitespace: результатом должна стать пустая строка.
4. В новом графе используйте `StringTrim` с `mode = "Both"`.

Фрагмент «Удалить пробельные символы с обоих краёв строки» содержит один внешний `STRING` и `StripWhitespace` без настроек. Официального workflow-примера нет; фрагмент не запускался на холсте.

## Входы, выходы и параметры

`texts` — единственный обязательный вход `STRING`, `multiline = false`. Runtime задаёт `is_input_list = false`, поэтому класс получает одну строку за вызов, несмотря на множественное имя порта.

Параметров режима нет: нельзя выбрать только левый или только правый край и нельзя передать собственный набор удаляемых символов. `str.strip()` всегда применяется с обеих сторон и без аргумента `chars`.

Выход называется `texts`, тип — `STRING`, `output_is_list = null`. Прямой вызов возвращает `['очищенный текст']`; после стандартного объединения результата одного запуска структура выходов становится `[[['очищенный текст']]]`.

## Типовые связки

Перед нодой может стоять любой источник одиночной строки. После неё разумно поставить точный просмотр или сравнение, которое не скрывает пустой результат и списочную оболочку.

`StringTrim(mode = "Both")` использует тот же `string.strip()`. В изолированном прогоне закреплённого исходника обе реализации удалили `U+00A0`, табуляцию, перевод строки и `U+2003` с краёв одной тестовой строки.

Официальные шаблоны 0.1.42 не дают подтверждённой топологии с `StripWhitespace`. Поэтому статья не приписывает ноде готовый сценарий, которого нет в проверенном пакете.

## Практический пример

Строка `"  a \t b  "` превращается в `"a \t b"`: два внешних отступа исчезают, а пробел и табуляция между буквами сохраняются. Ввод из одних `U+00A0`, табуляции, перевода строки и `U+2003` дал пустую строку.

Если вход уже равен `"a b"`, содержимое не меняется. Метод всё равно создаёт результат по стандартному поведению Python, а старый базовый класс затем помещает его в список.

Полный регистрозависимый census просмотрел 512 JSON и все 8120 root/subgraph nodes. Ни сырого совпадения, ни exact `node.type = "StripWhitespace"` не обнаружено.

## Частые ошибки и способы проверки

**Пропуски в середине остались.** Это штатное поведение `strip()`. Проверьте позиции символов; метод работает только от двух краёв до первого непробельного знака.

**Строка стала пустой.** Весь ввод состоял из whitespace. Покажите кодовые точки исходника, если невидимые символы имеют значение.

**Следующая текстовая нода получает `list`.** Runtime не помечает выход списочным, но `TextProcessingNode.execute()` возвращает `NodeOutput([result])`. Проверьте форму данных до соединения.

**Устаревание не видно в machine flag.** Display name и класс содержат `DEPRECATED`, однако общий schema builder пропускает `is_deprecated`; `/object_info` фиксирует `deprecated = false`.

## Производительность и внутреннее поведение

`str.strip()` просматривает края строки до непробельных символов и возвращает строку. Затраты ограничены длиной входа; нода не обращается к диску, сети или моделям.

Список распознаваемых пробельных символов задаёт Python, а не отдельная таблица внутри ComfyUI. Нода не принимает локаль или кодировку.

Базовый класс определяет индивидуальный режим по `_process`. Поскольку `is_output_list = None`, результат уходит в ветку одиночного выхода и оборачивается как `[result]`.
