# LoraLoaderModelOnly: LoRA только для MODEL

## Назначение

`LoraLoaderModelOnly` применяет LoRA только к diffusion-модели. Нода не принимает `CLIP`, не пытается добавить в него патчи и возвращает один `MODEL`. Это подходящий вариант для model-only адаптера или графа, где текстовый энкодер должен остаться без изменений.

Если LoRA рассчитана одновременно на denoiser и CLIP, используйте полный `LoraLoader`: model-only вариант намеренно пропустит текстовую часть файла.

## Место в графе

На вход приходит `MODEL` от checkpoint или отдельного diffusion loader. Выход подключают к sampler, model-sampling patch либо следующей model-only LoRA. Ветвь `CLIP` проходит отдельно и не зависит от этой ноды.

Нода особенно удобна в современных official workflow с lightning/distillation или control LoRA, где адаптер распространяется только для diffusion-модели. Назначение всё равно нужно сверять по карточке конкретного файла.

## Входы

`model` — базовый `MODEL`. `lora_name` — динамический список `models/loras` и дополнительных путей. `strength_model` принимает от −100 до 100, шаг 0,01, default 1.

Широкий технический диапазон не является рекомендацией. В просмотренных official workflow значения обычно близки к 1, но встречаются 0,3, 0,5, 0,8, 1,5 и 3 для разных адаптеров. Сравнивать их без учёта файла и модели нельзя.

## Выходы

Единственный выход — клон `MODEL` с добавленными совместимыми патчами. Исходный объект можно использовать параллельно как контрольную ветвь.

Runtime snapshot 0.32.0 наследует от родительского класса два текста tooltip при одном выходе. Фактический контракт однозначен: `RETURN_TYPES` содержит только `MODEL`.

## Как работает

Класс наследует кэш и загрузку от `LoraLoader`. Метод вызывает общий путь как `load_lora(model, None, lora_name, strength_model, 0)` и берёт первый результат. Карта ключей CLIP не строится, а текстовый encoder не клонируется.

Один последний разобранный файл LoRA кэшируется внутри экземпляра ноды. При смене пути кэш сбрасывается. State dict читается в safe mode с metadata; неподошедшие ключи выводятся как `NOT LOADED`.

## Параметры и настройка

При `strength_model=0` общий loader видит нулевыми оба коэффициента и возвращает исходный `MODEL`, не читая файл. Отрицательная сила меняет знак вклада, но не гарантирует смысловую инверсию эффекта.

Начинайте с exact значения official workflow или рекомендации автора LoRA. При проблеме проверьте базовую архитектуру и файл до изменения силы. Если в логе не загружены все значимые ключи, повышенный коэффициент не добавит отсутствующую совместимость.

## Проверенный пример

Рецепт «Model-only LoRA для Z-Image Turbo» повторяет корневой участок official `basic_switch_node`. `UNETLoader` № 60 загружает `z_image_turbo_bf16.safetensors`, затем link 60 подаёт `MODEL` в `LoraLoaderModelOnly` № 62 с `pixel_art_style_z_image_turbo.safetensors` и strength 1.

В исходном графе изменённый выход и необработанный `MODEL` входят в `ComfySwitchNode`, что позволяет сравнить ветви. Fragment сохраняет загрузчик и LoRA; switch не включён, чтобы рецепт не зависел от значения внешнего UI-переключателя. Веса не исполнялись.

## Частые ошибки

**LoRA должна менять текстовый энкодер, но эффект слабый или иной.** Нода игнорирует CLIP-патчи; выберите полный `LoraLoader`.

**Файл не виден.** Проверьте `models/loras`, дополнительный model path и обновление списка.

**`NOT LOADED` для большинства ключей.** LoRA не соответствует базовой diffusion-архитектуре либо содержит другой тип патчей.

**Цепочка LoRA трудно воспроизводится.** Зафиксируйте порядок и коэффициенты; добавляйте адаптеры по одному.

**Нулевую силу считают удалением предыдущих патчей.** Она лишь не добавляет текущую LoRA и возвращает входной объект, который уже может быть изменён upstream.

## Ограничения и производительность

Первое чтение файла требует десериализации, следующие выполнения того же экземпляра и пути используют кэш. Патчи добавляются к clone patcher, но sampling затем учитывает их. Время и память зависят от размера LoRA, модели и числа цепочных патчей.

Model-only вариант экономит работу с CLIP, но не делает несовместимый адаптер совместимым. Качество и оптимальная сила не выводятся из схемы; для них нужен запуск с точными весами и контрольными seed.
