# PairConditioningSetPropertiesAndCombine: добавить обработанную пару

## Назначение

`PairConditioningSetPropertiesAndCombine` принимает базовые положительную и отрицательную ветви, отдельно принимает новую пару, добавляет свойства только новым записям и затем соединяет соответствующие списки. В каждом результате базовые элементы расположены первыми, новые — после них.

Название может навести на мысль о числовом смешивании, но такого шага нет. Тензоры не усредняются и не умножаются на `strength`. Этот параметр записывается как `mask_strength` только для новой пары и только при подключённой маске.

## Место в графе

Нода полезна для регионального или временного дополнения уже готовой пары условий. Например, базовые положительная и отрицательная подсказки могут действовать на весь кадр, а новая пара — только внутри маски и в заданной части семплирования.

Если базовой пары нет, проще использовать `PairConditioningSetProperties`. Если никаких свойств новой паре не требуется, достаточно `PairConditioningCombine`. Одноимённая нода без `Pair` выполняет ту же схему только для одной ветви.

## Входы

`positive` и `negative` — базовые ветви. `positive_NEW` и `negative_NEW` — новые ветви, к которым применяются свойства. Все четыре порта обязательны и имеют тип `CONDITIONING`.

`strength` допускает значения от 0 до 10 с шагом 0,01. `set_cond_area` принимает `default` или `mask bounds`. Необязательные входы: `mask` типа `MASK`, `hooks` типа `HOOKS` и `timesteps` типа `TIMESTEPS_RANGE`. Один набор свойств действует на обе новые ветви.

## Выходы

Выход `positive` содержит записи `positive`, а за ними обработанные записи `positive_NEW`. Выход `negative` строится из `negative` и `negative_NEW` в том же порядке. Базовая положительная ветвь никогда не соединяется с отрицательной.

Базовые записи переходят в результат как те же объекты. У новых записей основной тензор тоже сохраняется; при наличии свойств создаются новые словари метаданных. Исходные данные не меняются на месте. Прежние маска, `mask_strength`, режим области и временные границы новых записей перезаписываются, а существующие `HOOKS` объединяются с подключённой группой.

## Как работает

Сначала помощник проходит только по `positive_NEW` и `negative_NEW`. Он добавляет `HOOKS`, затем маску, затем границы времени. Маска с двумя измерениями получает ведущую ось. `mask bounds` становится логическим ключом `set_area_to_bounds`, а `strength` — ключом `mask_strength`.

После обработки для каждой ветви создаётся новый список. В него последовательно добавляются базовые и новые записи. Длина списков условий внутри положительной и отрицательной ветвей может различаться: нода не сопоставляет отдельные записи и не требует равенства их количества.

## Параметры и настройка

Свойства никогда не применяются к `positive` и `negative`. Если базовые записи уже содержат маску, диапазон или `HOOKS`, они сохраняются как есть. Новая группа `HOOKS` объединяется только с группой из метаданных новой записи; маска и временные границы, напротив, заменяют прежние значения новой записи. Когда обе новые ветви ссылаются на одну прежнюю группу, общий кэш переиспользует один результат `clone_and_combine`.

Без `mask` параметры `strength` и `set_cond_area` не дают эффекта. Без всех трёх необязательных входов новая пара добавляется без копирования своих записей, и поведение становится близким к `PairConditioningCombine`. При подключённом `timesteps` оба числа записываются без проверки порядка.

Одноимённый ключ `strength`, который уже может находиться в метаданных новой записи, нода не меняет. Виджет записывает только `mask_strength`; при семплировании общий множитель и сила маски перемножаются.

## Проверенный пример

Рецепт «Добавить пару условий в области маски» принимает базовую пару, новую пару и внешнюю маску. Он задаёт `strength: 0.25`, оставляет `set_cond_area: default` и добавляет временной диапазон через отдельный порт. Результат сохраняет базовые записи первыми, а новые получают `mask_strength: 0.25`, `set_area_to_bounds: false`, `start_percent` и `end_percent`.

Проверка на синтетических данных подтвердила порядок обеих ветвей, неизменность исходных словарей, сохранение тензоров, перезапись прежних значений и применение свойств только к новым элементам. В 512 официальных файлах JSON 0.1.42 прямых случаев ноды нет; рецепт построен по исходнику и серверной схеме и не выдаётся за перенесённый официальный граф.

## Частые ошибки

**Ждут, что маска ограничит базовую пару.** Маска записывается только в `positive_NEW` и `negative_NEW`.

**Понимают `strength` как коэффициент смешивания двух пар.** Он становится силой маски и без `MASK` игнорируется.

**Ожидают одну запись на выходе.** Нода сохраняет все записи обоих списков. Две одноэлементные ветви дают двухэлементный результат.

**Путают `default` в `set_cond_area` с запасным условием.** Здесь это режим вычисления области маски. Для ключа `default: true` существует другая нода.

## Ограничения и производительность

Вычисления самой ноды линейны по числу новых записей. Без свойств она создаёт только два внешних списка. С маской, временем и `HOOKS` выполняются отдельные проходы по новой паре; словари копируются, но тензоры скрытых представлений не переносятся и не пересчитываются.

После объединения семплер может выполнить больше работы из-за дополнительных условий, областей и групп `HOOKS`. Нода не проверяет совместимость кодировщиков, моделей, размер пакета или порядок временных границ. Обратный диапазон записывается без проверки порядка. Экспериментальный контракт требует повторной сверки после обновления ComfyUI.
