# LoadLatent: прочитать .latent из input

## Что делает нода

`LoadLatent` выбирает файл `.latent` из папки input и читает его через `safetensors.torch.load_file` на CPU. Tensor под ключом `latent_tensor` преобразуется в `float32` и возвращается в новом словаре `{"samples": ...}`.

Если файл содержит маркер `latent_format_version_0`, значения не масштабируются. Для старого файла без маркера код умножает tensor на `1 / 0,18215`, то есть примерно на `5,49`. Это проверка наличия ключа, а не номера версии в metadata.

Prompt, workflow metadata и другие tensors из файла в LATENT не переносятся. Нода создаёт только поле `samples`; `noise_mask`, `batch_index` и пользовательские поля после загрузки отсутствуют.

## Когда использовать и когда не использовать

Нода нужна для продолжения работы с LATENT, ранее созданным через `SaveLatent`, или для исследования доверенного `.latent` из совместимого pipeline. После загрузки можно декодировать tensor либо использовать его как вход sampler.

Не открывайте этой нодой произвольные checkpoint-файлы и не переименовывайте другой формат в `.latent`. Загрузчик ожидает safetensors и обязательный ключ `latent_tensor`.

LoadLatent не восстанавливает модель, VAE, prompt, scheduler и состояние sampling. Если происхождение файла неизвестно, сначала уточните его архитектуру и не подменяйте совместимость совпадением формы.

## Короткий рецепт подключения

1. Поместите доверенный файл `.latent` прямо в корень `input`.
2. Добавьте `LoadLatent` или обновите существующую ноду, чтобы combo перечитал список.
3. Выберите точное имя файла в `latent`.
4. Подключите выход к `VAEDecode` и укажите тот же VAE, которым создавался tensor.
5. Проверьте форму и визуальный результат до sampling; для inpaint отдельно восстановите `noise_mask`.

Fragment «Загрузить .latent и декодировать для проверки» содержит `LoadLatent`, `VAEDecode` и `PreviewImage`. Значение файла — placeholder, который надо заменить установленным `.latent`; полного workflow нет.

## Входы, выходы и параметры

Единственный обязательный вход `latent` — динамический `COMBO`. В `/object_info` чистой установки без файлов его options пусты. При построении ноды backend выполняет `os.listdir(input)` и оставляет только обычные файлы верхнего уровня, чьи имена заканчиваются на `.latent`, затем сортирует список.

Поиск не рекурсивный и чувствителен к регистру: файл в подпапке или с суффиксом `.LATENT` не попадёт в combo. Выход — один `LATENT`, не list-output.

`VALIDATE_INPUTS` проверяет существование через защищённый annotated path. `IS_CHANGED` читает весь выбранный файл, вычисляет SHA-256 и возвращает hex-строку; замена содержимого должна инвалидировать кэш ноды.

Во время `load` safetensors читается на CPU. Затем `latent_tensor.float()` всегда даёт `float32`; при отсутствии marker дополнительно применяется legacy-множитель.

## Типовые связки

`LoadLatent` → `VAEDecode` → `PreviewImage` — безопасная диагностическая цепочка при наличии известного VAE. Она показывает содержимое без нового denoise.

`LoadLatent` → `KSampler` продолжает генерацию, только если модель, conditioning и latent-формат совместимы с исходным tensor. Параметры sampler файл не хранит.

В паре с `SaveLatent` нужен ручной переход между каталогами: Save создаёт output-файл, Load перечисляет input. После копирования имя файла становится доступно при следующем обновлении combo.

## Практический пример

Полный census 496 официальных workflow 0.1.42 не нашёл `LoadLatent` ни в root, ни в subgraph. Recipe Wizard поэтому является минимальной диагностической схемой, а не вырезкой из официального workflow.

В exact-source файловой пробе `SaveLatent` создал tensor `float16` с marker. После копирования в временный input `LoadLatent` вернул те же значения в `float32` и только ключ `samples`. Динамический combo перечислил имя файла, validation подтвердил его существование, а `IS_CHANGED` совпал с самостоятельным SHA-256.

Отдельный legacy-файл содержал значение `0,18215` и не имел `latent_format_version_0`; результат загрузки был `1,0`. Проба использовала временную папку и минимальный совместимый safetensors-кодек вокруг exact-source методов. Полный fragment с настоящим VAE не исполнялся.

## Частые ошибки и способы проверки

**Combo пуст.** Проверьте, что `.latent` лежит прямо в input, а не в `output/latents` или подпапке. После копирования обновите интерфейс.

**Файл существует, но загрузка падает.** Validation проверяет путь, а не структуру safetensors. Убедитесь, что внутри есть `latent_tensor` и файл не повреждён.

**Значения неожиданно выросли примерно в 5,49 раза.** В файле нет `latent_format_version_0`, поэтому сработала legacy-ветка. Не добавляйте marker вручную, пока не подтверждён исходный масштаб.

**После загрузки пропали mask и batch metadata.** Нода создаёт новый словарь только с `samples`. Восстановите нужные поля отдельными нодами.

**Decode выглядит неверно при правильной форме.** Выбран другой VAE или модельное латентное пространство. Форма tensor не доказывает совместимость.

**Изменённый большой файл долго пересчитывается.** `IS_CHANGED` читает его целиком для SHA-256. Это ожидаемая стоимость проверки содержимого.

## Производительность и внутреннее поведение

Загрузчик читает весь safetensors на CPU, затем `.float()` может создать полную копию при исходном dtype `float16`, `bfloat16` или другом типе. Legacy-умножение создаёт ещё один результат вычисления.

`IS_CHANGED` использует `f.read()` без потокового цикла и хеширует полученный byte buffer. Для крупного video latent это временно требует память размером файла независимо от памяти самого tensor.

Список combo строится через один `os.listdir` корня input и сортировку имён. Это быстро для обычной папки, но нода намеренно не обходит вложенные каталоги.

## Совместимость, изменения и устаревание

Статья проверена для ComfyUI `0.32.0`, frontend `1.48.7`, модуль `nodes`. Runtime fingerprint: `sha256:a3e54162b1ea53e9d1b7a63ef31ced76348e19c410798e9602b3d39745515a31`.

Нода не помечена как experimental, deprecated или API node. В Node Replacement API для неё нет замены. Логика marker и legacy-множителя привязана к реализации 0.32.0 и должна проверяться при изменении формата `.latent`.

Russian embedded docs 0.5.9 ошибочно переводят имя входа как `скрытый`, а English-версия не уточняет условие scaling. Точный идентификатор runtime — `latent`; правило marker взято из кода.

## Связанные ноды и источники
