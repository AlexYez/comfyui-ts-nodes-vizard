# SaveGLB: сохранение MESH и готовых 3D-файлов

## Что делает нода

`SaveGLB` — конечная нода для 3D-данных. В интерфейсе она называется `Save 3D Model`, потому что её фактические возможности шире системного имени. Поведение зависит от входного объекта.

Если на вход приходит `MESH`, нода собирает новый бинарный glTF-файл с расширением `.glb`. В файл попадают вершины, треугольные индексы, а при наличии — UV-координаты, цвета вершин, RGB-текстура и признак unlit-материала. Пакет MESH обрабатывается поэлементно: для каждого непустого элемента создаётся отдельный GLB.

Если на вход приходит `File3D`, перекодирования нет. Нода копирует исходные байты в `output` и берёт расширение из `File3D.format`. Поэтому SPZ останется SPZ, OBJ — OBJ, а FBX — FBX. NodeId `SaveGLB` в этой ветке не обещает конвертацию в GLB.

Обычных выходов у ноды нет. Backend возвращает только UI-список сохранённых файлов. Frontend 1.48.7 добавляет внутрь ноды 3D-просмотрщик, загружает первый результат из `output` и при поддержке asset preview сохраняет его миниатюру.

## Когда использовать и когда не использовать

Ставьте `SaveGLB` в конце ветки, когда результат должен остаться в папке `output`. Для `MESH` это прямой способ получить самодостаточный GLB без внешней библиотеки экспорта. Для готового `File3D` нода удобна как универсальная запись файла, который вернул загрузчик, API-нода или сериализатор Gaussian Splat.

Не используйте её как конвертер готовых файлов. Подключение `FILE_3D_OBJ` не превращит OBJ в GLB, а `FILE_3D_SPZ` — в mesh. Если нужен другой формат, выполните преобразование до сохранения либо воспользуйтесь доступным экспортом 3D-просмотрщика и затем проверьте полученный файл.

Нода терминальная. Если тот же `File3D`, камера и трансформация должны продолжить граф, удобнее `Save3DAdvanced` либо специализированные `SaveGaussianSplat` и `SavePointCloud`: у них есть pass-through-выходы. Для растрового кадра 3D-сцены нужна render-нода, а не сохранение контейнера.

При копировании `.gltf` или `.obj` учитывайте связанные ресурсы. `File3D.save_to` переносит один основной файл; соседние `.bin`, `.mtl` и текстуры эта нода не собирает автоматически. Самодостаточный GLB переносится надёжнее, если downstream-приложение должно открыть результат без исходной папки ресурсов.

## Короткий рецепт подключения

В официальном `3d_triposplat_image_to_gaussian_splat.json` используется ветвь `SplatToFile3D → SaveGLB`:

1. Подайте внешний `SPLAT` в `SplatToFile3D`.
2. Выберите `format = spz`.
3. Соедините выход `model_3d` со входом `mesh` у `SaveGLB`.
4. Задайте `filename_prefix = 3d/ComfyUI_TripoSplat`.
5. Запустите граф и проверьте файл `.spz` в `output/3d`.

Fragment «Официальная ветвь SPZ → SaveGLB» переносит точные настройки узлов № 92 и № 51 из этого шаблона. Он намеренно не содержит генератор TripoSplat и весовые файлы. Формат `spz` выбирает предыдущая нода; `SaveGLB` только записывает полученный `File3D`.

Для MESH схема ещё короче: `VoxelToMesh → SaveGLB`. Такая связь встречается в четырёх официальных 3D-шаблонах. Имя файла можно оставить `mesh/ComfyUI` или заменить своим префиксом.

## Входы, выходы и параметры

`mesh` — обязательный multitype-вход. Точная схема 0.32.0 принимает `MESH`, `FILE_3D_GLB`, `FILE_3D_GLTF`, `FILE_3D_OBJ`, `FILE_3D_FBX`, `FILE_3D_STL`, `FILE_3D_USDZ`, `FILE_3D_PLY`, `FILE_3D_SPLAT`, `FILE_3D_SPZ`, `FILE_3D_KSPLAT`, семейства splat/point-cloud и общий `FILE_3D`.

`filename_prefix` — строка с исходным значением `3d/ComfyUI`. Часть до последнего разделителя становится подпапкой, оставшаяся часть — основой имени. `folder_paths.get_save_image_path` проверяет, что итоговая папка находится внутри `output`, и подбирает следующий числовой счётчик. Frontend применяет к этому полю подстановки значений нод, как и у других save-нод.

Для `File3D` имя имеет вид `<prefix>_00001_.<format>`. Если `format` пуст, расширение принудительно становится `.glb`, но содержимое не меняется. Неверная метка формата поэтому создаёт файл с неверным расширением.

Для `MESH` имя тоже оканчивается на `_00001_.glb`; счётчик увеличивается после каждого записанного элемента пакета. Элемент без вершин или без граней пропускается с предупреждением.

Runtime объявляет скрытые `prompt` и `extra_pnginfo`. Они добавляются в `asset.extras` только при создании GLB из MESH и только когда metadata не отключена аргументом запуска ComfyUI. При копировании `File3D` байты остаются прежними, поэтому новая workflow metadata в него не внедряется.

Серверных выходов нет: `output = []`, `output_node = true`. Внедрённый frontend-виджет `image: PREVIEW_3D` не является ещё одним входом `/object_info` и не требует отдельного провода.

## Типовые связки

`VoxelToMesh → SaveGLB` использует кодировщик GLB. Если MESH содержит vertex colors, они записываются как `COLOR_0`; UV попадают в `TEXCOORD_0`. Текстура связывается с материалом только при наличии UV.

`SplatToMesh → SaveGLB` превращает Gaussian Splat в треугольную геометрию до сохранения. Это уже не исходный splat-контейнер. В официальном TripoSplat-шаблоне такая ветвь существует рядом с прямой записью SPZ.

`SplatToFile3D → SaveGLB` сохраняет выбранный PLY, KSPLAT или SPZ без повторной сериализации. В этой связке качество, spherical harmonics и степень сжатия определяет `SplatToFile3D`, а не save-нода.

3D API-ноды часто возвращают несколько форматов одновременно. В закреплённых шаблонах `FILE_3D_GLB`, `FILE_3D_OBJ` и `FILE_3D_FBX` подключаются к отдельным экземплярам `SaveGLB`. Так каждый исходный файл получает собственный output-префикс, но содержимое каждого остаётся в формате поставщика.

`Preview3DAdvanced` полезен перед сохранением, если нужно проверить ракурс и трансформацию, но его временная копия не заменяет постоянный output. После записи `SaveGLB` показывает сохранённый результат в собственном viewer, однако эта нода не отдаёт камеру дальше.

## Практический пример

Рекурсивный обход wheel 0.1.42 охватил 512 JSON-файлов, 496 корневых графов и 768 графов с учётом `definitions.subgraphs`. `SaveGLB` найден 39 раз в 31 шаблоне. Входящие связи распределились так: 18 `FILE_3D_GLB`, 6 `FILE_3D_OBJ`, 5 `FILE_3D_FBX`, 3 общих `FILE_3D` и 7 `MESH`. Три специализированные save-ноды из этой семьи в том же wheel отсутствуют.

Exact-source probe проверил обе ветви `SaveGLB`. Для MESH был создан пакет из двух элементов: первый содержал один треугольник, UV, RGBA-цвета и `unlit=true`, у второго реальные счётчики вершин и граней были нулевыми. Нода записала один GLB и пропустила пустой элемент. В JSON-части GLB обнаружены `TEXCOORD_0`, `COLOR_0`, `KHR_materials_unlit` и workflow metadata в `asset.extras`.

Во второй ветви memory-backed `File3D` с меткой `spz` был записан как `probe_file_00001_.spz`; байты до и после совпали. Файл без метки получил расширение `.glb`, но сохранил исходное непрозрачное содержимое. Это подтверждает, что fallback меняет имя, а не формат данных.

Probe исполнил реальные функции закреплённого исходника на временной папке. Он не запускал внешний `SPLAT` через весь fragment и не проверял визуальный результат в браузере, поэтому `exampleExecuted` остаётся `false`.

## Частые ошибки и способы проверки

**После подключения OBJ получился файл `.obj`, хотя ожидался GLB.** Это штатная File3D-ветвь. Проверьте `model_3d.format` и добавьте явное преобразование до `SaveGLB`.

**Файл назван `.glb`, но просмотрщик его не открывает.** У stream-backed `File3D` могла отсутствовать метка формата. Нода подставила расширение GLB, не перекодировав байты. Исправьте producer, который создаёт `File3D`.

**Для части MESH-пакета ничего не сохранено.** Код пропускает элемент, если число вершин или граней равно нулю. Смотрите warning `SaveGLB: skipping empty mesh at batch index ...` и проверяйте `vertex_counts`/`face_counts`.

**Экспорт падает на индексах.** `save_glb` отклоняет отрицательный индекс и индекс, который не меньше числа вершин. UV и цвета также должны иметь по одной записи на вершину. Исправьте геометрию до save-ноды.

**В viewer виден один объект, хотя файлов несколько.** Backend возвращает все результаты, но frontend берёт элемент `[0]` для встроенного preview. Проверьте папку `output` или UI-список, а не только сцену первой модели.

**У GLTF или OBJ пропали материалы.** Проверьте относительные `.bin`, `.mtl` и изображения. Копирование основного File3D не переносит набор внешних ресурсов.

**Префикс пытается выйти из `output`.** `get_save_image_path` отклоняет такой путь. Используйте относительную подпапку внутри output, например `3d/project/model`.

## Производительность и внутреннее поведение

File3D-ветвь выполняет последовательное копирование. Для disk-backed объекта используется `shutil.copy2`, для потока — чтение и запись всех байтов. Нода не разбирает геометрию и не проверяет соответствие содержимого расширению. Время и дополнительное место растут вместе с размером файла.

MESH-ветвь дороже. Тензоры вершин, граней, UV и цветов переносятся на CPU и превращаются в NumPy. Индексы записываются как `uint32`, данные выравниваются по четыре байта, затем собираются JSON- и BIN-части GLB. RGB-текстура сначала ограничивается диапазоном `0…1`, переводится в 8 бит и кодируется в PNG. Каждый элемент batch пишется отдельно.

Цвета вершин ограничиваются диапазоном `0…1`. `unlit` создаёт материал `KHR_materials_unlit`, только если встроенной текстуры нет. При текстуре и UV формируется обычный двусторонний PBR-материал с base color texture.

Frontend после выполнения снова читает первый output-файл для 3D-просмотра. При поддержке asset preview он ждёт завершения загрузки, делает миниатюру 256 × 256 и сохраняет её отдельно. Значит, пиковые расходы включают backend-запись, повторную загрузку в браузер и ресурсы WebGL-viewer.

## Совместимость, изменения и устаревание

Статья проверена по ComfyUI 0.32.0 и frontend 1.48.7. Exact NodeId — `SaveGLB`, module — `comfy_extras.nodes_save_3d`, category — `3d`. Нода не экспериментальная, не устаревшая, не dev-only и не API-only; она входит в essentials category `Basics`. Replacement API не содержит её ID.

Schema fingerprint закреплён как `sha256:4474c1f85e14392be1eabb1001bcae0c1fb9a2b78ea09754d11afa584a5c302a`. При изменении объединённого списка File3D-типов, скрытых входов, флагов или выходов статья должна пройти повторную проверку.

Frontend-регистрация `Comfy.SaveGLB` добавляет preview, восстанавливает последний output-путь, показывает export menu для обычной mesh-модели и скрывает его для splat adapter. Эти функции не видны в серверной схеме, поэтому совместимость нужно сверять одновременно с backend и frontend.

Embedded docs 0.5.9 верно описывает два семейства входов, но не объясняет, что готовый File3D копируется без конвертации, metadata добавляется только в MESH-ветке, пустые элементы batch пропускаются, а preview показывает первый результат.

## Связанные ноды и источники

`SplatToFile3D` создаёт splat-контейнер для File3D-ветви. `Save3DAdvanced` сохраняет готовую mesh-модель и возвращает файл, камеру и transform metadata дальше. `SaveGaussianSplat` и `SavePointCloud` ограничивают вход своим семейством и используют тот же интерактивный viewport. `Preview3DAdvanced` создаёт временную, а не постоянную копию.

Факты сверены с `comfy_extras/nodes_save_3d.py`, `File3D` в `geometry_types.py`, защитой пути в `folder_paths.py`, frontend `saveMesh.ts`, embedded docs 0.5.9 и полным recursive census workflow wheel 0.1.42. Probe проверил GLB-структуру, metadata, пустой batch item, byte-preserving File3D и ошибку индексов; ручное открытие файлов в сторонних 3D-приложениях ещё не отмечено как пройденное.
