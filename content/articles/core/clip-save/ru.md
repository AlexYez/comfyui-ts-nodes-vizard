# CLIPSave: сохранить текстовые энкодеры по отдельным prefix-группам

## Что делает нода

`CLIPSave` получает объект `CLIP`, извлекает предназначенный для сохранения state dict и пишет его в один или несколько файлов `.safetensors`. Количество файлов определяется ключами: известные группы `clip_l`, `clip_g`, T5, Gemma, Llama и другие сохраняются отдельно, а оставшиеся ключи попадают в базовый файл.

Нода подходит для экспорта текстового энкодера после merge или другого изменения. Это не полный checkpoint: diffusion MODEL и VAE в результат не входят.

Имена файлов нумеруются. Для prefix `clip/wizard-encoder` группа `clip_l` может получить путь `output/clip/wizard-encoder_clip_l_00001_.safetensors`, а неразобранный остаток — `output/clip/wizard-encoder_00001_.safetensors`.

## Место в графе

Ставьте `CLIPSave` в конце ветки `CLIP`, когда дальнейшая обработка этого объекта в данной ветке не нужна. Нода имеет `OUTPUT_NODE = True` и не возвращает соединяемый результат. Если один CLIP одновременно нужен для conditioning и для экспорта, разветвите исходную связь до saver-ноды.

Чаще всего вход приходит от loader или CLIP merge. Экспортированный файл затем можно использовать только там, где загрузчик понимает его архитектуру и схему ключей. Наличие `.safetensors` само по себе не гарантирует, что произвольный CLIP loader примет файл.

Для совместного экспорта MODEL, CLIP и VAE предназначена `CheckpointSave`. `ModelSave` и `VAESave` решают две другие раздельные задачи.

## Входы

- `clip: CLIP` — обязательный объект текстового энкодера.
- `filename_prefix: STRING` — prefix внутри output; default `clip/ComfyUI`.
- `prompt: PROMPT` — скрытый prompt-граф.
- `extra_pnginfo: EXTRA_PNGINFO` — скрытые дополнительные данные, обычно workflow.

Перед чтением state dict нода вызывает `clip.load_model()`. Затем `clip.state_dict_for_saving()` объединяет состояние model patcher с состоянием tokenizer. Поэтому сохранённый набор ключей шире, чем простой вызов `cond_stage_model.state_dict()`.

Runtime не принимает настройку формата, dtype или список групп. Схема разделения зафиксирована в коде ComfyUI 0.32.0.

## Выходы

Соединяемых выходов нет, а метод возвращает `{}`. Нода также не отдаёт UI-список созданных файлов. Результат нужно искать на диске по prefix и возможным suffix.

Один входной `CLIP` может создать несколько файлов. Каждая непустая группа отдельно вызывает path helper и получает счётчик по собственному basename. Поэтому номера разных suffix не обязаны совпадать, если в папке уже лежат старые экспорты.

Если state dict пуст, цикл не вызывает writer и файл не появляется. Специального результата «ничего не записано» runtime не возвращает.

## Как работает внутри

Нода вызывает `clip.load_model()`, получает mutable state dict и обходит prefix в точном порядке:

`clip_l.`, `clip_g.`, `clip_h.`, `t5xxl.`, `pile_t5xl.`, `mt5xl.`, `umt5xxl.`, `t5base.`, `gemma2_2b.`, `llama.`, `hydit_clip.`, затем пустой prefix.

Для каждой группы подходящие ключи удаляются из общего словаря и переносятся в отдельный. Непустой prefix добавляется к имени файла как suffix и удаляется из ключей. После этого из начала ключей удаляется `transformer.`. Пустой prefix обрабатывается последним и забирает весь остаток, включая неизвестные будущие схемы ключей.

Пример: `clip_l.transformer.encoder.weight` попадает в файл с suffix `_clip_l`, а внутри файла становится `encoder.weight`. Ключ `transformer.shared.weight`, не попавший в именованную группу, оказывается в базовом файле как `shared.weight`. Неизвестный `custom.weight` остаётся `custom.weight`.

При включённых metadata каждый файл получает `format = pt`, JSON-строку `prompt` и JSON-строки из `extra_pnginfo`. Значение `format` — metadata-метка; физический контейнер всё равно safetensors. При `--disable-metadata` словарь metadata остаётся пустым.

## Настройки

`filename_prefix` задаёт подпапку и основу имени. Prefix `clip/project-a/encoder` создаёт файлы внутри `output/clip/project-a`. Попытка выйти наружу через `..` отклоняется после проверки `realpath` целевой папки и output-корня. Уже существующий symlink наружу тоже не проходит проверку. Между проверкой и записью нет атомарной фиксации пути, поэтому это не абсолютная гарантия против файловых гонок.

Path helper вычисляет следующий номер по уже существующим файлам. Операция не блокируется: два параллельных запуска с одинаковыми prefix и suffix могут выбрать один номер. Разные encoder-группы счётчик друг с другом не делят, поскольку basename различается.

Подстановки даты и времени в prefix поддерживаются общим helper. `%width%` и `%height%` для этой ноды превращаются в `0`, так как размеры изображения не передаются.

## Пример подключения

Fragment `recipe.clip-save-export` содержит одну `CLIPSave` с `filename_prefix = clip/wizard-encoder`:

1. Подключите нужный `CLIP` ко входу `clip`.
2. Выполните граф.
3. Просмотрите все новые файлы в `output/clip`, включая имена с `_clip_l`, `_clip_g`, `_t5xxl` и другими suffix.
4. Для каждого файла зафиксируйте происхождение и совместимый loader; по одному имени это не всегда восстанавливается.

Полный просмотр 512 JSON workflow-пакета 0.1.42, включая 272 subgraph, не нашёл `CLIPSave`. Fragment составлен по runtime и исходнику. Изолированная проба выполнила точный цикл prefix-разделения на синтетических тензорах во временной папке: именованные группы были отделены, `transformer.` снят, остаток записан в базовую группу. Настоящий CLIP и полный fragment не запускались.

## Частые ошибки

**Ожидался один файл, появилось несколько.** Это штатное поведение multi-encoder CLIP. Список файлов определяется prefix ключей state dict.

**Имена ключей внутри файла отличаются от исходных.** Нода намеренно удаляет групповой prefix и затем `transformer.`. Сравнивайте с точным контрактом загрузчика, а не с исходным словарём посимвольно.

**Номера файлов разных групп разошлись.** У каждого basename собственный счётчик. Старый `_clip_l_00003_` не заставляет базовый файл начинаться с того же номера.

**В metadata указано `format=pt`, хотя файл safetensors.** Это строка metadata из реализации 0.32.0, а не расширение или Python pickle. Writer вызывает safetensors.

**Файл сохранился, но loader его отвергает.** Save-код не проверяет модельное семейство и не выбирает за вас совместимый loader. Проверьте набор ключей, архитектуру и ожидаемый tokenizer.

**Нода ничего не создала.** Убедитесь, что state dict не пуст и выполнение дошло до output-node. Runtime не возвращает отдельного сообщения о пустом словаре.

## Ограничения и производительность

`clip.load_model()` может загрузить энкодер на вычислительное устройство перед экспортом. Затем state dict группируется в памяти и синхронно записывается. Для крупных T5- или Llama-энкодеров объём файла и время I/O значительны.

Разделение использует удаление ключей из полученного словаря. Это безопасно для обычного возвращённого state dict, но пользовательская реализация `CLIP` должна соблюдать тот же контракт. Неизвестные prefix не теряются: их забирает пустая группа, однако получившийся базовый файл может не соответствовать конкретному loader.

Нода не вычисляет checksum, не проверяет свободное место и не пробует загрузить результат. Для распространения файла нужны отдельная проверка целостности и тест совместимости.
