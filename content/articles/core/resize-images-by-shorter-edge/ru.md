# Resize Images by Shorter Edge: устаревшее масштабирование

## Что делает нода

`ResizeImagesByShorterEdge` масштабирует изображение так, чтобы меньшая сторона стала равна `shorter_edge`. Большая сторона вычисляется пропорционально; crop и padding не применяются.

Display name и Python-класс помечают ноду как deprecated. Комментарий в исходнике указывает современный `ResizeImageMaskNode` с режимом `scale shorter dimension`, но отдельной записи для этой ноды в официальном Replacement API ComfyUI 0.32.0 нет.

## Когда использовать

Старая нода нужна для воспроизведения унаследованного графа и сравнения результата перед ручной заменой. В новый workflow её добавлять не следует.

Операция по короткой стороне полезна перед последующим crop: изображение гарантированно покрывает целевую ширину или высоту без пустых полей. Например, landscape `1600 × 900` при цели `512` станет примерно `910 × 512`, после чего можно вырезать `512 × 512`.

Если требуется ограничить максимальный размер, выбирайте масштабирование по длинной стороне. Short-edge resize способен сильно увеличить длинную сторону панорамы.

## Входы и выход

`images` — `IMAGE` batch. `shorter_edge` — целое от `1` до `8192`, по умолчанию `512`.

Выход `images` сохраняет batch и channels. У landscape фиксируется высота, у portrait — ширина. У квадратного изображения обе стороны становятся равны target.

Runtime помечает ноду `experimental: true`, но не выставляет `deprecated`. Причина та же, что у longer-edge: общий `ImageProcessingNode.define_schema` не передаёт class attribute `is_deprecated`, хотя display name содержит предупреждение.

## Как вычисляется размер

Если `width < height`, новая ширина равна `shorter_edge`, а высота — `int(height × shorter_edge / width)`. Иначе новая высота равна target, ширина — `int(width × shorter_edge / height)`.

В synthetic-проверке landscape `8 × 4` при `shorter_edge = 6` стал `12 × 6`; portrait `4 × 8` — `6 × 12`.

Пропорциональная сторона усекается к целому. Это может дать расхождение в один пиксель относительно округления и должно учитываться перед точным crop.

## Интерполяция и представление

Каждый кадр переводится в Pillow `uint8`, масштабируется фильтром Lanczos и возвращается как CPU `float32 / 255`.

Перед конверсией значения ограничиваются `0…1`. Float-данные теряют точность до 8 бит, а значения вне диапазона обрезаются. Параметра для смены фильтра нет.

RGB и RGBA сохраняют число каналов. Одноканальный IMAGE с последней размерностью `1` не принимается Pillow helper; для маски следует использовать ноду, которая обрабатывает тип `MASK` напрямую.

## Batch и память

Базовый dispatcher применяет `_process` отдельно к каждому кадру, затем соединяет результаты по batch-оси. Поскольку входной IMAGE batch имеет общую геометрию, все кадры получают одинаковую форму.

Операция выполняется на CPU. Большое значение shorter_edge на широкой панораме может создать очень длинное изображение и резко увеличить память. Например, цель относится к короткой, а не к длинной стороне.

Нода не устанавливает верхний предел рассчитанной длинной стороны, кроме косвенного ограничения target. Формула может дать размер заметно больше `8192`, если aspect ratio велик.

## Проверенный пример и ручная замена

Рецепт Wizard использует старую ноду с `shorter_edge = 512` и отправляет результат в `PreviewImage`. Это диагностический fragment для старого графа.

Для ручной миграции исходник рекомендует `ResizeImageMaskNode` и вариант `resize_type = scale shorter dimension`. Однако в `/api/node_replacements` нет mapping для `ResizeImagesByShorterEdge`, поэтому Wizard не объявляет формальную связь `replacedBy` без проверки будущей версии.

В official workflow templates JSON 0.1.42 старая нода отсутствует. Resize исполнен на landscape, portrait и RGBA; полный fragment через frontend ещё не запускался.

## Частые ошибки

**Длинная сторона стала огромной.** Target относится к короткой стороне. Проверяйте aspect ratio и итоговый размер до следующей операции.

**Автоматическая замена не появилась.** Для shorter-edge в версии 0.32.0 нет записи Node Replacement API, несмотря на комментарий в коде.

**Runtime показывает deprecated=false.** Это потерянный флаг общего schema-builder; ориентируйтесь также на display name и источник.

**Размер отличается на пиксель.** Пропорциональная сторона усекается через `int`.

**Цвет слегка изменился.** Это результат 8-битной Pillow-конверсии и Lanczos.

## Ограничения и производительность

CPU Pillow resize выполняется для каждого кадра. Video высокого разрешения потребует повторных копий и может стать дорогим по времени и памяти.

Нода работает только с IMAGE, не возвращает соответствующую MASK и не даёт выбора интерполяции. Современный `ResizeImageMaskNode` предназначен для согласованной обработки обоих типов и более явного режима размера.

После ручной миграции сравните итоговую ширину, высоту и несколько мелких деталей: другой путь реализации может не быть побитово идентичен старому Pillow Lanczos.
