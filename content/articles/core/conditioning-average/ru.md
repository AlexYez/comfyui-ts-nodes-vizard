# ConditioningAverage: взвешенная интерполяция conditioning

## Назначение

`ConditioningAverage` смешивает значения тензоров из двух conditioning по линейной формуле. Каждая запись `conditioning_to` интерполируется с первой записью `conditioning_from`; коэффициент `conditioning_to_strength` задаёт долю стороны `to`.

Нода не объединяет списки и не добавляет токены в конец последовательности. Перед смешиванием она подгоняет токенную длину `conditioning_from` к длине текущей записи `conditioning_to`.

## Место в графе

Оба conditioning обычно получают от совместимых text encoder. Результат используют вместо исходного условия на одной стороне сэмплера или передают в последующие conditioning-преобразования.

`conditioning_to` служит каркасом результата: от него берутся число записей, целевая длина токенов и основной словарь метаданных. `conditioning_from` даёт один тензор и, при наличии, `pooled_output` для интерполяции.

## Входы

`conditioning_to` — список основных записей. Нода обрабатывает каждую из них и выпускает столько же записей.

`conditioning_from` — список-источник. Используется только первая запись. Если в списке больше одной, ComfyUI пишет предупреждение и игнорирует остальные; если список пуст, обращение к элементу `[0]` завершится ошибкой.

`conditioning_to_strength` — число от 0,00 до 1,00, по умолчанию 1,00, шаг 0,01. Это доля `conditioning_to`, а не `conditioning_from`.

## Выход

Выход имеет тип `CONDITIONING` и длину списка, равную длине `conditioning_to`. Для каждой записи тензор рассчитывается как `to × strength + from_aligned × (1 − strength)`.

Словарь метаданных копируется из `conditioning_to`. Исключение — ключ `pooled_output`: если он есть с обеих сторон, значения смешиваются тем же коэффициентом; если он есть только у `conditioning_from`, это значение переносится в результат.

## Как работает

Нода берёт тензор первой записи `conditioning_from`. Для очередного тензора `to` она сначала обрезает `from` до токенной длины `to`. Если `from` короче, справа добавляются нулевые токены до той же длины. После этого два тензора умножаются на дополняющие коэффициенты и складываются поэлементно.

Выравнивается только ось токенов. Остальные размеры должны быть совместимы для поэлементной арифметики; сама нода их не подгоняет. Метаданные, кроме отдельно обработанного `pooled_output`, со стороны `conditioning_from` не переносятся.

## Параметры и настройка

При значении 1,00 тензорная часть результата равна `conditioning_to`; при 0,00 — выровненному `conditioning_from`. Последний случай не всегда равен исходному `conditioning_from`: длинная последовательность будет обрезана, короткая — дополнена нулями до формы `conditioning_to`.

Для сравнения начните с 0,50, закрепите seed и меняйте только коэффициент. Не считайте середину гарантированно «нейтральной»: линейная интерполяция embedding не обязана соответствовать линейному переходу в воспринимаемых свойствах результата.

Полный поиск по 512 official workflow templates JSON 0.1.42, включая ноды подграфов, не нашёл `ConditioningAverage`. Поэтому fragment показывает только проверяемый контракт операции, не приписывает ему официальный model case и не обещает визуальный эффект. Пример не исполнялся.

## Частые ошибки

**Коэффициент читают наоборот.** Значение 0,8 означает 80 % `conditioning_to` и 20 % выровненного `conditioning_from`.

**Ожидают усреднения всех записей обоих списков.** Обрабатываются все записи `to`, но только первая запись `from`. Остальные сопровождаются предупреждением и не участвуют.

**При strength 0 ожидают точную копию `conditioning_from`.** Форма результата задаётся стороной `to`, поэтому `from` предварительно обрезается или дополняется нулями.

**Conditioning получены от несовместимых энкодеров.** При различной ширине признаков, batch-размере или несовместимой форме pooled output тензорная арифметика может завершиться ошибкой.

## Ограничения и производительность

Для каждой записи `conditioning_to` создаётся новый смешанный тензор, а при короткой стороне `from` — ещё и нулевое дополнение. Стоимость растёт с числом записей и размером тензоров, но обычно остаётся подготовительной операцией по сравнению с полным diffusion sampling.

Нода не нормализует embedding, не проверяет смысловую совместимость и не сохраняет метаданные `conditioning_from`, кроме особого случая `pooled_output`. Веса областей, маски и диапазоны действия на стороне `from` таким способом перенести нельзя.
