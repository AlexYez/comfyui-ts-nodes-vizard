# ReplaceText: устаревшая буквальная замена подстрок

## Что делает нода

`ReplaceText` вызывает `texts.replace(find, replace)` для одной строки. Python находит все неперекрывающиеся буквальные совпадения и заменяет их слева направо.

Поиск зависит от регистра и не использует регулярные выражения. Если `replace` пуст, совпадения удаляются; если `find` пуст, вставка происходит в начале, между каждым символом и в конце.

Общий `TextProcessingNode` оборачивает итоговую строку в одноэлементный список. Runtime при этом не объявляет выход списочным: `output_is_list = null`.

## Когда использовать и когда не использовать

Старую ноду имеет смысл сохранять ради совместимости существующего графа. Для нового графа комментарий исходника указывает на другую ноду Replace Text; точный системный класс — `StringReplace` из `comfy_extras.nodes_string`.

Операция подходит для точной замены известной последовательности. Для шаблонов, групп, границ слов или нечувствительного к регистру поиска она не подходит.

Не оставляйте `find` пустым случайно: default обоих дополнительных полей — пустая строка, и такой запуск вставит `replace` во все позиции, а не вернёт текст без изменений.

## Короткий рецепт подключения

1. Подключите одну строку к `texts`.
2. Укажите буквальный фрагмент в `find`, например `cat`.
3. Введите замену в `replace`, например `dog`.
4. Проверьте регистр, все совпадения и форму выхода.

Фрагмент «Заменить буквальную подстроку во всей строке» содержит одну `ReplaceText`, внешние входы `texts`, `find` и `replace` и не задаёт выдуманных значений. Официальной топологии нет; фрагмент не импортировался и не запускался.

## Входы, выходы и параметры

`texts` — обязательный однострочный `STRING`; `is_input_list = false`.

`find` и `replace` — обязательные `STRING` с default `""` и `multiline = false`. Если исполнитель передаёт одноэлементные списки параметров, base class извлекает строки перед `_process`.

Выход `texts` — `STRING` с `output_is_list = null`. Реальный аргумент `NodeOutput` — `[result]`.

## Типовые связки

Replace можно поставить перед `TruncateText`, если лимит относится к уже исправленной строке. Если сначала обрезать текст, совпадение может быть разделено границей и не заменится.

Для нового графа `StringReplace` выполняет тот же `str.replace` и имеет многострочные входы с обычным одиночным выходом. В синтетической проверке оба класса заменили `aa` в `aaaa` на `b` и получили `bb`.

Проверенных связок из официального workflow wheel нет. Рецепт остаётся одной нодой с внешними строками, чтобы не изображать подтверждённый кейс.

## Практический пример

`aaaa` с `find = aa` и `replace = b` дало `bb`: совпадения не перекрываются. Для `AbA`, поиска `a` и замены `x` строка не изменилась из-за регистра.

Пустой `find` и `replace = -` превратили `abc` в `-a-b-c-`. Замена `one` на пустую строку в `one two one` оставила ` two `. Одноэлементные `["a"]` и `["A"]` были развёрнуты base class.

Это точные вызовы закреплённого исходника без внешних данных. Case-sensitive census 512 JSON не нашёл `ReplaceText` ни в корневых нодах, ни в subgraph.

## Частые ошибки и способы проверки

**Тире или другой текст появился между всеми символами.** Поле `find` осталось пустым. Заполните его явной непустой подстрокой.

**Совпадение с другим регистром не изменилось.** `str.replace` регистрозависим. Нормализуйте обе стороны осознанно или выберите другой алгоритм.

**Ожидалось регулярное выражение.** `find` трактуется буквально; специальные символы regex не имеют особого смысла.

**Перекрывающиеся вхождения дали меньше замен.** Python выбирает неперекрывающиеся совпадения слева направо.

**Следующая нода получила список.** Проверьте форму старого `NodeOutput`; строка находится внутри дополнительной оболочки.

**Нет deprecated-флага.** Display name и класс говорят `DEPRECATED`, но общий schema builder не переносит `is_deprecated`; `/object_info` показывает `false`.

## Производительность и внутреннее поведение

Стоимость зависит от длины строки, числа совпадений и размера замены. Операция создаёт новую строку и не меняет вход на месте.

Пустой `find` особенно быстро увеличивает результат: `replace` вставляется в `len(text) + 1` позиций.

Списочные формы `find` и `replace` длиной один элемент превращаются в скаляры. Сам вход `texts` обрабатывается как одна строка, а не как dataset-список.

## Совместимость, изменения и устаревание

Материал сверён с ComfyUI `0.32.0`, frontend `1.48.7` и `comfy_extras.nodes_dataset`. Отпечаток: `sha256:6984fddec80d7fac480bed86b95d0600a03a8b03e178a501e80bd6c6ff48527f`.

Runtime-флаги: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Код и display name считают ноду устаревшей; Node Replacement API не содержит перехода к `StringReplace`, поэтому формальная `replacedBy`-связь пока не опубликована.

EN embedded docs предупреждает о замене, но использует `text` вместо `texts` и утверждает применение ко всем входным текстам, хотя runtime индивидуальный. RU-версия опускает deprecated-предупреждение и повторяет неточное описание множественного входа.
