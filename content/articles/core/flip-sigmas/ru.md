# FlipSigmas: развернуть порядок сигм

## Что делает нода

`FlipSigmas` разворачивает последовательность `SIGMAS` по оси `0`. Для обычного одномерного списка первый элемент становится последним, второй — предпоследним и так далее.

После разворота нода проверяет новый первый элемент. Если он точно равен нулю, значение заменяется на `0.0001`. Поэтому вход `[4, 2, 0]` превращается не в `[0, 2, 4]`, а в `[0.0001, 2, 4]`.

Нода не определяет смысл исходного порядка и не проверяет пригодность результата для сэмплера. Она выполняет две точные операции: `flip(0)` и условную замену первого нуля.

## Когда использовать и когда не использовать

Используйте ноду, если конкретный алгоритм требует пройти известное расписание в обратном направлении. До подключения выясните, поддерживает ли сэмплер возрастающие сигмы и зачем ему нужен ненулевой старт.

Нода подходит для небольшого диагностического эксперимента: развернуть список, вывести его значения и сравнить с исходным. Это безопаснее, чем сразу направлять незнакомое расписание в длинный workflow.

Не воспринимайте `FlipSigmas` как стандартный шаг генерации. В 512 JSON-файлах официального пакета 0.1.42 нет ни одного её использования. Embedded docs называют разворот необходимым для обратной генерации, но код и официальный census не подтверждают универсальность этого совета.

Для замены только начального значения используйте `SetFirstSigma`. Для двух последовательных участков в исходном направлении предназначена `SplitSigmas`.

## Короткий рецепт подключения

1. Подайте проверенное расписание в `sigmas`.
2. Подключите выход к просмотру данных или временной ветке custom sampler.
3. Сравните первый и последний элементы до и после разворота.
4. Если исходный список заканчивался нулём, учитывайте автоматическую замену нового первого значения на `0.0001`.
5. Запускайте сэмплер только после проверки направления и допустимого диапазона.

Fragment «Развернуть внешнее расписание» содержит одну `FlipSigmas` с внешним входом `SIGMAS`. Полного workflow нет: официальная топология для этой ноды отсутствует.

## Входы, выходы и параметры

`sigmas` — обязательный вход `SIGMAS`. Виджетов и числовых настроек нет. Выход один, также `SIGMAS`; list-семантика выключена.

Пустой вход обрабатывается отдельно: нода возвращает тот же объект без `flip`. Ошибки внутри `FlipSigmas` не будет, но пустое расписание остаётся непригодным для сэмплера, который читает `sigmas[0]` и `sigmas[-1]`.

Для одного ненулевого элемента результат содержит то же значение. Единственный ноль превращается в `0.0001`. Такой список всё ещё описывает ноль переходов, потому что его длина равна единице.

`flip(0)` сохраняет dtype и устройство тензора. При непустом входе создаётся новый развёрнутый тензор; исходные значения не меняются. Замена нуля выполняется уже в новом объекте.

## Типовые связки

Возможная исследовательская цепочка: scheduler или `ManualSigmas → FlipSigmas → SamplerCustomAdvanced`. Она допустима только для сэмплера, которому действительно нужен обратный порядок.

Порядок с `SetFirstSigma` меняет смысл. `SetFirstSigma → FlipSigmas` переносит заданное первое значение в конец. `FlipSigmas → SetFirstSigma` сначала разворачивает список, затем явно задаёт новый старт.

`SplitSigmas` после Flip режет уже возрастающее или иначе развёрнутое расписание. Имена `high_sigmas` и `low_sigmas` при этом могут перестать соответствовать численной величине; Split не проверяет направление.

## Практический пример

Exact-source probe подал `[4, 2, 0]`. Результат равен `[0.0001, 2, 4]`, а исходный `float64`-тензор остался `[4, 2, 0]`. Тип данных сохранился.

Для пустого тензора probe подтвердил возврат того же объекта. Для `[0]` получено приблизительно `9.9999997e-05`: это представление `0.0001` в `float32`, а не другое заданное кодом число.

Полный recursive scan 512 JSON и 496 корневых workflow-графов, включая `definitions.subgraphs[*].nodes`, не нашёл `FlipSigmas`. Поэтому recipe основан на exact source и edge-case probe, а не выдан за официальный рабочий пресет.

## Частые ошибки и способы проверки

**Ожидался чистый разворот.** Если последний входной элемент равен нулю, новый первый станет `0.0001`. Сравнивайте фактические значения, а не только длину и порядок.

**Двойной Flip не восстановил исходник.** `[4, 2, 0]` после двух нод станет `[4, 2, 0.0001]`. Первая нода уже заменила ноль, и вторая не возвращает его автоматически.

**Сэмплер получил возрастающую последовательность и завершился ошибкой или артефактами.** `FlipSigmas` не проверяет требования алгоритма. Верните исходный список и сверяйте документацию конкретного сэмплера.

**Пустой вход прошёл без ошибки.** Это только поведение самой ноды. Следующий сэмплер всё равно может обратиться к отсутствующему первому элементу.

**Один элемент принят за один шаг.** Число переходов равно `len(sigmas) − 1`; у списка длины один их нет.

**После Split перепутаны high и low.** Эти имена предполагают обычный убывающий порядок. После Flip ориентируйтесь на числа, а не на подписи портов.

## Производительность и внутреннее поведение

Для непустого списка `torch.flip` проходит по значениям и создаёт новый тензор. Затраты линейны по длине расписания и обычно ничтожны по сравнению с одним шагом модели.

Пустая ветвь не создаёт копию и возвращает исходный объект. Для непустого входа изменение первого элемента не затрагивает оригинал, потому что выполняется после `flip`.

Нода не сокращает число sampling-переходов: длина остаётся прежней. Она также не переносит данные между CPU и GPU и сохраняет dtype.

При необычном многомерном тензоре разворачивается только ось `0`. Тип `SIGMAS` обычно представляет одномерную последовательность; другие формы в этой статье не считаются поддержанным пользовательским сценарием.
