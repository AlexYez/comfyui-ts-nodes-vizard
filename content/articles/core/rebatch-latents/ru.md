# Rebatch Latents: перегруппировать поток LATENT

## Что делает нода

`RebatchLatents` принимает список LATENT-значений, разворачивает совместимые пакеты в общую последовательность и нарезает её на новые пакеты размером не больше `batch_size`. Выход тоже является списком значений ComfyUI. Это не один словарь `LATENT` с большой batch-осью, а несколько LATENT-словарей, которые исполнитель передаёт дальше по list-семантике.

Порядок элементов сохраняется. Последняя порция может быть короче заданного размера. Если у следующего входного LATENT отличаются две последние размерности `samples`, текущая порция завершается и новая геометрия начинает отдельную группу: нода не масштабирует латенты между такими границами.

При пересборке она заново формирует выходные словари и переносит только `samples`, `batch_index` и, когда маска не считается пустой, `noise_mask`.

## Когда использовать и когда не использовать

Нода нужна, когда upstream-ветвь выдаёт список LATENT-пакетов разной длины, а downstream-обработку требуется выполнять порциями до заданного размера. Это помогает ограничить размер одного запуска, собрать мелкие порции в более крупные или привести остатки нескольких совместимых пакетов к единой нарезке.

Не используйте её как resize: разные пространственные размеры остаются разными группами. Для приведения геометрии есть `LatentUpscale`, `LatentUpscaleBy` или заранее согласованные источники. Для объединения нескольких обычных LATENT-подключений в один пакет подходит `BatchLatentsNode`; для выбора диапазона внутри одного пакета — `LatentFromBatch`.

Если LATENT содержит важные пользовательские поля, например служебные коэффициенты или собственную разметку, сначала проверьте downstream-контракт. `RebatchLatents` их отбрасывает.

## Короткий рецепт подключения

1. Подключите поток `LATENT` к `latents`.
2. Укажите `batch_size`: например, `2` для порций по два элемента.
3. Убедитесь, что downstream-нода корректно принимает list-output.
4. Проверьте последнюю порцию: она может содержать один элемент.
5. При наличии `noise_mask` сравните её форму и batch-размер с `samples` до запуска sampler.

Fragment Wizard создаёт `RebatchLatents` с `batch_size = 2` и оставляет LATENT внешним. Полного workflow нет: выбор sampler и требуемого размера зависит от модели и доступной памяти.

## Входы, выходы и параметры

`latents` имеет тип `LATENT`, но вся нода объявлена с `is_input_list = true`. Поэтому backend получает Python-список LATENT-словарей, даже если к сокету ведёт одно обычное соединение. `batch_size` показан в интерфейсе как один `INT` от 1 до 4096 с default `1`; из-за list-режима backend получает и его списком и использует первый элемент `batch_size[0]`.

Выход имеет тип `LATENT` и флаг `output_is_list = true`. Каждый элемент списка — отдельный словарь. В нём обязательно находятся `samples` и `batch_index`; `noise_mask` остаётся только тогда, когда среднее значение собранной маски не равно точно `1.0`.

`batch_size` задаёт верхнюю границу, а не обещание одинаковой длины всех порций. Граница пространственной формы и конец потока могут дать меньший пакет.

## Типовые связки

List-producing или mapped-ветвь → `RebatchLatents` → sampler подходит для последовательной обработки порций. `BatchLatentsNode` → `RebatchLatents` полезна, если сначала нужно установить порядок нескольких обычных входов, а затем ограничить размер исполнения.

`RebatchLatents` → `LatentFromBatch` имеет смысл, когда downstream list-семантика сначала разворачивает отдельные порции, а внутри каждой требуется выбрать диапазон. Для управления повторным шумом после изменения пакетов пригодна `LatentBatchSeedBehavior`, но её правила надо выбирать отдельно: `RebatchLatents` лишь переносит или создаёт `batch_index`.

Нода не согласует параллельные IMAGE и MASK ветви. Если одна последовательность описывает кадры, а другая — соответствующие им маски, перегруппируйте их одинаково и проверяйте остаточные пакеты.

## Практический пример

В полном снимке официальных workflow templates JSON 0.1.42 `RebatchLatents` не встречается ни в корневых графах, ни в subgraph. Рецепт поэтому помечен как source-derived и не приписан официальному примеру.

В синтетическом запуске точного класса из pinned-исходника два входа содержали 2 и 3 элемента, а `batch_size` равнялся 2. Выходные размеры составили `[2, 2, 1]`. Первый вход имел `batch_index = [10, 11]`, второй не имел индексов; результат сохранил первые два и создал для второго `[2, 3, 4]`, поскольку к началу второго входа уже были обработаны два элемента.

Отдельный тест с формами `[2, 4, 2, 2]` и `[1, 4, 3, 3]` дал два выходных пакета, не выполняя resize. Пользовательское поле первого словаря исчезло. Это безопасная проверка реализации на синтетических tensor, а не запуск fragment в живом ComfyUI.

## Частые ошибки и способы проверки

**Ожидался один LATENT, а downstream запускается несколько раз.** Выход помечен как list. Если нужен один пакет, используйте `BatchLatentsNode` или собирайте данные до этой точки.

**Последняя порция меньше `batch_size`.** Это штатный остаток. То же происходит при смене ширины или высоты. Downstream не должен предполагать фиксированное число элементов без проверки.

**Пропали пользовательские поля LATENT.** Выходной словарь строится заново только из `samples`, `noise_mask` и `batch_index`. Перенос остальных полей кодом не предусмотрен.

**Маска не привелась к размеру samples.** В версии 0.32.0 вызов `torch.nn.functional.interpolate` не присваивается переменной, а проверка высоты сравнивает маску с latent-высотой без множителя 8. Фактически несовместимая входная маска не исправляется и может вызвать ошибку при `torch.cat`.

**Осмысленная маска исчезла.** Код удаляет `noise_mask`, когда её среднее равно `1.0`, а не когда каждый элемент равен единице. Необычная маска с разными значениями, но средним ровно `1.0`, тоже будет отброшена.

## Производительность и внутреннее поведение

Для LATENT без `noise_mask` нода создаёт на CPU единичную маску формы `[B, 1, H × 8, W × 8]`. Если маска короче `samples` по batch-оси, она повторяется до нужной длины и обрезается. Затем совместимые пакеты соединяются через `torch.cat`, а готовые участки режутся Python-срезами.

Соединение выделяет новые тензоры для `samples` и масок. Чем больше `batch_size`, тем выше пиковый объём одной операции, хотя число выходных порций становится меньше. Срезы остатка обычно дешевле конкатенации, но дальнейшее хранение списка удерживает все выходные словари.

Сгенерированная единичная маска удаляется после сборки, если её среднее равно единице. Такой путь всё равно временно выделяет память. Устройствам и dtype соединяемых tensor надо совпадать; автоматического переноса между CPU и GPU для `samples` нет.

## Совместимость, изменения и устаревание

Нода не помечена как experimental или deprecated. Node Replacement API не объявляет для неё замену. Встроенная документация 0.5.9 верно описывает общую цель, но не фиксирует list-флаги, удаление произвольных метаданных и фактическое поведение несовместимой `noise_mask`; эти детали сверены по pinned-коду и `/object_info`.

При обновлении ComfyUI особенно проверяйте масочную ветвь. Исправление неприсвоенного результата interpolate или условия размерности изменит поведение без изменения видимого набора портов.

## Связанные ноды и источники

`BatchLatentsNode` создаёт один LATENT из нескольких обычных входов. `LatentFromBatch` вырезает непрерывный диапазон. `RepeatLatentBatch` повторяет элементы, а `LatentBatchSeedBehavior` меняет способ использования `batch_index` для шума.
