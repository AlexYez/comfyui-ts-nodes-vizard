# MergeTextLists: устаревший проходной список строк

## Что делает нода

`MergeTextLists` получает `texts` целиком, потому что у класса включён групповой режим и runtime выставляет `is_input_list = true`. Собственная `_group_process` возвращает входной Python-список без копирования, сортировки или фильтрации.

Название говорит об объединении, но внутри метода нет операции склейки нескольких коллекций. Комментарий исходника предполагает, что исполнитель уже собрал элементы до вызова; сама нода только записывает их количество в лог и пропускает список дальше.

Выходной контракт противоречив: `output_is_list = null`, а базовый класс возвращает `NodeOutput([texts])`. В результате полезный список оказывается ещё на один уровень глубже.

## Когда использовать и когда не использовать

Нода уместна при разборе старого графа, где такой проходной узел уже присутствует и последующие шаги учитывают его вложенность. Для новой схемы исходник рекомендует `CreateList`.

Не выбирайте `MergeTextLists`, чтобы соединить строки в один большой текст. Она не вставляет delimiter и вообще не вызывает `join()`; число строк на полезном уровне остаётся тем же.

Если нужны несколько явно видимых входных веток, `CreateList` лучше выражает эту задачу: у него есть autogrow-входы согласованного типа и выход с `is_output_list = true`.

## Короткий рецепт подключения

1. Передайте в `texts` уже подготовленный список строк.
2. Проверьте порядок, повторы, пустые элементы и глубину выходной структуры.
3. Подключайте результат только к потребителю, чей списочный контракт известен.
4. В новой схеме соберите ветки через `CreateList` и проверьте его явный list output.

Фрагмент «Проверить проход подготовленного списка строк» содержит только `MergeTextLists` и внешний `STRING`-вход с ожидаемой списочной семантикой. Он не обещает несколько соединений с одним сокетом, не импортировался и не исполнялся на холсте.

## Входы, выходы и параметры

`texts` — единственный обязательный порт `STRING`. У всей ноды `is_input_list = true`, поэтому исполнитель передаёт в один вызов список значений; у самого порта нет autogrow-описания или набора отдельных имён `input1`, `input2`.

Настроек нет. Пустой список допустим для прямого метода и остаётся пустым на полезном уровне; одиночный элемент, дубликаты и пустые строки не удаляются.

Выход также называется `texts` и имеет тип `STRING`, но `output_is_list = null`. Для входа `['a', 'b']` прямой аргумент выхода имеет форму `[['a', 'b']]`, а `merge_result_data` одного запуска добавляет ещё уровни массива выходов и запусков.

## Типовые связки

Списочный источник текста может подать значения в `MergeTextLists`, после чего нужен потребитель, рассчитанный на реальную вложенность. Обычная индивидуальная строковая нода ожидает `str` и при прямой передаче списка может завершиться ошибкой.

`CreateList` — заявленный преемник. Он проходит по autogrow-входам в порядке словаря, расширяет общий список через `+=` и объявляет результат списочным; в изолированном прогоне закреплённого исходника две ветки `['первый', '']` и `['первый', 'третий']` дали четыре значения в исходном порядке.

В официальном пакете 0.1.42 нет готовой связки ни с `MergeTextLists`, ни подтверждения нескольких графовых соединений с единственным портом `texts` этой ноды.

## Практический пример

В изолированном прогоне на вход передали `['первый', '', 'первый', 'третий']`. `_group_process` вернула тот же объект: порядок, пустая строка и повтор сохранились. Одиночный `['один']` и пустой `[]` тоже прошли без изменения полезного содержимого.

После старой обёртки прямой результат для четырёх строк выглядел как `[['первый', '', 'первый', 'третий']]`. Стандартное объединение одного вызова сформировало `[[[['первый', '', 'первый', 'третий']]]]]`, тогда как `CreateList` с явным списочным флагом дал обычный массив выхода `[['a', 'b']]`.

Регистрозависимый поиск по 512 JSON, 496 root workflows, 272 subgraphs и всем 8120 нодам не нашёл `MergeTextLists`. Реального официального набора соседей и настроек для статьи нет.

## Частые ошибки и способы проверки

**Ожидалась одна строка.** Нода возвращает коллекцию и не использует `join()`. Для текстовой склейки выберите `StringConcatenate` или другой узел с delimiter.

**Появился лишний уровень списка.** Это закреплённое поведение базового класса: при `is_output_list = None` он выполняет `NodeOutput([result])`. Покажите `repr` значения на каждой границе.

**Документация предлагает несколько подключений к `texts`.** В runtime-схеме есть один обычный required-порт без autogrow. Исходный комментарий описывает предполагаемую предварительную сборку, но официальный workflow её не демонстрирует; не стройте рецепт на непроверенной топологии.

**Нода не отмечена deprecated машинно.** Display name и класс содержат устаревание, однако `TextProcessingNode.define_schema()` не передаёт `is_deprecated`, поэтому `/object_info` возвращает `false`.

## Производительность и внутреннее поведение

Сама `_group_process` работает как проходная функция и возвращает ту же ссылку на список. Она вычисляет `len(texts)` для сообщения в журнале, но не проходит по содержимому.

Дополнительные контейнеры появляются в базовой выходной обёртке и затем при сборке результатов исполнения. Строки не копируются и не изменяются, однако глубина структуры влияет на совместимость следующих нод.

`CreateList` ведёт себя иначе: последовательно расширяет новый список элементами входных веток и объявляет `is_output_list = true`, поэтому `merge_result_data` не добавляет слой как для обычного одиночного выхода.

## Совместимость, изменения и устаревание

Статья относится к ComfyUI `0.32.0`, интерфейсу `1.48.7` и `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:4e0814b665dbe8f92ca6762a25ad1d54e1d356f414bbfc670abc9d7a14fe99bc`.

Флаги runtime: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`, `is_input_list = true`, `output_is_list = [null]`. Исходник задаёт `is_deprecated = True` и называет преемником `CreateList`.

Закреплённый снимок API замен не содержит ни `MergeTextLists`, ни `CreateList`. Поэтому статья предупреждает о направлении миграции, но манифест оставляет `replacedBy = null` до формальной связи и отдельной проверенной статьи.
