# Get Latent From Batch: выбрать отрезок LATENT-батча

`LatentFromBatch` берёт из входного `LATENT` один элемент или несколько соседних элементов. Нода работает по первой, batch-оси тензора `samples`, а вместе с ним старается согласованно перенести `noise_mask` и `batch_index`. Это не выбор произвольного набора позиций: результат всегда представляет один непрерывный срез.

## 1. Что делает нода

Пусть батч содержит четыре латента: `[A, B, C, D]`. При `batch_index = 1` и `length = 2` нода вернёт `[B, C]`. Значения внутри латентов не пересчитываются: выбранный участок тензора клонируется.

Отрицательный индекс считается от конца. Для того же батча `batch_index = -1`, `length = 1` выбирает `D`, а `batch_index = -2`, `length = 2` — `[C, D]`. Если запрошенный участок упирается в правую границу, нода сокращает результат, а не повторяет элементы.

## 2. Место в графе

Нода нужна, когда следующая ветка должна получить лишь часть уже собранного LATENT-батча: отдельный результат sampler, последний элемент, короткий диапазон или один фрагмент для повторной обработки. Обычно её ставят после ноды, которая создала либо объединила батч, и перед sampler, VAE Decode или другой LATENT-операцией.

Она не разбивает батч на список выходов, не выбирает разрозненные индексы и не меняет spatial-размер. Для увеличения батча служит `RepeatLatentBatch`, для объединения — batch-ноды. Если требуется только изменить порядок генерации шума, нужен `LatentBatchSeedBehavior`, а не срез.

## 3. Входы

- `samples` — входной `LATENT`. Обязательное поле `samples` внутри него должно содержать тензор хотя бы с batch-осью. Дополнительные поля могут включать `noise_mask`, `batch_index`, коэффициенты downscale и другие метаданные.
- `batch_index` — стартовая позиция. В runtime ComfyUI 0.32.0 виджет допускает целые значения от `-16384` до `16384`, значение по умолчанию — `0`.
- `length` — максимальное число элементов в результате. Диапазон виджета — от `1` до `64`, значение по умолчанию — `1`.

Провод, подключённый к числовому входу, может передать разрешённое runtime значение независимо от того, что сохранено в виджете. Фактический результат всё равно ограничивается размером входного батча.

## 4. Выход

Выход имеет тип `LATENT`. Поле `samples` содержит clone среза, поэтому его storage не совпадает с исходным тензором. Для выбранного диапазона размер batch-оси равен фактическому `length`, которое могло сократиться у правой границы.

Словарь LATENT сначала копируется поверхностно. Поля, которые нода не обрабатывает отдельно, остаются теми же объектами, что и во входе. `samples` заменяется клоном среза; `noise_mask`, если присутствует, обрабатывается по отдельным правилам; `batch_index` создаётся либо срезается. Поэтому нельзя считать, что любой пользовательский metadata-тензор автоматически уменьшился вместе с батчем.

## 5. Как устроена операция

Для отрицательного `batch_index` код один раз прибавляет размер батча `B`. Затем старт прижимается к диапазону от `0` до `B - 1`. Это clamp, а не циклическая индексация. При `B = 4` значение `-5` после прибавления остаётся отрицательным и становится `0`; значение `100` становится `3`.

После этого `length` заменяется меньшим из двух чисел: запрошенной длины и количества элементов от старта до конца. Для `[A, B, C, D]`, `batch_index = 2`, `length = 64` выходом будут только `[C, D]`.

Если есть `noise_mask`, реализация смотрит на её batch-размер:

- одна маска клонируется как один элемент и не размножается до длины результата — дальнейшие ноды могут применить её ко всему батчу через broadcast;
- несколько масок, которых меньше, чем samples, сначала циклически повторяются до размера исходного батча, затем из них берётся тот же диапазон;
- при достаточном числе масок сразу берётся соответствующий срез.

Ветка дополнения использует жёстко заданный четырёхмерный `repeat(..., 1, 1, 1)`. Для пяти- и более мерной video-маски с `1 < mask_batch < samples_batch` число repeat-осей окажется меньше числа осей тензора, и PyTorch завершит операцию ошибкой. Одиночная такая маска попадает в отдельную ветку clone, а уже согласованная по batch-размеру — в обычный срез.

Если вход не содержит `batch_index`, выход получает список абсолютных позиций `[start, …, start + length - 1]`. Если поле уже было, нода берёт из него тот же срез без дополнительной проверки длины списка.

## 6. Как выбирать batch_index и length

Для первого элемента используйте `0, 1`; для последнего — `-1, 1`. Чтобы взять последние `N` элементов, задайте `batch_index = -N` и `length = N`, но учитывайте clamp: если `N` больше размера батча, начало станет нулём, а результатом будет весь доступный батч.

Большое `length`, например `64`, удобно как запрос «весь хвост» в пределах разрешённого виджета. Оно не создаёт недостающие элементы. Если downstream-нода требует ровно заданный batch size, проверьте размер заранее или добавьте отдельное повторение после среза.

Отрицательные значения дальше левой границы не дают ошибку и не оборачиваются несколько раз. Это полезно как безопасный fallback к первому элементу, но может скрыть неверно вычисленный индекс. Если точная позиция существенна, не полагайтесь на clamp как на проверку корректности.

## 7. Проверенный пример

Fragment `Выбрать последний элемент LATENT-батча` содержит одну `LatentFromBatch` с `batch_index = -1` и `length = 1`. Внешний вход принимает любой совместимый `LATENT`; выход можно подключить к sampler, VAE Decode или диагностической ветке.

Параметры fragment сверены с runtime-схемой 0.32.0, а сам JSON прошёл проверку схемы и портов. В установленном ComfyUI пример пока не исполнялся. Полный рекурсивный просмотр 512 JSON из `comfyui-workflow-templates-json 0.1.42`, включая корневые графы и `definitions.subgraphs`, не нашёл `LatentFromBatch`. Поэтому fragment основан на точной реализации ноды, но не выдаётся за вырезку из официального workflow.

## 8. Частые ошибки

- `length` понимают как обязательный размер результата. На деле это верхняя граница: у конца батча элементов может оказаться меньше.
- Отрицательный индекс принимают за modulo. Код прибавляет размер только один раз, после чего применяет clamp.
- Ожидают, что `batch_index = B` означает первый элемент следующего цикла. Он указывает за правую границу и потому превращается в `B - 1`.
- Считают, что одиночная `noise_mask` будет физически повторена для каждого выбранного элемента. Нода сохраняет один clone маски.
- Пользовательское поле LATENT считают синхронно срезанным. Все неизвестные поля переносятся поверхностной копией без изменения.
- Передают вручную созданный `batch_index`, длина которого не совпадает с batch-размером `samples`. Реализация не исправляет такой список, и downstream-логика шума может получить несогласованные данные.
- Выбирают часть video latent с многомасочным пятиосевым `noise_mask`, который короче `samples`. Ветка дополнения масок в 0.32.0 рассчитана на четыре измерения; сначала приведите batch-размер маски в соответствие отдельной операцией.

## 9. Ограничения и производительность

Время и дополнительная память для `samples` растут с размером выбранного среза: `.clone()` выделяет новый тензор. При наличии многомасочного `noise_mask` возможны временное повторение масок до размера исходного батча и clone выбранной части. Одиночная маска тоже клонируется, но остаётся одной.

Нода не выполняет VAE, sampling или интерполяцию spatial-размера, поэтому обычно дешевле этих операций. Однако выбор большого видео-латента всё равно копирует соответствующий объём данных. Поверхностный перенос остальных полей экономит память, но требует осторожности: их формы могут больше не соответствовать укороченному `samples`.
