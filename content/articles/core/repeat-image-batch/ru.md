# RepeatImageBatch: повторить весь IMAGE-бэтч

`RepeatImageBatch` копирует входной IMAGE-бэтч вдоль batch-оси `amount` раз. Если вход состоит из одного кадра, получится нужное число его копий. Если кадров несколько, повторяется вся последовательность целиком — это важное отличие от поэлементного дублирования.

## Точная операция repeat

Реализация вызывает `image.repeat((amount, 1, 1, 1))`. Меняется только первая, batch-размерность. Высота, ширина и число каналов каждого изображения остаются прежними.

При входном размере `B × H × W × C` выход имеет размер `(B × amount) × H × W × C`. Нода не масштабирует кадры, не смешивает пиксели и не создаёт промежуточных изображений.

## amount задаёт число повторов всего входа

В ComfyUI 0.32.0 `amount` — целое число от 1 до 4096, значение по умолчанию равно 1. При `amount = 1` выходная последовательность совпадает со входной по значениям и порядку.

Параметр можно задать виджетом или подключить из другой ноды. В официальных workflow amount часто вычисляется по длине видео, поэтому сохранённое в `widgets_values` число не всегда является фактическим значением при выполнении.

## Порядок для нескольких входных кадров

Пусть вход равен `[A, B]`. При `amount = 3` результатом будет `[A, B, A, B, A, B]`. Нода повторяет блок `[A, B]` три раза.

Она не выдаёт `[A, A, A, B, B, B]`. Для такой группировки потребовалась бы другая перестановка или повторение каждого элемента по отдельности. Утверждение «повторяет изображение» верно только для входного бэтча из одного IMAGE.

## Это репликация, а не конкатенация двух источников

`RepeatImageBatch` имеет один IMAGE-вход. Она не может добавить к `[A, B]` новый кадр `C`, которого во входе нет. Для соединения разных источников нужна BatchImagesNode или старый `ImageBatch` в унаследованном графе.

Обратное тоже верно: `ImageBatch` не содержит `amount` и не предназначен для размножения одного источника. Цепочка из множества ручных объединений хуже выражает намерение и сложнее поддерживается.

## Память растёт вместе с размером бэтча

Нода материализует повторённый тензор. Если вход содержит `B` кадров, выход содержит `B × amount`; вместе с этим растёт объём данных для следующих IMAGE-операций. Верхняя граница 4096 не означает, что любое такое значение безопасно для доступной памяти.

Для больших кадров увеличивайте amount постепенно и учитывайте, какие downstream-ноды одновременно держат вход, выход и промежуточные тензоры. Если нужен только один граничный кадр, сначала выберите его через ImageFromBatch, а уже затем повторяйте.

## Официальный LTX-рецепт вычисляет amount

В `template_ltx2_3_ic_lora_ingredients` с workflow ID `0112e9af-5129-48ba-af78-92c40ac40b40` активная RepeatImageBatch № 709 получает IMAGE от LoadImage № 724. `amount` приходит от ComfyMathExpression № 717, а выход идёт в ResizeAndPadImage № 722.

В файле сохранено значение 125, но подключённый вход имеет приоритет при выполнении. Топология показывает практическую задачу: растянуть одно загруженное изображение на вычисленную длину дальнейшей последовательности.

## Официальные VACE-ветки повторяют изображение маски

В корне `video_wan_vace_outpainting` нода № 129 получает IMAGE от MaskToImage № 111, amount — от PrimitiveInt № 131, а результат возвращается в тип MASK через ImageToMask № 130. Сохранённое значение amount равно 17.

В subgraph `video_wan_vace_flf2v` активная нода № 149 также получает результат MaskToImage, но передаёт повторённый IMAGE сразу в две BatchImagesNode. Amount вычисляет ComfyMathExpression; сохранённое значение равно 30.

## Bypass-экземпляр не равен активному примеру

Полный рекурсивный просмотр wheel `comfyui-workflow-templates-json 0.1.42` нашёл четыре RepeatImageBatch в четырёх файлах, но только три работают в `mode = 0`. Экземпляр № 132 в `video_wan_vace_14B_ref2v` сохранён в `mode = 4`, то есть bypassed.

Поэтому формулировка «три официальных активных случая» не скрывает четвёртое совпадение. Bypassed-нода полезна как свидетельство структуры графа, но не доказывает, что её повторение участвует в текущем выполнении.

## Fragment повторяет масочную топологию outpainting

Рецепт «Повторить IMAGE-представление маски» строит участок `внешний IMAGE → RepeatImageBatch → ImageToMask` и ставит `amount = 17`, как в официальном outpainting workflow. Внешний вход соответствует результату MaskToImage, но сама конверсия перед ним не дублируется.

Так fragment остаётся коротким и проверяемым: он показывает повторение и последующее возвращение к MASK, не притворяясь полным video workflow. Схема проверена, живое выполнение не проводилось.

## Когда сначала нужен ImageFromBatch

Если вход содержит несколько разных кадров, RepeatImageBatch повторит их все. Чтобы размножить только последний, сначала используйте ImageFromBatch с `batch_index = −1`, `length = 1`, затем подключите RepeatImageBatch.

Чтобы повторить отрезок, выберите его тем же способом с нужным `length`. Порядок операций влияет на результат: `select → repeat` копирует выбранный фрагмент, а `repeat → select` сначала создаёт большую циклическую последовательность и затем обрезает её.

## Как проверить длину и порядок

Перед нодой определите batch size `B`, после неё ожидайте `B × amount`. Для одиночного входа и `amount = 17` должно получиться 17 элементов. Для трёхэлементного входа то же значение даст 51 элемент.

Если кадры сгруппированы не так, как ожидалось, проверьте исходный бэтч: RepeatImageBatch сохраняет порядок блока. Если число элементов не меняется, amount может быть равен 1 либо нода может находиться в bypass-режиме. Если возникает нехватка памяти, уменьшайте amount или размер IMAGE до повторения.
