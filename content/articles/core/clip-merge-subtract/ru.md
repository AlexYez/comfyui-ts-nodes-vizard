# CLIPMergeSubtract: получить масштабированную разность CLIP

## Что делает нода

`CLIPMergeSubtract` строит для общих весов выражение `multiplier × (clip1 − clip2)`. Она клонирует первый CLIP, масштабирует его параметр на multiplier и добавляет параметр второго с коэффициентом `−multiplier`.

Это отличается от часто предполагаемой формулы `clip1 − multiplier × clip2`: multiplier действует на обе части разности. При `1` обе записи совпадают, при `0.5` получается половина всей дельты, при `−1` — разность в обратном направлении.

Нода сохраняет wrapper, tokenizer и структуру `clip1`. `.position_ids` и `.logit_scale` не вычитаются. Результат обычно служит промежуточной дельтой для `CLIPMergeAdd`, а не самостоятельным text encoder для prompt.

## Когда использовать и когда не использовать

Используйте Subtract, чтобы выделить изменение между родственными encoder: например, `tuned − base`. Затем эту дельту можно прибавить к совместимому target CLIP. Такой перенос остаётся экспериментом; он не доказывает, что найденная разность соответствует одному стилю или понятию.

Не ставьте `multiplier = 0` ради bypass. Для common keys patcher сначала умножит вес `clip1` на ноль, а добавка `clip2` тоже станет нулевой. В результате большая часть encoder будет обнулена, тогда как пропущенные и несовпавшие параметры останутся от первого входа.

Не вычитайте модели разных архитектур. Разность имеет смысл только для параметров одинаковой формы и роли. Частичное совпадение ключей создаёт гибрид с дельтой на одной части сети и нетронутыми весами на другой.

## Короткий рецепт подключения

1. Подайте fine-tuned encoder в `clip1`, исходную модель до fine-tune — в `clip2`.
2. Начните с `multiplier = 1`.
3. Подключите выход к `clip2` ноды `CLIPMergeAdd`.
4. В `clip1` Add подайте target encoder, на который переносится изменение.
5. Сравните target и `target + multiplier × (tuned − base)` на одном наборе prompt.

Shared fragment «Перенести разность tuned − base на target CLIP» реализует именно этот порядок. Все три CLIP приходят извне; sampler, diffusion model, save и полный workflow отсутствуют.

## Входы, выходы и параметры

`clip1` и `clip2` принимают `CLIP`. `multiplier` — `FLOAT` от `−10` до `10`, default `1`, шаг `0.01`. Выход — один `CLIP`. Runtime aliases: `clip difference` и `text encoder subtract`.

Для каждого ключа второго encoder, кроме `.position_ids` и `.logit_scale`, нода вызывает `add_patches` с `strength_patch = −multiplier`, `strength_model = multiplier`. После materialization common tensor равен `multiplier × W1 − multiplier × W2`.

При `multiplier = 1` получается `W1 − W2`. При `0.25` — `0.25W1 − 0.25W2`. При `−1` — `W2 − W1`. Значения с модулем больше единицы усиливают всю дельту и могут быстро вывести веса за обычный диапазон.

Ключи только `clip1` не получают patch и остаются от первого входа без умножения. Ключи только `clip2` не создаются. Поэтому краткая формула описывает именно пересечение совместимых, неотфильтрованных параметров.

## Типовые связки

Осмысленная семейная цепочка: `Subtract(tuned, base, m) → Add(target, delta)`. На common keys её итог равен `target + m(tuned − base)`. Tokenizer конечного объекта берётся у target, потому что он подключён как `clip1` Add.

Выход Subtract технически можно передать прямо в `CLIPTextEncode`, но при близких tuned и base веса дельты будут малы и не представляют обычный обученный encoder. Такой запуск годится для диагностики, а не как обязательная часть delta-transfer.

Если нужна интерполяция двух полных моделей, используйте `CLIPMergeSimple`. Subtract решает другую задачу: выделяет направление изменения, которое затем добавляют к третьей точке.

## Практический пример

В полном пакете workflow templates JSON 0.1.42 нет ни одного `CLIPMergeSubtract`: проверены 512 JSON, root nodes и все `definitions.subgraphs[*].nodes`. Официальные widgets и topology для этой версии отсутствуют.

Exact-source probe использовал `clip1 = [2, 4]`, `clip2 = [10, 20]`, `multiplier = 2`. Node зарегистрировал `strength_model = 2` и `strength_patch = −2`; `calculate_weight` вернула `[−16, −32]`, то есть `2 × ([2, 4] − [10, 20])`.

Probe проверил также фильтр `.position_ids` и `.logit_scale` и сохранение tokenizer первого входа. Это безопасная алгебраическая проверка на tensors, не полный encode реальных моделей.

## Частые ошибки и способы проверки

**Multiplier трактуется как сила только второй модели.** Запишите коэффициенты обоих слагаемых. В этой ноде они равны `+m` и `−m`.

**Ноль выбран для отключения.** Он обнуляет common weights. Для bypass соедините `clip1` напрямую или уберите ветку из графа.

**Порядок tuned и base перепутан.** Получится дельта противоположного знака. Проверьте, что `clip1` — состояние после изменения, `clip2` — исходное состояние.

**Разность подключена в Add не в тот порт.** Target должен быть `clip1` Add, потому что от первого входа берутся tokenizer и структура. Delta входит в `clip2`.

**Часть слоёв не изменилась.** Сравните наборы ключей. Несовпавшие и отфильтрованные параметры сохраняются от первого входа Subtract, а не становятся разностью.

**Появилось предупреждение `SHAPE MISMATCH`.** Для одноимённого параметра разных форм patcher сначала умножает вес `clip1` на `multiplier`, а несовместимый вес `clip2` не вычитает. Такой слой не равен ожидаемой разности; при нулевом multiplier он обнулится.

**Большой отрицательный multiplier дал нестабильный текстовый encode.** Диапазон виджета допускает `−10`, но это технический предел. Проверяйте малые значения и нормы conditioning, не принимая край диапазона за безопасную рекомендацию.

## Производительность и внутреннее поведение

Создание результата проходит по key patches второго CLIP и регистрирует отложенные операции. Разность не materialize целиком в момент выполнения ноды. Сложность начального шага линейна по числу ключей.

При последующем Add сначала вычисляется фактический вес delta-объекта, затем он прибавляется к target. Такая вложенная patch-цепочка удерживает ссылки на несколько encoder и требует дополнительной памяти при materialization.

Входные обёртки не меняются; клон получает собственный список патчей. Токенизатор и структура cond-stage остаются связанными с первым входом по правилам `CLIP.clone`, поэтому самостоятельная дельта не становится отдельной архитектурой.

Multiplier по модулю меньше единицы не сокращает число вычислений: меняются коэффициенты, а не количество параметров. Быстрого пути для нуля нет; нода всё равно обходит keys и создаёт нулевые patches.

## Совместимость, изменения и устаревание

Нода не помечена как deprecated, experimental или API node. Формальной замены нет. Exact NodeId `CLIPMergeSubtract` зарегистрирован для Python-класса `CLIPSubtract`; это registry mapping, а не проверенный alias переименования.

Embedded docs 0.5.9 называют операцию вычитанием `clip2` из `clip1`, но не раскрывают масштабирование первой модели. Описание multiplier как «силы вычитания» легко прочитать как `clip1 − mclip2`; exact source и patcher дают `m(clip1 − clip2)`.
