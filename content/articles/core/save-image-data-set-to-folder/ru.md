# SaveImageDataSetToFolder: устаревшая запись списка PNG

## Что делает нода

`SaveImageDataSetToFolder` принимает список значений `IMAGE` и записывает их как PNG в подпапку каталога `output`. Она не возвращает данных в граф: это выходная нода с файловым побочным эффектом.

Перед сохранением тензор умножается на 255, обрезается до диапазона 0–255 и преобразуется в `uint8`. Поэтому файлы всегда восьмибитные, а значения вне рабочего диапазона теряются.

В ComfyUI 0.32.0 нода одновременно помечена `experimental` и `deprecated`. Комментарий в исходнике называет её избыточной и указывает на обычные Save Image-ноды, где целевую подпапку можно задать в `filename_prefix`.

## Когда использовать и когда не использовать

Нода нужна главным образом для чтения и аккуратного запуска старого графа, который уже содержит этот runtime ID. Для нового workflow выбирайте `SaveImage` и указывайте путь вроде `dataset/image` в `filename_prefix`.

Если старую ноду пока нельзя заменить, режим `increment` снижает риск перезаписать существующие имена. Он не даёт транзакционных гарантий: сбой в середине списка оставляет уже созданные файлы.

Один тензор с batch-размером больше 1 не подходит как элемент списка. Вспомогательная функция снимает четырёхмерную batch-ось только при размере 1; `[B,H,W,C]` с `B > 1` до Pillow не приводится.

## Короткий рецепт подключения

1. Подайте списочный `IMAGE` во вход `images`.
2. В `folder_name` задайте подпапку внутри `output`.
3. Укажите основу имени в `filename_prefix`.
4. Для диагностического запуска выберите `increment`.
5. После проверки замените ноду на `SaveImage`, если граф не зависит от её списочной семантики.

Fragment «Сохранить IMAGE-список без перезаписи имён» содержит одну устаревшую ноду с `folder_name = dataset`, `filename_prefix = image` и `mode = increment`. Он документирует точный контракт старого графа, а не официальный workflow; импорт fragment не выполнялся.

## Входы, выходы и параметры

`images` — обязательный вход `IMAGE`, который из-за `is_input_list` приходит как Python-список. Поддерживаются элементы `[1,H,W,C]`, `[H,W,C]` и некоторые `[C,H,W]`: channel-first распознаётся при 1, 3 или 4 каналах и пространственных осях больше 4.

`folder_name` по умолчанию равен `dataset`; `filename_prefix` — `image`. Поскольку вся нода списочная, эти скаляры тоже поступают как списки, а метод берёт только элемент с индексом 0.

`mode = overwrite` создаёт `prefix_00000.png`, `prefix_00001.png` и далее. `mode = increment` спрашивает общий счётчик у `get_save_image_path` для каждого элемента и в чистой папке создаёт имена вида `prefix_00001_00000.png`, затем `prefix_00002_00001.png`.

Выходов нет. Поля `prompt` и `extra_pnginfo`, видимые как скрытые runtime-входы выходной ноды, метод не записывает в PNG.

## Типовые связки

Историческая связка — `LoadImageDataSetFromFolder → SaveImageDataSetToFolder` после поэлементного преобразования. Источник выдаёт список отдельных `[1,H,W,C]`, под который рассчитана нода сохранения.

Для нового графа используйте `SaveImage`: путь `dataset/image` в `filename_prefix` создаёт подпапку через штатный механизм `output`. `SaveImageAdvanced` нужен, когда важны разрядность, формат или расширенные параметры записи.

Если данные сопровождаются подписями, эта нода их игнорирует. `SaveImageTextDataSetToFolder` создаёт одноимённые TXT, но перед ним нужно проверить соответствие длин.

## Практический пример

Полный просмотр пакета workflow 0.1.42 охватил 512 JSON, 496 корневых workflow и 272 подграфа. `SaveImageDataSetToFolder` не встречается ни в одном, поэтому официального примера старой ноды для копирования нет.

В изолированном временном каталоге точный класс сохранил два элемента как `sample_00000.png` и `sample_00001.png`. Повторный `overwrite` с одним элементом заменил первый файл, но не удалил старый `sample_00001.png`. В `increment` два элемента получили имена `sample_00001_00000.png` и `sample_00002_00001.png`.

Отдельная проверка передала вспомогательной функции один элемент формы `[2,5,6,3]`; Pillow отклонил четырёхмерный массив. Пользовательский fragment в интерфейсе не исполнялся.

## Частые ошибки и способы проверки

**Старые PNG остались после `overwrite`.** Режим заменяет совпавшие имена, но не очищает папку. Если новый список короче, файлы с большими индексами сохраняются. Очищайте отдельный каталог вручную только после проверки пути и резервной копии.

**Ошибка Pillow о типе или форме.** Проверьте каждый элемент списка. Ожидается отдельное изображение, обычно `[1,H,W,C]`, а не целый batch внутри одного элемента.

**Файлы неожиданно стали темнее или ярче.** Нода считает вход нормализованным в 0–1. Значения умножаются на 255 и обрезаются; HDR-диапазон и float-точность в PNG не сохраняются.

**Путь отвергнут как выходящий из `output`.** Уберите `..`, абсолютный путь и символьные ссылки наружу. `folder_name` должен разрешаться внутри настроенного output-каталога.

**Нода отмечена deprecated, но автоматической замены нет.** В `/api/node_replacements` для неё нет записи. Рекомендация `SaveImage` взята из комментария исходника и требует ручной проверки графа.

## Производительность и внутреннее поведение

Сохранение идёт последовательно на CPU. Для каждого элемента создаются NumPy-массив `uint8` и объект Pillow, затем PNG кодируется на диск. GPU не используется.

Метод создаёт целевой каталог до обработки списка. При ошибке на позднем элементе ранние PNG остаются. Отката, временного файла и атомарной публикации набора нет.

В `increment` каталог перечитывается для вычисления счётчика перед каждым файлом. На очень большой папке это добавляет повторные обходы. `overwrite` проще по именам, но может оставить старый хвост набора.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7` и `comfy_extras.nodes_dataset`. Runtime fingerprint: `sha256:bb2e065b0d23b4fe81c9dfc54161a666905a13812c869239424973101817ee0c`.

Runtime-флаги: `experimental = true`, `deprecated = true`, `dev_only = false`, `api_node = false`. Формального объявления в Node Replacement API нет. Связь `replacedBy: core.save-image` в Wizard редакционная и опирается на прямой комментарий закреплённого исходника.

Embedded docs 0.5.9 называют ноду deprecated и верно указывают отсутствие выходов, но полностью пропускают `mode`, восьмибитную конвертацию, правила формы, остаточные файлы и рекомендованную замену.
