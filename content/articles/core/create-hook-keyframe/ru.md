# CreateHookKeyframe

## Что делает нода

`CreateHookKeyframe` создаёт одну точку расписания хука. Точка содержит `strength_mult` и `start_percent`. Если подключена предыдущая группа `HOOK_KEYFRAMES`, нода создаёт отдельную группу и отдельные объекты ключевых кадров, затем добавляет новую точку и возвращает объект с именем выхода `HOOK_KF`. Значение `strength` внутри кадра копируется обычным присваиванием; для штатного числа это безопасно, но называть такую операцию безусловно глубоким клонированием неточно.

`strength_mult` — множитель исходной силы хука, а не самостоятельная сила модели. Для весового хука с `strength_model=0.8` текущий кадр 0,5 даст итоговый модельный коэффициент 0,4.

## Где ставить её в графе

Для последовательности соедините несколько экземпляров через `prev_hook_kf`. Выход последней ноды направьте в `SetHookKeyframes`, а уже его `HOOKS` — в потребитель. Сам `HOOK_KF` не подключается к сэмплеру или conditioning напрямую.

Чтобы задать изменение в середине сэмплирования, обычно нужны как минимум две точки: исходное значение при 0 и новое значение позже. Одна точка с процентом 0,5 не означает автоматически «до половины использовать 1, после половины — указанную силу».

## Что известно об официальных графах

Официальный пакет графов 0.1.42 не содержит `CreateHookKeyframe`. Полный обход охватил 512 JSON, 496 корневых графов, 272 подграфа и 8120 нод. Точного или отличающегося только регистром NodeId нет.

Поэтому двухступенчатый рецепт Wizard построен по исходнику. Он не воспроизводит опубликованный граф и не утверждает качество конкретной LoRA. Модельное выполнение не проводилось.

## Входы, выход и диапазоны

Обязательные параметры:

- `strength_mult` — число от −20 до 20, шаг 0,01, исходно 1;
- `start_percent` — число от 0 до 1, шаг 0,001, исходно 0.

Необязательный `prev_hook_kf` имеет тип `HOOK_KEYFRAMES`. Выходной тип — `HOOK_KEYFRAMES`, но видимое имя порта — `HOOK_KF`. Нода экспериментальная и находится в `advanced/hooks/scheduling`.

Отрицательный множитель разрешён. Это инверсия направления патча, а не обычное ослабление. Допустимый диапазон не является рекомендацией качества.

## Клонирование, сортировка и одинаковые проценты

При отсутствии `prev_hook_kf` создаётся пустая группа. При наличии группа клонируется вместе с каждым ключевым кадром. Затем новая точка добавляется и весь список стабильно сортируется по `start_percent`. Исходная группа остаётся неизменной.

Точки с одинаковым процентом не объединяются. Стабильная сортировка сохраняет прежний порядок: существующая точка 8 при 0,8 остаётся перед новой точкой 3 при 0,8. Для цепочки одиночных нод каждая новая точка получает `guarantee_steps=1`, поэтому совпавшие точки способны удерживаться по одному шагу. В расписании CLIP тот же набор трактуется иначе: при одинаковом проценте для диапазона остаётся последняя точка.

## Как процент становится моментом переключения

Во время инициализации `start_percent` преобразуется методом `model_sampling.percent_to_sigma`. Это зависит от модели и её схемы шума. Равные интервалы процентов не обязаны соответствовать равному числу фактических шагов конкретного сэмплера.

Группа сразу выбирает первую отсортированную точку как текущую. При инициализации каждый процент переводится в sigma. Во время partial denoise точки, чья sigma находится раньше максимальной sigma текущего запуска, получают эффективную гарантию 0 и могут быть пропущены. За один вызов проверка способна перескочить несколько кадров с нулевой гарантией. Практическое правило: явно создавайте начальную точку при 0 и проверяйте расписание на фактическом диапазоне sigma используемого сэмплера.

## Проверенный рецепт

Общий с `SetHookKeyframes` рецепт создаёт две ноды `CreateHookKeyframe`: 1 при 0 и 0 при 0,5. Первая выдаёт начальную группу, вторая добавляет поздний переход через `prev_hook_kf`. Затем расписание назначается внешней группе `HOOKS`.

Связи и числовые диапазоны проверены по `/object_info`. Рецепт не содержит LoRA или checkpoint и не запускает сэмплирование. Замените значения под свою задачу только после проверки начальной точки и порядка процентов.

## Частые ошибки и диагностика

- Создать единственную позднюю точку и ждать неявной силы 1 до неё.
- Перепутать имя выхода `HOOK_KF` с типом `HOOK_KEYFRAMES`.
- Подать `HOOK_KF` прямо в `ConditioningSetProperties`: сначала нужен `SetHookKeyframes`.
- Создать одинаковые проценты, не учитывая стабильный порядок и `guarantee_steps`.
- Считать отрицательный множитель обычным затуханием.

Для диагностики распечатайте или отдельно проверьте пары «процент — сила» до назначения хукам. Начинайте с двух простых точек при 0 и 1, затем добавляйте промежуточные.

## Производительность и внутреннее поведение

Каждый вызов клонирует всю предыдущую последовательность. При длинной цепочке из отдельных нод это даёт повторное копирование уже созданных точек. Для десятков значений эффективнее `CreateHookKeyframesInterpolated` или `CreateHookKeyframesFromFloats`.

Безмодельная проверка подтвердила отдельные объекты группы и кадров, сортировку точки −2 при 0,2 перед прежней точкой 8 при 0,8 и сохранение порядка двух точек при 0,8. Исходник потребления расписания отдельно проверен для преобразования процентов в sigma, эффективной гарантии и последовательного поиска следующих кадров; полный сэмплер с моделью не запускался.

## Совместимость и источники

Материал относится к ComfyUI 0.32.0 и встроенной клиентской части 1.48.7. Точные порты, диапазоны и поисковые псевдонимы взяты из `/object_info`; формальной замены нет.

Создание точки сверено по `comfy_extras/nodes_hooks.py`, а сортировка, клонирование, `guarantee_steps` и преобразование процента — по `comfy/hooks.py`. Встроенная документация 0.5.9 верно описывает базовое назначение, но русская страница переводит системные имена входов. Редактор пока не проверил материал вручную.
