# AlignYourStepsScheduler: расписание AYS для SD1, SDXL и SVD

`AlignYourStepsScheduler` возвращает подготовленную последовательность уровней шума для одного из трёх семейств: SD1, SDXL или SVD. При десяти шагах она использует закреплённую таблицу без пересчёта; при другом числе шагов строит log-linear интерполяцию.

## Что делает нода

Нода формирует `SIGMAS` для custom sampling. Она не принимает модель и не выполняет денойзинг. Выбор `model_type` означает только выбор одной из трёх таблиц; он не анализирует checkpoint и не подтверждает, что таблица ему подходит.

В каждой исходной таблице одиннадцать положительных уровней, то есть десять переходов до принудительного конечного нуля. SD1 и SDXL начинаются примерно с 14,61, а SVD — с 700. Разница существенна, поэтому неверный preset нельзя считать косметической настройкой.

## Место в графе

Выход `SIGMAS` подключают к `SamplerCustomAdvanced` или другой ноде, которая принимает этот тип. Остальные компоненты — `NOISE`, `GUIDER`, `SAMPLER` и `LATENT` — собираются отдельно.

Поскольку у scheduler нет входа `MODEL`, ComfyUI не может автоматически сопоставить таблицу с моделью guider. Пользователь сам отвечает за пару `model_type` и checkpoint. Для неизвестной или изменённой sampling-конфигурации безопаснее сначала сравнить диапазон SIGMAS с расписанием, рассчитанным из самой модели.

## Входы

- `model_type` — `SD1`, `SDXL` или `SVD`.
- `steps` — целое число от 1 до 10000, по умолчанию 10. Оно задаёт число переходов до возможного сокращения по `denoise`.
- `denoise` — число от 0 до 1, по умолчанию 1, с шагом интерфейса 0,01.

Входа `MODEL` нет. Название `model_type` — выбор таблицы, а не runtime-проверка архитектуры.

## Выход

Нода возвращает один тензор `SIGMAS`. При `steps = 10` и `denoise = 1` он содержит одиннадцать значений: исходные десять верхних уровней и ноль вместо последнего минимального уровня таблицы.

При частичном denoise остаётся хвост длиной `round(steps * denoise) + 1`. Для `denoise <= 0` возвращается пустой `FloatTensor`. Малое положительное значение ведёт себя иначе: если округление даёт ноль, остаётся только последний элемент, который заменяется нулём, то есть результат равен `[0]`.

## Как работает расписание

Для SDXL исходный ряд начинается `14.6146412293, 6.3184485287, 3.7681790315` и заканчивается `0.0291671582`. У SD1 отличается середина, а у SVD ряд идёт от `700` до `0.002`. Если `steps + 1` не равно 11, функция разворачивает значения, берёт их логарифмы, интерполирует по равномерной оси и разворачивает результат обратно.

После интерполяции нода считает `total_steps`. При частичном denoise используется Python `round`, затем из расписания берётся хвост `total_steps + 1`, и его последнее значение принудительно становится нулём. Это сокращение выбрасывает самые шумные точки, а не равномерно разрежает уже готовый ряд.

## Параметры и настройка

Для нативной AYS-таблицы используйте десять шагов. Другие значения допустимы, но это уже вычисленная log-linear сетка между закреплёнными точками, а не новая оптимизированная таблица. Особенно большие значения создают много интерполированных уровней и затем столько же дорогих model-переходов в sampler.

`denoise` выбирает хвост через округление. Например, при десяти шагах и `denoise = 0,5` остаются пять переходов и завершающий ноль. На половинных границах действует стандартное округление Python к ближайшему чётному, поэтому не стоит выводить точную длину только из десятичной записи без проверки.

## Проверенный пример

Учебный fragment Wizard задаёт `model_type = SDXL`, `steps = 10`, `denoise = 1` и подключает результат к `SamplerCustomAdvanced`. Noise, guider, sampler и latent оставлены внешними портами, чтобы рецепт не притворялся полным SDXL workflow без checkpoint и conditioning.

Полный просмотр 512 JSON официального wheel 0.1.42, включая 272 subgraph, не нашёл `AlignYourStepsScheduler`. Поэтому fragment помечен как пример, выведенный из source и runtime-схемы, а не как официальный кейс. Exact-метод проверен для нативной таблицы, интерполяции, половинного denoise, нуля и малого положительного denoise. Модель и полный sampling не запускались. Редактор пока не проверил материал вручную.

## Частые ошибки

- Для SDXL выбран `SVD`: диапазоны отличаются на порядки, а автоматической проверки нет.
- `steps = 20` принимается за официальную двадцатишаговую AYS-таблицу: это интерполяция одиннадцати исходных точек.
- `denoise = 0` ожидается как `[0]`: эта ветвь возвращает пустой тензор.
- Очень малый положительный denoise ожидается как пустой результат: после округления возможен `[0]`.
- Scheduler подключён к guider другой модельной семьи.
- Изменение `steps` оценивается только по длине, без просмотра диапазона и монотонности SIGMAS.

## Ограничения и производительность

Сама интерполяция недорогая и выполняется на CPU через NumPy; результат затем создаётся как CPU `FloatTensor`. Стоимость всего графа растёт уже в sampler примерно вместе с числом переходов.

Таблицы фиксированы и не читают sampling-настройки конкретного `MODEL`. Нода также не предупреждает о несовпадении семейства, не измеряет качество и не подбирает число шагов. Для нестандартных model-patch сценариев это сознательная ручная ответственность.
