# Image Grid: разложить IMAGE-бэтч по ячейкам одного холста

`ImageGrid` превращает несколько кадров в один коллаж. Нода распрямляет входной IMAGE-бэтч или список, масштабирует каждый кадр до одинаковой ячейки и вставляет их слева направо, строка за строкой, на чёрный RGB-холст.

## Вход читается как список кадров

Runtime помечает ноду `is_input_list = true`. Базовый класс принимает либо IMAGE-тензор `[B, H, W, C]`, либо список таких тензоров и распрямляет каждый бэтч до элементов формы `[1, H, W, C]`.

Поэтому BatchImagesNode с `[A, B, C]` на выходе становится для ImageGrid тремя ячейками. Если в list-вход поступают два бэтча, сохраняется их последовательность, а внутри каждого — порядок кадров.

## Число строк вычисляется автоматически

Пользователь задаёт `columns` от 1 до 20. Строки считаются как `ceil(N / columns)`, точнее `(N + columns − 1) // columns`. Отдельного параметра rows нет.

Кадр с индексом `i` получает строку `i // columns` и столбец `i % columns`. Раскладка идёт слева направо, затем переходит на следующую строку.

## Размер холста следует точной формуле

Ширина равна `columns × cell_width + (columns − 1) × padding`. Высота — `rows × cell_height + (rows − 1) × padding`. `cell_width` и `cell_height` допускают 32–2048, `padding` — 0–50 пикселей.

Например, два кадра при `columns = 2`, ячейке `256 × 256` и `padding = 4` дают один IMAGE размером `516 × 256`. Внешней рамки нет: отступ добавляется только между соседними ячейками.

## Каждый кадр растягивается до ячейки

Нода вызывает PIL `resize((cell_width, cell_height), LANCZOS)` независимо по ширине и высоте. Она не сохраняет исходное соотношение сторон и не добавляет letterbox-поля.

Квадратная ячейка сделает прямоугольный кадр квадратным. Чтобы избежать искажения, сначала подготовьте кадры нодой, которая явно сохраняет пропорции и добавляет поля, либо задайте ячейку с нужным отношением сторон.

## Незаполненные ячейки остаются чёрными

Холст создаётся сразу на полное число столбцов. Если последняя строка неполная, её правые ячейки не обрезаются и остаются фоном `(0, 0, 0)`.

При пяти кадрах и четырёх столбцах получается две строки и три пустых чёрных позиции во второй. Это влияет на итоговую ширину и композицию; автоматически центрировать неполную строку нода не умеет.

## Преобразование проходит через 8-битный PIL RGB

Каждый tensor умножается на 255, ограничивается диапазоном 0–255 и переводится в `uint8`. Итоговый холст создаётся в режиме PIL `RGB`, затем возвращается как float-тензор, поделённый на 255.

Значит, ImageGrid не является точным tensor-preserving композитором: дробная точность квантуется до 8 бит, а альфа не сохраняется в RGB-результате. Для технических промежуточных данных лучше не использовать коллаж как обратимое преобразование.

## Выход — один IMAGE, а не новый бэтч

Runtime output имеет `output_is_list = false`; результат содержит один холст с batch size 1. Все входные кадры уже нарисованы внутри его пространственных координат.

Это обратная задача по отношению к BatchImagesNode. Batch Images сохраняет кадры раздельными под batch-осью, а ImageGrid объединяет их визуально в один кадр.

## Пустой список вызывает ошибку

Реализация явно проверяет `len(images) == 0` и выбрасывает `ValueError`. Нужен хотя бы один фактический IMAGE-элемент.

При одном кадре rows равен 1, но ширина всё равно рассчитывается по заданному `columns`. Если `columns = 4`, справа останутся три чёрные ячейки. Для одиночного входа обычно разумно поставить один столбец.

## В ComfyUI 0.32.0 нода экспериментальная

Базовая schema для этого семейства выставляет `is_experimental = true`, и runtime inventory подтверждает `experimental: true`. Формат входов и поведение могут измениться быстрее, чем у стабильных core-нод.

В полном scan workflow wheel 0.1.42 нет ни одного ImageGrid — ни в корневых графах, ни в subgraph. Поэтому эта статья опирается на закреплённые source/runtime, а не выдаёт синтетический пример за официальный template-case.

## Fragment строит небольшую contact sheet

Рецепт получает два внешних IMAGE, собирает их через BatchImagesNode и передаёт бэтч в ImageGrid с двумя столбцами, ячейками `256 × 256` и четырьмя пикселями между ними. Preview Image показывает один холст `516 × 256`.

Топология выведена из source-контрактов и не найдена в официальном wheel. Формула размера и 8-битное округление проверены в чистой Python-модели, но PIL и сама нода не запускались. Fragment в ComfyUI не исполнялся. Редактор пока не проверил материал вручную.
