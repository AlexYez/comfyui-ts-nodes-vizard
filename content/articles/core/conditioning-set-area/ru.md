# ConditioningSetArea: прямоугольная область в пикселях

## Назначение

`ConditioningSetArea` назначает каждой записи `CONDITIONING` прямоугольную область и коэффициент силы. В интерфейсе размеры и смещения задаются как целые пиксельные значения, но нода сразу делит их на 8 и сохраняет latent-координаты.

Embedding при этом не обрезается и не пересчитывается. Нода меняет metadata, по которой sampler позже выбирает пространственный участок.

## Место в графе

Обычно `conditioning` приходит от `CLIPTextEncode`. После назначения area запись объединяют с общим conditioning либо подают на соответствующую сторону сэмплера. Для фона нужна отдельная запись без area или с областью всего кадра: одна локальная запись сама не описывает содержание за пределами прямоугольника.

`ConditioningSetAreaPercentage` решает похожую задачу в долях от текущего latent-размера. `ConditioningSetMask` использует произвольную маску. Пиксельная area удобна для фиксированного разрешения, относительная — для графа, который меняет размер кадра.

## Входы

`conditioning` — список `CONDITIONING`; прямоугольник применяется ко всем его записям.

`width` и `height` — размеры от 64 до 16 384 с шагом 8, по умолчанию 64. `x` и `y` — смещение левого верхнего угла от 0 до 16 384, также с шагом 8.

`strength` — число от 0,00 до 10,00, по умолчанию 1,00. Это общий множитель записи внутри area. Он отличается от `mask_strength` у `ConditioningSetMask`.

## Выход

Выход содержит столько же записей `CONDITIONING`, сколько вход. Для каждой нода сохраняет исходный тензор, копирует metadata и записывает:

- `area: (height // 8, width // 8, y // 8, x // 8)`;
- `strength` из виджета;
- `set_area_to_bounds: false`.

Если эти ключи уже существовали, новые значения их заменяют. Прочие поля, включая маску и временной диапазон, сохраняются.

## Как работает

При подготовке sampling значение `area` читается в порядке «размеры, затем смещения»: высота, ширина, y, x. Sampler ограничивает размер прямоугольника оставшейся частью latent и обрезает `input_x` до выбранного участка. Conditioning для модели также обрабатывается с этой area.

Если у записи нет маски, sampler смягчает границы прямоугольника: на краях используется переход шириной до восьми latent-ячеек, но не более четверти размера области. Это служебное поведение sampler, а не отдельный параметр ноды.

## Параметры и настройка

Для кадра 1024 × 1024 область `width: 512`, `height: 512`, `x: 0`, `y: 0` задаёт левую верхнюю четверть. Выбирайте значения, кратные восьми: такой шаг задан runtime и совпадает с целочисленным делением в реализации.

Координаты не сверяются с фактическим размером текущего latent в самой ноде. Держите `x < canvas_width`, `y < canvas_height`, а также `x + width ≤ canvas_width` и `y + height ≤ canvas_height`, если не хотите обрезки у края. Число 16 384 — граница виджета, а не размер активного кадра.

## Проверенный пример

Fragment-only рецепт «Область 512 × 512 в пиксельных координатах» принимает внешний `CONDITIONING` и задаёт `width: 512`, `height: 512`, `x: 0`, `y: 0`, `strength: 1.0`. Он рассчитан на canvas не меньше 512 × 512. Поля и типы сверены с `/object_info`, tuple metadata — с `nodes.py`.

Exhaustive-поиск по 512 official workflow templates JSON 0.1.42, включая подграфы, не нашёл `ConditioningSetArea`. Поэтому официальных widget values и соседних нод для закреплённой версии нет. Fragment структурно проверен, но sampling не выполнялся.

## Частые ошибки

**Координаты принимают за latent-ячейки.** Виджеты задаются в пиксельном масштабе, а нода делит каждое число на 8. Если передать 64, в metadata попадёт 8.

**Прямоугольник выходит за кадр.** Максимумы виджетов не зависят от текущего разрешения. Sampler может обрезать размер у края, а смещение вне latent способно привести к пустой или недопустимой области.

**От локального prompt ждут заполнения всего кадра.** Area ограничивает одну запись. Для остального изображения нужны другие совместимые условия.

**После маски меняется поведение bounds.** `ConditioningSetArea` всегда пишет `set_area_to_bounds: false`; порядок с `ConditioningSetMask` важен.

## Ограничения и производительность

Сама нода только копирует metadata. При sampling локальная запись обрабатывается на обрезанном участке latent, поэтому небольшая area может уменьшить работу именно для этой записи. Несколько перекрывающихся областей добавляют отдельные условия и могут вернуть часть затрат.

Делитель 8 жёстко записан в классе и не вычисляется из активной модели. Статья не переносит эту схему на архитектуры с другой пространственной организацией latent без отдельной проверки. Сила выше 1 усиливает множитель, но не гарантирует пропорциональное визуальное изменение.
