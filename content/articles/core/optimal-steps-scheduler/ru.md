# OptimalStepsScheduler: таблицы для FLUX, Wan и Chroma

`OptimalStepsScheduler` строит `SIGMAS` из одной из трёх закреплённых таблиц: FLUX, Wan или Chroma. У таблиц разная нативная длина, а любое другое число шагов получается log-linear интерполяцией.

## Что делает нода

Нода готовит расписание уровней шума для custom sampling. Она не получает `MODEL` и не запускает sampler. Параметр `model_type` лишь выбирает массив чисел; название checkpoint, его конфигурация и предыдущие model-патчи не проверяются.

FLUX содержит десятишаговый ряд, Wan — двадцатишаговый, Chroma — сорокашаговый. Это означает, что одно и то же значение `steps` может сохранить исходную таблицу для одного семейства и включить интерполяцию для другого.

## Место в графе

Выход `SIGMAS` ведите в `SamplerCustomAdvanced` или другую совместимую sampling-ноду. Noise, guider, sampler и latent подключаются отдельно. `MODEL` для guider должен соответствовать выбранному семейству и его sampling-шкале.

Типовая связь проверяет только `SIGMAS → sigmas`. ComfyUI не сравнивает строку `model_type` с моделью внутри guider. Ошибка выбора может проявиться уже во время генерации как неподходящая траектория шума, а не как сообщение о несовместимых портах.

## Входы

- `model_type` — один из вариантов `FLUX`, `Wan`, `Chroma`.
- `steps` — целое число от 3 до 1000, по умолчанию 20.
- `denoise` — число от 0 до 1 с шагом интерфейса 0,01, по умолчанию 1.

У ноды нет входов `MODEL`, `SAMPLER` или `LATENT`. Она возвращает только числовое расписание.

## Выход

Единственный выход имеет тип `SIGMAS`. При полном denoise его длина равна `steps + 1`; последний элемент принудительно равен нулю. Исходный минимальный уровень таблицы `0.001` в финальном результате заменяется, а не дополняется отдельным нулём.

Для частичного denoise остаётся хвост длиной `round(steps * denoise) + 1`. Ноль и малое положительное значение различаются: `denoise <= 0` возвращает пустой тензор, а округление положительного произведения до нуля даёт `[0]`.

## Как работает расписание

FLUX хранит 11 значений от `0.9968` до `0.001`, Wan — 21 значение от `1.0` до `0.001`, Chroma — 41 значение от `0.992` до `0.001`. Нативное число переходов равно соответственно 10, 20 и 40.

Если `steps + 1` не совпадает с длиной выбранного массива, функция интерполирует логарифмы развёрнутого ряда по равномерной оси и возвращает значения в убывающем порядке. После этого применяется хвост denoise и финальный элемент заменяется нулём. Поэтому default `steps = 20` сохраняет Wan без интерполяции, но пересчитывает FLUX и Chroma.

## Параметры и настройка

Чтобы использовать таблицу без математического пересчёта, задайте FLUX 10, Wan 20 или Chroma 40 шагов. Другие значения разрешены и могут быть осмысленны, но представляют интерполяцию исходного ряда, а не отдельный опубликованный preset.

`denoise` выбрасывает начало уже построенной последовательности. При двадцати шагах и `denoise = 0,5` останется десять переходов и завершающий ноль. Расчёт использует Python `round`, поэтому около границ длина меняется ступенчато.

## Проверенный пример

Fragment Wizard выбирает `Wan`, `steps = 20`, `denoise = 1` и подключает `SIGMAS` к `SamplerCustomAdvanced`. Это нативная длина Wan-таблицы: интерполяция не включается. Модель, guider, noise, sampler и latent намеренно остаются внешними.

Exhaustive-просмотр wheel 0.1.42 охватил 512 JSON, 496 root workflow и 272 subgraph; `OptimalStepsScheduler` не встретился. Следовательно, fragment основан на source/runtime, а не выдан за официальный workflow. Exact-метод проверен для нативных длин всех трёх семейств, интерполяции default FLUX 20, частичного и нулевого denoise. Реальная модель и полный sampling не запускались. Редактор пока не проверил материал вручную.

## Частые ошибки

- `model_type = FLUX` выбран для Wan-модели или наоборот: входа `MODEL` нет, предупреждения не будет.
- Default 20 считается нативным для всех вариантов: без интерполяции он работает только для Wan.
- Исходный `0.001` ожидается в конце: реализация заменяет последний элемент нулём.
- `denoise = 0` ожидается как `[0]`: результат пуст.
- Очень малый положительный denoise принимается за один полноценный переход: он может дать лишь `[0]`.
- Тысяча шагов выбирается без оценки времени model-вызовов.

## Ограничения и производительность

Расчёт короткой нативной таблицы почти бесплатен; интерполяция выполняется на CPU через NumPy. Производительность полного графа определяется sampler и числом переходов. Разрешённое значение 1000 технически создаёт расписание, но может сделать генерацию чрезмерно долгой.

Таблицы не адаптируются к checkpoint, разрешению, prompt или выбранному sampler. Название «Optimal» относится к имени реализации и не является гарантией лучшего качества для любого графа. Сравнение вариантов требует одинаковых seed, модели, sampler и остальных настроек.
