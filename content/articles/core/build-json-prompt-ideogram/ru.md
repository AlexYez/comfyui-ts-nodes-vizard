# Build JSON Prompt (Ideogram)

## 1. Назначение

`BuildJsonPromptIdeogram` превращает несколько текстовых полей, палитру и массив объектов в структурированный словарь `DICT`. Формат рассчитан на Ideogram 4: в нём отдельно хранятся общее описание, стиль и композиция.

Нода не кодирует текст в `CONDITIONING`, не обращается к сети и не запускает генерацию. Она только собирает данные. Чтобы увидеть содержимое, подключите выход к `PreviewAny`; чтобы получить изображение, передайте словарь совместимой API-ноде.

## 2. Место в графе

Штатная связка начинается с `CreateBoundingBoxes`. Его выход `elements` содержит тип области, координаты, подпись, описание и палитру; этот массив приходит на `element`. Выход `prompt` затем передают ноде Ideogram, которая умеет принять `DICT` и отправить запрос.

Использовать ноду без рамок тоже можно: подайте пустой массив. В словаре всё равно появится `compositional_deconstruction` с фоном и пустым списком элементов. Если нужный потребитель принимает обычную строку, эта нода не подходит без дополнительного преобразования.

## 3. Входы

`element` — обязательный `ARRAY`. Любое значение, которое не является списком на уровне Python, тихо превращается в пустой список. `high_level_description` — рекомендуемое общее описание; пустая или состоящая только из пробелов строка не добавляет соответствующий ключ.

`background`, `aesthetics`, `lighting` и `medium` технически имеют пустые значения по умолчанию. Подсказки называют обязательными все четыре поля, однако серверная часть пустые строки не отклоняет. `color_palette` — виджет `COLORS`; интерфейс 1.48.7 разрешает до 16 цветов.

`style` — динамический выбор. Вариант `none` не имеет вложенных полей. `photo` открывает строку `photo`, а `art_style` — одноимённое описание художественного стиля.

## 4. Выход

Единственный выход `prompt` имеет тип `DICT`. Ключ `compositional_deconstruction` присутствует всегда:

`{"background": background, "elements": elements}`.

`high_level_description` появляется только для непустого после `.strip()` текста, но в словарь записывается исходная строка вместе с ведущими и конечными пробелами. `style_description` отсутствует при `style = none`. Нода не сериализует JSON-строку: это обычный словарь в памяти графа.

## 5. Как собирается словарь

Сервер читает из динамического значения ключ `style`. Для `photo` создаётся объект с `aesthetics`, `lighting`, `photo` и `medium`. Для остальных ненулевых вариантов код попадает в художественную ветвь и добавляет `art_style`.

Палитра включается только внутрь `style_description`. Поэтому при `style = none` даже непустой `color_palette` не попадёт в результат. Функция нормализации сохраняет непустые строки и переводит их в верхний регистр; она не проверяет, что строка действительно имеет вид `#RRGGBB`.

Сам метод `execute` получает `style` как словарь. Если вызвать этот Python-метод напрямую и передать строку, код выберет `none`. Это не относится к запросу `/prompt`: там динамический вход записывается плоскими полями, например `"style": "photo"` и `"style.photo": "35mm"`, а исполнитель ComfyUI собирает из них словарь перед вызовом ноды.

## 6. Значения стиля

Для `photo` поле `photo` предназначено для оптики и съёмки: например, `35mm, f/1.4, bokeh`. В официальном примере там стоит `editorial`. Подсказка рекомендует при этом явно задать `medium = photograph`, но код не исправляет несовместимое или пустое значение.

Для `art_style` укажите технику или визуальный язык в `art_style`; `medium` остаётся отдельным полем. `aesthetics` отвечает за общее впечатление, `lighting` — за свет. Это рекомендации формата, а не валидируемые перечисления: любые строки проходят без проверки.

Палитра элементов из `CreateBoundingBoxes` и общая `color_palette` — разные уровни. Первая описывает конкретные области, вторая попадает в общий объект стиля.

## 7. Проверенный пример

Официальный граф `api_ideogram_p_image_t2i` передаёт пять элементов обложки из `CreateBoundingBoxes`. У `BuildJsonPromptIdeogram` выбраны `style = photo`, `style.photo = editorial`, тёмный фон, редакционная эстетика, направленный свет и четыре цвета: `#0a1628`, `#ffffff`, `#8b0000`, `#c9a227`.

Выход связан с `PreviewAny.source`, после чего строковое представление уходит в поле `prompt` ноды `IdeogramPImage`. Рецепт Wizard сохраняет проверенную часть до предпросмотра. Он не содержит API-ключа, не расходует кредиты и не выдаёт структуру за исполненный запрос.

## 8. Ошибки и диагностика

Если `style_description` исчез, сначала проверьте `style`: при `none` это штатное поведение. Если пропала палитра, убедитесь, что стиль не `none` и список содержит непустые строки. Регистр цветов изменится на верхний.

Отсутствие `high_level_description` при строке из пробелов тоже штатно. При этом `background` остаётся в словаре даже пустым. Нода не сообщает, что рекомендуемые поля не заполнены; проверять итог удобно через `PreviewAny`.

При ручном вызове `BuildJsonPromptIdeogram.execute` передавайте `{"style": "photo", "photo": "35mm"}`. В JSON-запросе к `/prompt` используйте плоскую запись: `"style": "photo"` и `"style.photo": "35mm"`. Смешивать эти два контракта нельзя.

## 9. Ограничения и производительность

Операция выполняет только сборку небольшого Python-словаря и практически не влияет на время или память графа. GPU, модель и тензоры ей не нужны. Размер массива `element` кодом не ограничивается, хотя слишком подробная структура может быть неудобна или неприемлема для последующего API.

Валидации схемы Ideogram нет: нода не проверяет поля входных элементов, длину описаний, допустимость цветов и обязательность фона. Часть ограничений обеспечивает интерфейс, но прямой вызов Python-метода может передать больше 16 цветов или произвольные строки.

Wizard проверил обе формы вызова — прямую и через `/prompt`. Точный `execute` выполнен для ветвей `none`, `photo`, `art_style` и для ошибочного строкового значения вместо словаря. Отдельная проверка воспроизвела преобразование плоских полей `/prompt` во вложенный динамический вход. Внешняя генерация не выполнялась.
