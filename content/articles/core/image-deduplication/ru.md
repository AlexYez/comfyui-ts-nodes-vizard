# ImageDeduplication: фильтр по 64-битному усреднённому хешу

## Что делает нода

`ImageDeduplication` принимает полный список изображений, вычисляет для каждого 64-битный усреднённый хеш (average hash) и удаляет последующие элементы, сходство которых с уже сохранёнными не меньше заданного порога.

Для хеша изображение переводится через Pillow в 8-битный вид, уменьшается до 8×8 фильтром LANCZOS и преобразуется в серый. Каждый из 64 пикселей даёт бит: 1, если он строго выше среднего значения этой миниатюры, иначе 0.

Сходство двух хешей равно `1 − HammingDistance / 64`. Если оно `>= similarity_threshold`, более позднее изображение считается дубликатом. Первое найденное представление сохраняется, порядок оставшихся элементов не меняется.

## Когда использовать и когда не использовать

Нода подходит для грубой очистки списка изображений от точных и визуально близких повторов перед просмотром или экспортом. Результат нужно проверить глазами: 64-битный хеш намеренно теряет много информации.

Не используйте её как доказательство пиксельного равенства. Цвет сбрасывается, разрешение сводится к 8×8, а сравнение идёт только по рисунку значений выше и ниже собственного среднего.

Для набора «изображение–подпись» отдельная ветка `texts` не фильтруется. Прямое применение `ImageDeduplication` только к изображениям разрушит соответствие индексов; нужен парный механизм, который удалит те же позиции из обеих веток.

## Короткий рецепт подключения

1. Подключите список или пакет `IMAGE` ко входу `images`.
2. Начните с исходного `similarity_threshold = 0.95`.
3. Сохраните исходный список отдельно, пока результат не проверен.
4. Просмотрите оставшиеся элементы и выборочно сравните удалённые пары.
5. Повышайте порог для более строгого совпадения; понижайте только после проверки ложных срабатываний.

Фрагмент «Отфильтровать список с порогом 0,95» содержит одну ноду и внешний `IMAGE`. Порог взят из схемы. Официальных графов с `ImageDeduplication` нет, а после импорта фрагмент не запускался.

## Входы, выходы и параметры

`images` — обязательный `IMAGE` с групповой списочной семантикой. Если приходит один тензор `[B,H,W,C]`, базовый класс делит его на `B` элементов `[1,H,W,C]`. Если приходит список таких тензоров, их оси пакетов также разворачиваются в плоский список.

Трёхмерный `[H,W,C]` как групповой вход не принимается: `_ensure_image_list` требует четыре измерения. Элементы списка могут иметь разные `H` и `W`, потому что каждый всё равно уменьшается до 8×8.

`similarity_threshold` — расширенный параметр `FLOAT` от 0 до 1, по умолчанию 0,95. Сравнение включительное. При 0,95 дубликатами становятся хеши с расстоянием Хэмминга 0, 1, 2 или 3; расстояние 4 даёт 0,9375 и уже проходит фильтр.

Выход `images` является списочным `IMAGE`. Индексы, оценки сходства, карта удалений и тексты не возвращаются.

## Типовые связки

`LoadImageDataSetFromFolder → ImageDeduplication` соответствует типам списочного выхода и группового входа. После фильтра можно собрать `ImageGrid` для визуальной проверки либо передать список в ноду сохранения, которая понимает отдельные изображения.

Не подключайте параллельный список подписей напрямую к другой ветке и не считайте его синхронным после фильтра. `ImageDeduplication` не сообщает, какие индексы удалены.

Порядок имеет смысл: при совпадении остаётся самый ранний элемент. Если нужен другой представитель группы, сначала упорядочьте набор осознанно.

Эти соединения следуют портам исполнения. Полный официальный пакет шаблонов 0.1.42 реального примера не содержит.

## Практический пример

Полная проверка 512 файлов JSON, 496 корневых графов и 272 подграфов не нашла `ImageDeduplication`. Официальный порог и схема пользовательского графа не подтверждены.

В точном прогоне два шаблона 8×8 различались одним битом хеша: сходство равнялось `0.984375`. При пороге ровно `0.984375` второй был удалён из-за сравнения `>=`; при пороге на 0,0001 выше оба сохранились. При исходном пороге 0,95 тот же элемент был удалён.

Чёрное изображение 8×8 и белое 10×6 получили одинаковый нулевой усреднённый хеш. При пороге 1,0 осталось только чёрное, стоявшее первым. Даже максимальный порог не означает пиксельного совпадения.

Проверка также подтвердила пустой выход для пустого списка, сохранение только первого элемента при пороге 0 и разворачивание пакета в отдельные изображения. Фрагмент на холсте не запускался.

## Частые ошибки и способы проверки

**Разные однотонные изображения признаны дублями.** У однотонной миниатюры каждый пиксель равен среднему, условие `p > avg` везде ложно. Цвет и яркость не различаются.

**При пороге 1 удалилось неидентичное изображение.** Единица требует одинакового 64-битного хеша, а не одинаковых исходных пикселей. Коллизии и потеря деталей допустимы по алгоритму.

**Удаляется слишком много.** Повышайте порог и сравнивайте конкретные пары. Учитывайте дискретный шаг сходства: `1/64 = 0.015625`.

**Подписи больше не соответствуют изображениям.** Нода фильтрует только IMAGE. Вернитесь к исходному набору и примените удаление индексов к обеим веткам согласованно.

**Ошибка `Expected 4D image tensor`.** Подан отдельный `[H,W,C]` вместо `[1,H,W,C]` или batch `[B,H,W,C]`.

## Производительность и внутреннее поведение

Сначала для каждого элемента создаётся Pillow-изображение и 64-битная строка. Этот этап линеен по числу файлов и требует переноса тензора на CPU внутри `tensor_to_pil`.

Затем каждый новый хеш сравнивается с ранее сохранёнными. В худшем случае число сравнений квадратично, примерно `N × (N − 1) / 2`, когда почти все изображения уникальны.

Изображения не копируются ради результата: выход выбирает элементы из нормализованного списка. Однако весь входной набор, хеши и список сохранённых индексов существуют одновременно. Для очень большого набора деление на части меняет качество дедупликации, потому что элементы из разных частей не сравнятся.
