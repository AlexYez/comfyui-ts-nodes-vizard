# DiffusersLoader (DEPRECATED): legacy-каталог Diffusers

## Назначение

`DiffusersLoader` загружает старую каталоговую раскладку модели Diffusers и возвращает `MODEL`, `CLIP` и `VAE`. В ComfyUI 0.32.0 нода помечена `DEPRECATED`. Она не является общим импортёром любого репозитория Hugging Face.

Поддержка ограничена структурой и именами файлов, зашитыми в `comfy/diffusers_load.py`. Для нового графа предпочтительнее официальный single-file checkpoint либо раздельные `UNETLoader`, `CLIPLoader`/`DualCLIPLoader` и `VAELoader`, если модель распространяется компонентами.

## Место в графе

Выходы используются как у checkpoint loader: `MODEL` подключают к sampling, `CLIP` — к encode, `VAE` — к работе с latent. Нода сама не создаёт prompt, latent или sampler.

В отличие от раздельных загрузчиков, пользователь выбирает один каталог, а код внутри ищет все компоненты. Это удобно только когда каталог точно соответствует ожидаемой legacy-раскладке.

## Входы

`model_path` — относительный путь внутри зарегистрированных каталогов `models/diffusers`. Список строится рекурсивным обходом; кандидат появляется, если в его корне есть `model_index.json`. Обход следует по symlink.

Наличие marker-файла — только условие обнаружения. Текущий loader не разбирает `model_index.json`, чтобы узнать реальные классы и пути компонентов. Поэтому появление каталога в combo ещё не доказывает, что он загрузится.

## Выходы

`MODEL` создаётся из файла diffusion-модели в подкаталоге `unet`. `CLIP` собирается из `text_encoder` и, если найден, `text_encoder_2`. `VAE` читается из `vae`.

Выходы объявлены обязательной тройкой. Параметры `output_clip` и `output_vae` существуют в Python-методе, но не представлены пользователю как входы ноды, поэтому обычное выполнение запрашивает оба компонента.

## Как работает

Перед загрузкой выбранный путь повторно сверяется со свежим списком `_model_paths`, затем ищется первый зарегистрированный корень, где присутствует `model_index.json`. Это защищает от произвольной строки, не обнаруженной scanner.

Внутренний loader ищет в `unet` и `vae` один из четырёх вариантов `diffusion_pytorch_model` с расширением safetensors или bin и необязательным суффиксом fp16. Для text encoder список имён другой: `model.*` либо `pytorch_model.*`. Второй encoder необязателен, первый — фактически нужен. Diffusion-модель проходит текущий детектор ComfyUI, а CLIP загружается без явного `CLIPType`, то есть с default Stable Diffusion mode.

## Параметры и настройка

Проверьте на диске не только `model_index.json`, но и exact подкаталоги `unet`, `vae`, `text_encoder`; для двойного encoder — `text_encoder_2`. Имена shard-файлов и многие современные Diffusers-раскладки этот узкий loader не учитывает.

Если модель нуждается в особом `CLIPType`, custom tokenizer, нескольких нестандартных text encoder или отдельном latent format, раздельная загрузка по model-specific official workflow обычно точнее. Не переименовывайте файлы вслепую: ожидаемое имя не гарантирует совместимое содержимое.

## Проверенный пример

Рецепт «Проверка legacy-каталога Diffusers» содержит `DiffusersLoader` с placeholder пути. Перед вставкой Wizard должен потребовать реально найденный каталог и проверить marker плюс необходимые component files. Пример предназначен для диагностики старой установки, а не для скачивания модели.

В 512 JSON official workflow templates 0.1.42 не найдено ни одного `DiffusersLoader`. Поэтому нельзя честно назвать конкретную современную модель проверенным official case. Реальный каталог в тестовом окружении отсутствует; загрузка не выполнялась.

## Частые ошибки

**Каталог виден, но загрузка падает.** `model_index.json` есть, а один из жёстко ожидаемых файлов `unet`, `vae` или `text_encoder` отсутствует.

**Современный Diffusers repository не поддержан.** Loader не читает component mapping из index и не собирает shards произвольного формата.

**CLIP не соответствует модели.** Внутренний вызов не передаёт специальный `CLIPType`; используйте раздельный loader с точным типом из official workflow.

**Один каталог с одинаковым relative path есть в нескольких roots.** После проверки выбирается первый зарегистрированный root с marker-файлом; избегайте неоднозначных копий.

**Ожидают автоматическую загрузку из интернета.** Нода работает только с уже размещёнными локальными файлами.

## Ограничения и производительность

При запуске список моделей строится рекурсивным обходом каталогов. Большое дерево и symlink могут замедлить формирование combo. Затем загружаются три тяжёлых компонента; расход памяти зависит от их dtype и политики устройств.

Нода deprecated и не имеет формальной записи Node Replacement API в baseline. Альтернатива выбирается по формату исходной модели: single-file checkpoint — `CheckpointLoaderSimple`, раздельный комплект — специализированные component loaders. Универсальной автоматической конверсии нет.
