# Несколько опорных латентов для редактирования

Кодирует изображения VAE и добавляет `reference_latents` к положительным и при наличии отрицательным условиям модели редактирования. Одновременно создаёт пустой латент для генерации.

## Как пользоваться

Подключите `positive`, совместимый `vae`, изображения и при необходимости `negative`. Входы `image1`, `image2` и далее обрабатываются в числовом порядке. `keep resolution` оставляет входные размеры; `resize` подгоняет площадь каждого изображения к `megapixels × 1024 × 1024`, сохраняя пропорции, через Lanczos без обрезки.

Пустой латент равен первому закодированному референсу, умноженному на ноль, и сохраняет его форму. Если `negative` не подключён, второй выход возвращает положительные условия, а не отдельное кодирование пустого текста.

## Пример

Для совместимой модели редактирования закодируйте инструкцию, передайте два изображения, выберите resize 1 MP и подайте три выхода в сэмплер. Совместимость с несколькими референсами должна быть предусмотрена самой моделью.

## Ограничения

Без VAE изображения полностью игнорируются. Если референсов нет, создаётся квадратный EmptyLatentImage: обычно 1024×1024, а в resize — со стороной по заданной площади. Такой запасной латент не подбирает число каналов под любую модель. Большое число референсов увеличивает время кодирования и расход памяти.

## Входы и настройки

Снимок ComfyUI 0.43.0. Условные поля показаны вместе с режимом, в котором они доступны; список установленных моделей зависит от вашей системы.

| Вход | Тип | Обязательный | Значения из схемы |
| --- | --- | --- | --- |
| `positive` | `CONDITIONING` | да | соединение / значение без фиксированного default |
| `resolution` | `COMFY_DYNAMICCOMBO_V3` | да | режимы: keep resolution, resize |
| `resolution=resize → megapixels` | `FLOAT` | да | по умолчанию: 1.0; минимум: 0.01; максимум: 16.0; шаг: 0.01 |
| `negative` | `CONDITIONING` | нет | соединение / значение без фиксированного default |
| `vae` | `VAE` | нет | соединение / значение без фиксированного default |
| `images` | `COMFY_AUTOGROW_V3` | нет | префикс: image |
| `images → image` | `IMAGE` | нет | соединение / значение без фиксированного default |

## Выходы

| Выход | Тип | Список |
| --- | --- | --- |
| `positive` | `CONDITIONING` | нет |
| `negative` | `CONDITIONING` | нет |
| `empty_latent` | `LATENT` | нет |

## Источники и проверка

[Реализация ComfyUI 0.43.0](https://github.com/Comfy-Org/ComfyUI/blob/426f5eea52a7ece1dd599fff4cb6cd1f352ddd24/comfy_extras/nodes_edit_model.py#L34-L90). Входы и выходы сверены с чистым серверным снимком. Пример поясняет подключение, но не подтверждает выполненную генерацию с весами. Человеческое утверждение ещё нужно.

## Официальные примеры подключения

В закреплённом пакете [workflow-templates-json 0.1.123](https://pypi.org/project/comfyui-workflow-templates-json/0.1.123/) найдено 2 вхождений. Примеры сохранённых связей:

- `image_flux3_klein_distilled_image_edit.json`, подграф «main»: входы от `CLIPTextEncode`, `ConditioningZeroOut`, `LoadImage`, `VAELoader`; выходы к `KSampler`.
- `image_flux3_klein_image_edit.json`, подграф «main»: входы от `CLIPTextEncode`, `LoadImage`, `VAELoader`; выходы к `KSampler`.

Это автоматическая сверка сохранённых соединений, не запуск и не ручная проверка всех сценариев. Внешние входы и переключатели подграфа могут менять путь выполнения.
