# CLIPTextEncodeFlux: отдельно закодировать промпты CLIP-L и T5XXL

## Что делает нода

`CLIPTextEncodeFlux` принимает два текста для двух частей составного текстового энкодера. Поле `clip_l` токенизируется первым. Затем в полученном словаре значение `t5xxl` заменяется токенами из отдельной токенизации поля `t5xxl`.

Объединённый словарь передаётся в `clip.encode_from_tokens_scheduled`. В метаданные каждого полученного элемента `CONDITIONING` сразу записывается число `guidance`, поэтому отдельная `FluxGuidance` в этой ветви обычно не нужна.

Нода не склеивает строки и не отправляет один и тот же текст в оба энкодера автоматически.

## Когда использовать и когда не использовать

Используйте ноду с составным CLIP, в котором есть совместимые ветви CLIP-L и T5XXL, когда им нужны разные формулировки. Короткий `clip_l` может задавать основные объекты и стиль, а развёрнутый `t5xxl` — композицию и детали.

Если оба энкодера должны получить один промпт, проще применить обычный `CLIPTextEncode` с подходящим загрузчиком. Если `CONDITIONING` уже создан, значение `guidance` можно изменить через `FluxGuidance`, не повторяя токенизацию.

Нода не проверяет архитектуру входного `CLIP`. Если во второй токенизации нет ключа `t5xxl`, выполнение завершится ошибкой.

## Короткий рецепт подключения

1. Загрузите совместимый составной текстовый энкодер.
2. Подключите его выход `CLIP` к `CLIPTextEncodeFlux`.
3. В `clip_l` запишите краткое описание объектов и стиля.
4. В `t5xxl` уточните сцену естественной фразой.
5. Для начала оставьте `guidance = 3.5` и передайте `CONDITIONING` на положительный вход сэмплера.
6. Отрицательную ветвь собирайте способом, проверенным для выбранной модели. Например, в официальном графе Flux Schnell используется `ConditioningZeroOut`.

Рецепт Wizard повторяет структуру единственного официального примера этой ноды, но заменяет длинные демонстрационные промпты короткими нейтральными заготовками.

## Входы, выходы и параметры

`clip` — обязательный вход `CLIP`. `clip_l` и `t5xxl` — многострочные поля `STRING` с поддержкой динамических промптов. Они независимы и могут иметь разную длину.

`guidance` — `FLOAT` от `0` до `100`; значение по умолчанию — `3.5`, шаг — `0.1`. При кодировании число сохраняется в метаданных `CONDITIONING`.

Выход — один `CONDITIONING`. Форма тензора и разбиение на блоки зависят от подключённого CLIP и содержимого промптов. Число элементов результата дополнительно зависит от расписания хуков, если оно включено.

## Типовые связки

Полная перепись официальных шаблонов версии 0.1.42 нашла один экземпляр ноды — в корневом графе `flux_schnell_full_text_to_image`. Нода работает в режиме `Always`, получает `CLIP` от `DualCLIPLoader` и использует `guidance = 3.5`.

Выход разветвляется: одна связь идёт на положительный вход `KSampler`, другая — в `ConditioningZeroOut` для отрицательной ветви. Это зафиксированный пример, а не обязательная схема для всех моделей семейства Flux.

Вместо этой ноды можно собрать другую схему: обычный `CLIPTextEncode` и отдельную `FluxGuidance`.

## Практический пример

В официальном графе нода № 41 получает `CLIP` от `DualCLIPLoader` № 40. Первое текстовое поле содержит короткий визуальный промпт, второе — более полное предложение для T5XXL, а третье значение равно `3.5`.

`CLIPTextEncodeFlux` № 41 подключена к положительному входу `KSampler` № 31 и к `ConditioningZeroOut` № 42. Выход № 42 приходит на отрицательный вход того же сэмплера. `ConditioningZeroOut` обнуляет основной тензор `CONDITIONING`, а также `pooled_output` и `conditioning_lyrics`, если эти поля есть. Остальные метаданные копируются: в частности, `guidance = 3.5` сохраняется и в отрицательной ветви.

Рецепт Wizard не утверждает, что эти промпты или значение `guidance` подходят любому семейству чекпойнтов.

## Частые ошибки и проверка

**Оба поля дают одинаковый результат.** Проверьте, что загрузчик действительно содержит две разные ветви и не направляет оба типа токенов в один энкодер.

**Ошибка по ключу `t5xxl`.** Подключённый CLIP не возвращает токены T5XXL. Используйте загрузчик, предназначенный для выбранной архитектуры Flux.

**Изменение `clip_l` неожиданно влияет не только на CLIP-L.** Код берёт весь словарь первой токенизации и заменяет в нём только значение `t5xxl`. Остальные ключи остаются от токенизации `clip_l`.

**Значение `guidance` задано дважды.** Если сразу после ноды стоит `FluxGuidance`, она перезапишет прежнее значение в метаданных. Оставьте один осознанно выбранный источник.

## Производительность и внутреннее поведение

Метод дважды вызывает `clip.tokenize`, а затем один раз запускает кодирование с расписанием. Основная вычислительная нагрузка приходится на текстовые энкодеры; замена одного значения в словаре почти ничего не стоит.

Токены T5XXL извлекаются выражением `clip.tokenize(t5xxl)["t5xxl"]`. Другие группы токенов из второй строки отбрасываются. Токены CLIP-L и служебные поля берутся из первой токенизации.

Фронтенд сначала разрешает конструкцию вида `{вариант A|вариант B}` в одну строку при подготовке запуска. Сам `encode_from_tokens_scheduled` может вернуть несколько элементов `CONDITIONING` по другой причине: если у CLIP есть `forced_hooks` и включено расписание CLIP, бэкенд кодирует отдельный временной диапазон для каждого набора ключевых кадров хуков. Значение `guidance` из `add_dict` добавляется к каждому такому элементу.
