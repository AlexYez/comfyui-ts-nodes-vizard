# PrimitiveInt

## Что делает нода

`PrimitiveInt` хранит одно целое число и возвращает его как `INT`. Никакой арифметики, округления или приведения единиц внутри нет: `execute` помещает входной `value` в `NodeOutput` без изменения.

Нода служит общим числовым регулятором. Один выход можно развести, например, на несколько размеров, seed или счётчиков, если все принимают `INT`.

## Когда она нужна и когда не нужна

Она полезна, когда значение нужно редактировать в одном месте и использовать в нескольких узлах. В официальных workflow так задают width, height, frame count, steps, seed, длину batch и другие целые параметры.

Не используйте её вместо формулы: для вычисления значения нужна math-нода. `PrimitiveInt` также не проверяет требования потребителя — кратность восьми, положительный диапазон или допустимое число кадров.

## Короткий рецепт подключения

В `basic_datatype_conversion` `PrimitiveInt` со значением `0` подключён сразу к `PreviewAny` и `ComfyMathExpression` с выражением `a`.

1. Задайте целое число.
2. Подключите выход к preview, чтобы увидеть исходное значение.
3. Подайте тот же выход на `values.a` math-ноды.
4. Сравните её `INT`, `FLOAT` и `BOOLEAN` результаты.

Рецепт сохраняет официальную часть топологии; он не добавляет скрытого преобразования в primitive-ноду.

## Вход, выход и параметры

В snapshot 0.32.0 диапазон `value` равен от `-9223372036854775807` до `9223372036854775807`: код использует `±sys.maxsize`, а не минимальное знаковое 64-битное значение.

Schema задаёт `control_after_generate: fixed`. Поэтому frontend не должен автоматически randomize/increment этот виджет после queue. В workflow значение обычно сериализуется вместе со строкой режима `fixed`; backend-выход содержит только сам `INT`.

## Место в графе

Ставьте ноду рядом с группой потребителей, которыми она управляет. Подпишите title по смыслу — `Width`, `Steps`, `Seed`, — потому что системное имя не сообщает единицу измерения.

Связывать один INT с разными по смыслу параметрами стоит только намеренно. Общий `1024` для width и height понятен; тот же `1024` для seed и steps сделает граф труднее читать.

## Как работает внутри

Класс `Int` объявляет schema с NodeId `PrimitiveInt`, затем `execute(value: int)` возвращает `io.NodeOutput(value)`. Runtime не делает clamp и не копирует объект с metadata — здесь передаётся обычное число.

Ограничения виджета защищают штатный ввод. Программный клиент всё равно обязан соблюдать schema; прямой вызов Python-метода сам по себе не проверяет диапазон.

## Практический пример

Задайте `0`, подключите к `PreviewAny` и к math expression `a`. Preview покажет `0`, `INT` math-ноды останется нулём, а её `BOOLEAN`-ветвь даст false согласно правилам math-ноды.

Для seed можно развести один `PrimitiveInt` на encoder и sampler, как сделано в трёх ACE Step 1.5 templates. Равный seed не гарантирует одинаковый результат у разных алгоритмов: он лишь передаёт одно целое значение.

## Частые ошибки и проверка

- Ожидают автоматическую кратность восьми. Primitive не знает о размерах изображения.
- Путают `fixed` с постоянным seed всей системы. Это режим виджета, а не запрет другим нодам менять состояние.
- Подключают отрицательное число к входу, который принимает только положительное. Сверьте runtime-карточку потребителя.
- Используют INT там, где требуется FLOAT: не все входы автоматически приводят тип.
- Разводят одно число на несвязанные параметры и затем забывают об общей зависимости.

## Ограничения и производительность

Передача целого практически ничего не стоит. Время и память определяет потребитель: число `4096` может быть дешёвым seed, но очень дорогим размером изображения или batch.

Широкий schema-диапазон не означает, что любое значение безопасно для графа. Проверяйте ограничения каждой downstream-ноды до queue.

## Совместимость, изменения и источники

Проверено на ComfyUI `0.32.0`, frontend `1.48.7`, docs `0.5.9` и templates `0.1.42`. Полный census: 230 экземпляров — 27 root и 203 subgraph; mode 0 у 226, bypass mode 4 у четырёх. Самый частый сериализованный вариант в этом наборе — `4` с режимом `fixed`.

Редактор пока не проверил материал вручную. Boundary/pass-through выполнен отдельно; ресурсоёмкие workflow, использующие эти числа, не запускались.
