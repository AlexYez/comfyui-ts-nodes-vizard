# PolyexponentialScheduler: искривить сетку log sigma

`PolyexponentialScheduler` строит явные `SIGMAS` между двумя границами. Сначала он создаёт убывающий параметр от 1 до 0, возводит его в степень `rho`, а затем интерполирует логарифм sigma. Так можно сместить промежуточные уровни без изменения крайних точек.

## Результат содержит steps уровней и конечный ноль

При положительных границах функция возвращает `steps` ненулевых значений от `sigma_max` до `sigma_min`, затем добавляет 0. Значение `steps` по умолчанию равно 20, runtime разрешает 1–10000.

Если `steps = 1`, единственная ненулевая точка равна `sigma_max`; `sigma_min` не появляется. Для представления обеих границ нужны хотя бы два шага.

## Формула работает в пространстве log sigma

Пусть `r` убывает от 1 до 0. Исходник считает:

`sigma(r) = exp(r^rho · (log(sigma_max) - log(sigma_min)) + log(sigma_min))`.

При `r = 1` получается верхняя граница, при `r = 0` — нижняя. Отдельный `append_zero` завершает последовательность после неё.

## rho = 1 воспроизводит exponential-сетку

При единичной степени `r^rho = r`, поэтому математически формула совпадает с равномерной интерполяцией `log(sigma)`. Exact-source probe подтвердил численное совпадение с `ExponentialScheduler` в пределах погрешности `float32`.

Побитово массивы не равны: функции выполняют операции в другом порядке. Для практического сравнения используйте допуск, а не точное равенство tensor.

## rho больше 1 быстрее уводит промежуточные точки вниз

Для `0 < r < 1` степень больше единицы уменьшает `r^rho`. Логарифм sigma раньше приближается к `log(sigma_min)`, поэтому после первой точки промежуточные уровни ниже, чем у exponential-сетки.

При четырёх шагах, стандартных границах и `rho = 2` probe дал примерно `[14,614640; 0,462221; 0,058195; 0,0291675; 0]`. Для сравнения, exponential-вариант содержит около 1,840031 и 0,231666 в середине.

## rho между 0 и 1 дольше удерживает высокие sigma

Дробная положительная степень увеличивает `r^rho` на промежуточных точках. Значения остаются ближе к `sigma_max`, а спад к нижней границе сдвигается к концу расписания.

Это описание следует непосредственно из формулы. Оно не означает автоматически более высокое качество: sampler, модель и задача определяют, полезна ли такая плотность шагов.

## rho = 0 вырождает расписание

Runtime разрешает 0–100, но при нуле `torch.linspace(...) ** 0` даёт единицы и все `steps` ненулевых точек становятся равны `sigma_max`; затем добавляется 0. Переходов между границами больше нет.

Используйте строго положительное `rho`. Значение по умолчанию 1 — понятная отправная точка, потому что оно соответствует exponential-кривой.

## Обе границы должны быть положительными

Поля `sigma_max` и `sigma_min` имеют UI-диапазон 0–5000, шаг 0,01, `round = false` и значения по умолчанию 14,614642 и 0,0291675. Но формула берёт логарифм обеих границ, поэтому ноль вызывает `ValueError`.

Нода также не проверяет порядок. При `sigma_max < sigma_min` ненулевая часть возрастает, а потом падает к нулю. Обычная рабочая область: `sigma_max > sigma_min > 0` и `rho > 0`.

## MODEL не участвует в расчёте

Входа `MODEL` нет. Это отличает ноду от `BasicScheduler`, который читает `model_sampling` и получает модельные границы. Здесь диапазон полностью задаёт автор workflow.

Guider может содержать модель с другой шкалой sigma, и runtime не сообщит о расхождении заранее. При переносе параметров между архитектурами границы нужно проверять заново.

## В pinned workflow нет примера этой ноды

Полный census wheel 0.1.42 просмотрел 512 JSON, включая 496 root workflow и 272 subgraph. Exact type `PolyexponentialScheduler` отсутствует во всех 768 графовых областях.

Поэтому статья не приписывает ноде настройки из чужого template. Все числовые примеры получены из defaults runtime и точной функции pinned source.

## Fragment отделён от полного sampling

Recipe соединяет выход `SIGMAS` со входом `SamplerCustomAdvanced.sigmas` и оставляет остальные четыре входа sampler внешними. Это проверяемый fragment, но не готовый workflow и не рекомендация границ для любой модели.

Probe без моделей проверил `rho = 1`, `rho = 2`, вырожденный ноль, ошибку при нулевой границе и конечный ноль. Полный sampling не выполнялся. Редактор пока не проверил материал вручную.
