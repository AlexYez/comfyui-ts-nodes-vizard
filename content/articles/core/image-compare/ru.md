# Compare Images

## Что делает нода

`ImageCompare` показывает два изображения в одном viewport. Изображение B лежит снизу, A — сверху и обрезается вертикальной границей. Положение границы следует за указателем внутри области сравнения.

Это визуальный output node. Он не вычисляет разность, PSNR, SSIM или другой показатель и не имеет выходных портов.

## Когда она нужна и когда не нужна

Нода удобна для проверки upscaling, удаления фона, inpainting, цветокоррекции и edit-моделей. Совмещённая граница легче показывает локальные изменения, чем два независимых preview.

Для контактного листа нескольких разных изображений используйте `ImageGrid`. Для численного контроля качества нужна отдельная метрика. `ImageCompare` не выравнивает содержимое и не регистрирует кадры.

## Короткий рецепт подключения

Исходный `IMAGE` подключите к `image_a`, результат обработки — к `image_b`. Выполните граф и проведите указателем по viewport слева направо.

В официальном `api_magnific_image_upscale_creative` вход `LoadImage` подключён к A, а выход `MagnificImageUpscalerCreativeNode` — к B. Та же схема «исходник → A, результат → B» повторяется в remove-background, edit и upscale шаблонах.

## Входы и интерфейс

`image_a` и `image_b` необязательны. Если подключён только один, widget показывает его без границы. `compare_view` — встроенный socketless-widget типа `IMAGECOMPARE`; линию к нему не подключают.

После выполнения backend сохраняет каждый batch как временные preview с префиксами `comfy.compare.a` и `comfy.compare.b`. Frontend превращает записи в `/view` URL и добавляет cache-busting параметр.

Оба изображения показываются через `object-contain`. При разных размерах они вписываются в один viewport, поэтому визуальная граница не означает попиксельное соответствие координат исходных tensors.

## Как работает граница сравнения

Frontend держит позицию на 50% при создании widget. Пока указатель находится внутри viewport, позиция вычисляется как `x / width` и ограничивается диапазоном 0–100%.

Для A применяется CSS `clip-path`: слева виден A, справа — B. Перетаскивание с нажатой кнопкой не требуется; достаточно движения указателя. Позиция является локальным состоянием интерфейса и не записывается в workflow.

Backend не смешивает изображения и не меняет пиксели. Он только подготавливает preview-записи для frontend.

## Работа с batch

Если хотя бы один вход содержит больше одного кадра, над viewport появляются независимые навигаторы `A:` и `B:`. Индексы двух batch переключаются отдельно.

Когда новые preview приходят после выполнения, оба индекса сбрасываются на ноль. Batch могут иметь разную длину: пользователь вручную выбирает пару кадров, а автоматического сопоставления по последнему индексу нет.

Backend передаёт весь batch в механизм `PreviewImage`. Это создаёт временную preview-запись для каждого кадра и расходует больше времени и места, чем сравнение одиночной пары.

## Проверенные практические случаи

В пакете workflow 0.1.42 найдено 34 ноды `ImageCompare` в 34 корневых графах и ни одной внутри subgraph. Все работают в обычном режиме исполнения.

Примеры охватывают Magnific upscale, Bria background removal, Nano Banana edit, Topaz enhance, SeedVR2, Recraft, Anima и другие ветки. В `api_nano_banana_2_lite_image_edit` `LoadImage` № 8 идёт в A ноды № 9, а `SaveImageAdvanced` № 4 возвращает обработанный `IMAGE` в B.

Синтетическая backend-проверка передала batch A из двух кадров и batch B из одного. Получены две записи `a_images`, одна `b_images` и точные префиксы; при двух пустых входах оба списка остались пустыми.

## Частые ошибки и диагностика

**Нода ничего не показывает.** Проверьте, что хотя бы один IMAGE подключён и граф выполнен. До результата widget не получает preview URL.

**Граница сравнивает разные участки.** Входы имеют разные размеры или кадрирование. Сначала приведите их к одинаковой геометрии.

**Нужна картинка сравнения на выходе.** У ноды нет портов. Для сохранения split-view соберите его отдельными image-операциями.

**В классическом canvas написано Nodes 2.0 only.** Frontend 1.48.7 реализует полноценный widget только как Vue-компонент. LiteGraph-класс рисует предупреждение и не реагирует на клик.

## Ограничения и производительность

Каждое выполнение сохраняет временные preview для обоих входов. Большие batch и высокое разрешение увеличивают время кодирования и объём временных файлов. Нода не уменьшает данные заранее.

Сравнение зависит от визуального восприятия, масштаба viewport и цветопередачи дисплея. Оно не заменяет просмотр 100% crop и измерение ошибки. Позиция границы и выбранные индексы batch не являются вычислительными параметрами.
