# SaveSVGNode: сохранить SVG в выходной каталог

## Что делает нода

`SaveSVGNode` принимает объект `SVG` и записывает каждый его элемент в отдельный файл `.svg`. В ComfyUI этот объект хранит упорядоченный список потоков `BytesIO`, поэтому один вход может дать несколько файлов. Имена получают пятизначный счётчик: например, `svg/diagram_00001_.svg`.

Нода не строит векторную графику и не преобразует растровое изображение в SVG. Перед ней нужен источник типа `SVG`: в официальных шаблонах это API-ноды Quiver и Recraft. Содержимое сохраняется как есть, за исключением необязательной вставки метаданных.

После записи нода возвращает тот же объект `SVG` через соединяемый выход и сведения о файлах для интерфейса. Поэтому таблица встроенной документации 0.5.9, где указан только словарь UI, неполна: `/object_info` объявляет настоящий выход `svg: SVG`.

## Место в графе

Ставьте `SaveSVGNode` после ноды, которая уже сформировала корректный SVG. Она помечена как `output_node`, поэтому ветка с ней включается в выполнение даже без следующего потребителя. Соединяемый выход нужен, если тот же SVG должен идти в другую ветку.

В официальном пакете шаблонов 0.1.42 найдено семь точных экземпляров, все в корневых графах: у пяти стоит `mode=0`, у двух — `mode=4`. Активные примеры соединяют `QuiverImageToSVGNode`, `QuiverTextToSVGNode`, `RecraftTextToVectorNode` или `RecraftV4TextToVectorNode` со входом `svg`. Подграфов с этой нодой нет.

У семи официальных нод сохранения нет исходящих соединений, хотя схема допускает их. Сквозной выход подтверждён исходником и `/object_info`, но официальный пакет не показывает его практическое продолжение.

## Входы

- `svg: SVG` — один объект со списком UTF-8 SVG-потоков. Нода перебирает `svg.data` по порядку.
- `filename_prefix: STRING` — относительный префикс внутри выходного каталога. Значение по умолчанию: `svg/ComfyUI`.
- `prompt: PROMPT` — скрытое описание запроса API, которое ComfyUI подставляет при выполнении.
- `extra_pnginfo: EXTRA_PNGINFO` — скрытый словарь дополнительных сведений, обычно с описанием рабочего процесса.

Каждый поток читается целиком и декодируется строгим UTF-8. Битый UTF-8 вызовет исключение до записи соответствующего элемента. XML-валидность, наличие корневого `<svg>` и безопасность содержимого отдельно не проверяются.

Скрытые данные используются, если они не равны `None`. В отличие от общей ноды сохранения контрольной точки, `SaveSVGNode` не проверяет флаг запуска `--disable-metadata`: этот флаг сам по себе не отключает её SVG-вставку.

## Выходы

Соединяемый выход `svg: SVG` ссылается на тот же объект, который пришёл на вход. Нода не возвращает заново разобранный файл и не гарантирует, что записанный вариант с метаданными совпадает с объектом в следующей ветке: метаданные добавляются только в текст на диске.

Параллельно интерфейс получает массив `images` с именем, подпапкой и типом `output` для каждого файла. Это служебный результат интерфейса, а не второй порт.

Есть тонкость: перед чтением нода делает `seek(0)`, но после `read()` не возвращает курсор `BytesIO` к началу. В возвращённом объекте курсор каждого обработанного потока остаётся в конце. Следующий потребитель должен сам выполнить `seek(0)`, как это делает нода сохранения; иначе он может прочитать пустую строку.

## Как работает внутри

Сначала `get_save_image_path` вычисляет подпапку, основу имени и следующий счётчик. Затем для каждого `BytesIO` нода заменяет `%batch_num%` в основе на индекс элемента, формирует имя `<basename>_<counter:05>_.svg`, читает UTF-8 и увеличивает счётчик после записи.

Если есть `prompt` или `extra_pnginfo`, они сериализуются через `json.dumps(..., indent=2)`. Дополнительный словарь добавляется после `prompt`, поэтому его собственный ключ `prompt` способен заменить ранее записанное значение. Полученный JSON помещается в блок CDATA `<metadata>`.

Вставка сделана регулярным выражением `(<svg[^>]*>)` без ограничения числа замен. Поэтому метаданные появятся после каждого открывающего тега `<svg>`, включая вложенные SVG. Если тега нет, файл всё равно сохранится, но метаданные не добавятся. Строка `]]>` внутри сериализованных данных может преждевременно закрыть CDATA; XML-парсером нода результат не проверяет.

## Настройки имени файла

`%batch_num%` обрабатывает сама серверная нода. Например, префикс `svg/wizard-%batch_num%` для двух элементов даёт основы имён `wizard-0` и `wizard-1`; счётчик при этом также растёт, поэтому имена будут различаться по двум признакам.

Интерфейс 1.48.7 включает `SaveSVGNode` в расширение подстановки имён файлов. При сериализации оно раскрывает `%date:...%` и ссылки вида `%Название ноды.widget%`, а недопустимые для имени файла символы в значении виджета заменяет подчёркиваниями. Если найдено несколько нод с одинаковым именем для подстановки, берётся первая. Серверная часть отдельно понимает простые `%year%`, `%month%`, `%day%`, `%hour%`, `%minute%`, `%second%`, `%width%` и `%height%`; для SVG ширина и высота не передаются и равны нулю.

Подпапка остаётся внутри выходного каталога. Проверка через `realpath` отклоняет `../` и существующую символическую ссылку, ведущую наружу, на момент проверки. Счётчик не резервируется блокировкой, а проверка пути и последующая запись не атомарны: параллельные задания с одинаковым префиксом могут выбрать одно имя.

## Пример подключения

Фрагмент `recipe.save-svg-output` принимает внешний `SVG` и подключает его к `SaveSVGNode` с префиксом `svg/wizard-%batch_num%`. Он годится после любого совместимого производителя, но не включает API-вызов и не содержит чужих ключей или платных зависимостей.

Официальный активный пример `api_quiver_image_to_svg` использует более простой префикс `svg/Quiver`: `QuiverImageToSVGNode #1 → SaveSVGNode #3`. В `api_recraft_v4_1_text_to_vector` соединение идёт от `RecraftV4TextToVectorNode #13` к ноде сохранения `#14`, префикс — `svg/Recraft_v4.1_t2v`.

Полный обход нашёл семь файлов и пять разных идентификаторов рабочих процессов; у двух Recraft-примеров с `SaveSVGNode` стоит `mode=4`, поэтому они не доказывают выполненную запись. Наш фрагмент опирается на точную схему и активные официальные топологии, но сам не запускался в ComfyUI.

## Частые ошибки

**Подают IMAGE вместо SVG.** Типы различаются. Сначала нужна нода векторизации или генерации, которая действительно возвращает `SVG`.

**Считают файл безопасным, раз его сохранил ComfyUI.** Нода не удаляет `<script>`, внешние URL, стили, XML-конструкции и события. Не открывайте недоверенный SVG как документ и не публикуйте его без отдельной проверки.

**Ждут один файл от пакета SVG.** Число файлов равно длине `svg.data`, а не числу нод в графе.

**Ждут метаданные только в корне.** Регулярное выражение обрабатывает все открывающие `<svg>`. Для вложенной разметки могут появиться несколько одинаковых блоков.

**Включают `--disable-metadata` и считают SVG очищенным.** Код `SaveSVGNode` этот флаг не читает. Если метаданные нельзя сохранять, удалите чувствительные сведения до ноды или проверьте готовый файл.

**Продолжают ветку потребителем, который читает текущую позицию BytesIO.** После ноды сохранения курсор стоит в конце; потребитель должен перемотать поток.

## Ограничения и безопасность

Нода читает каждый SVG целиком в строку и затем создаёт ещё одну UTF-8 копию для записи. Для больших пакетов расход памяти примерно растёт с суммарным размером текущего текста и метаданных. Ограничения размера, контрольной суммы, атомарной временной записи и предварительной проверки свободного места нет.

ComfyUI 0.32.0 относит `image/svg+xml` к опасным активным MIME-типам. Маршрут `/view` для обычной навигации отдаёт такой файл как `application/octet-stream` с `attachment`, `nosniff` и `no-store`; исключение сделано только для запроса с заголовком `Sec-Fetch-Dest: image`. Это защита маршрута просмотра, а не очистка файла. При прямом открытии с диска, отправке на другой сайт или обработке сторонней программой действуют правила той среды.

Проверка пути основана на `realpath`, но запись выполняется позже обычным `open(..., 'wb')`. Между проверкой и записью остаётся файловая гонка. В среде, где недоверенный процесс может менять каталоги или символические ссылки одновременно с ComfyUI, одной этой проверки недостаточно.
