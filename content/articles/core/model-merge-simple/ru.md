# ModelMergeSimple: смешать diffusion-веса двух моделей

## Что делает нода

`ModelMergeSimple` создаёт ленивый патч `MODEL`: первая модель остаётся основой, а к её совпадающим diffusion-весам добавляются веса второй. Для ключа одинаковой формы итоговая арифметика в ComfyUI 0.32.0 выглядит так:

`result = ratio × model1 + (1 − ratio) × model2`.

Поэтому `ratio = 1` оставляет `model1`, `ratio = 0` берёт `model2`, а `0,5` даёт равную смесь. Нода не смешивает CLIP и VAE и сама не записывает checkpoint на диск.

## Когда использовать и когда не использовать

Нода подходит для контролируемого A/B-эксперимента с двумя checkpoint одной архитектуры: одинаковым набором UNet-ключей, совместимыми размерами тензоров и одним типом предсказания. Начинать разумно с небольшого вклада второй модели, например 10–25%, и проверять один и тот же prompt, seed и sampler.

Не соединяйте наугад модели разных семейств, размеров или назначений. Совпавшее имя ключа ещё не гарантирует совместимую форму, а отсутствующий в `model1` ключ из `model2` просто не попадёт в результат. Для CLIP нужен отдельный merge, для VAE — отдельный выбор или проверенная процедура.

## Короткий рецепт подключения

1. Загрузите два совместимых `MODEL`.
2. Подключите основной checkpoint к `model1`, второй — к `model2`.
3. Поставьте `ratio = 0,75`, если нужен результат из 75% `model1` и 25% `model2`.
4. Передайте выходной `MODEL` в тот же sampling-тракт, которым проверяли исходные модели.
5. Сначала сравните изображение в памяти; сохраняйте новый checkpoint лишь после проверки.

Фрагмент `Смешать 75% model1 и 25% model2` содержит только эту операцию. Полного workflow для него нет, потому что в официальных templates 0.1.42 точный тип `ModelMergeSimple` не найден.

## Входы, выходы и параметры

- `model1` (`MODEL`) — основа. Нода вызывает `clone()`, поэтому исходный объект не меняется.
- `model2` (`MODEL`) — источник эффективных патчей с префиксом `diffusion_model.`.
- `ratio` (`FLOAT`, 0…1, шаг 0,01, по умолчанию 1) — доля `model1`, а не доля второй модели.
- `MODEL` — клон первой модели с добавленной patch-операцией.

Живые границы и порядок входов Wizard показывает из установленного `/object_info`. Combo со списком моделей здесь нет: checkpoint выбираются во внешних loader-нодах.

## Типовые связки

Обычная цепочка выглядит как `CheckpointLoader → ModelMergeSimple → sampler или model patch`. Если у checkpoint есть собственные CLIP и VAE, их нельзя считать автоматически «смешанными» вместе с `MODEL`: выберите подходящие компоненты отдельно и зафиксируйте это в эксперименте.

`ModelMergeBlocks` решает похожую задачу, но назначает разные коэффициенты группам ключей. `CLIPMergeSimple` применяет отдельную операцию к текстовым энкодерам. `ModelMergeAdd` и `ModelMergeSubtract` нужны для алгебры дельт, а не для обычного процентного blend.

## Практический пример

В синтетической проверке точных методов ноды и `comfy.lora.calculate_weight` использовались веса `model1 = 2`, `model2 = 10`, `ratio = 0,25`. Результат равен `0,25 × 2 + 0,75 × 10 = 8`. Значение 0,25 означает 25% первой модели и 75% второй.

Та же проверка показала две границы области действия: ключ `clip.weight` не изменился, потому что фильтр берёт только `diffusion_model.`, а ключ, существующий только в `model2`, не был добавлен, поскольку `add_patches` принимает лишь ключи state dict первой модели. Это проверка арифметики без реальных весов и не доказательство качества конкретной пары checkpoint.

## Частые ошибки и способы проверки

- Перепутана сторона коэффициента. При `ratio = 0,8` вклад `model2` равен 0,2.
- Смешаны разные архитектуры. Сначала сравните семейство, назначение, prediction type и формы весов.
- Warning о несовпадении формы проигнорирован. В текущем расчёте базовый вес успевает умножиться на `ratio`, а добавление несовместимого тензора пропускается. При `ratio = 0` такой ключ способен превратиться в нулевой вес.
- Ожидалось смешивание CLIP или VAE. Нода обрабатывает только ключи `diffusion_model.`.
- Результат сразу сохранён поверх ценного файла. Используйте новый prefix и сначала проверьте граф без записи.

При странном результате смотрите консоль на `WARNING SHAPE MISMATCH`, затем сравнивайте выход с обеими исходными моделями при неизменных seed и sampling-параметрах.

## Производительность и внутреннее поведение

Нода не суммирует все тензоры в момент построения графа. Она клонирует `ModelPatcher`, получает эффективные key patches второй модели и регистрирует новую patch-операцию. Реальные веса рассчитываются при загрузке/исполнении модели. Это экономит немедленную запись checkpoint, но две исходные модели и цепочка патчей всё равно требуют памяти и времени на подготовку.

Если `model2` уже содержит LoRA или merge-патчи, `get_key_patches` возвращает вложенное описание и при расчёте сначала материализуется его эффективный вес. Порядок операций поэтому важен: blend до LoRA и blend после LoRA могут дать разные объекты патчей и другой результат.

## Совместимость, изменения и статус

Статья проверена по ComfyUI 0.32.0, frontend 1.48.7, embedded docs 0.5.9 и workflow templates JSON 0.1.42. В полном наборе из 512 JSON, 496 root-графов и 272 subgraph точного `ModelMergeSimple` нет; пример основан на runtime-схеме и исходнике.

Нода не помечена как deprecated или experimental и не указана в Node Replacement API. Встроенные docs верно описывают крайние значения ratio, но не раскрывают фильтр `diffusion_model.`, пропуск отсутствующих ключей и опасное поведение несовпадающих форм.

Редактор пока не проверил материал вручную.

## Связанные ноды и источники

Для разных коэффициентов по группам смотрите `ModelMergeBlocks`. Для дельты — связку `ModelMergeSubtract → ModelMergeAdd`. Текстовый энкодер смешивается отдельно через `CLIPMergeSimple`.
