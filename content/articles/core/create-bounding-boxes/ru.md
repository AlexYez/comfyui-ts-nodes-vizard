# Create Bounding Boxes

## 1. Назначение

`CreateBoundingBoxes` — интерактивная нода для ручной разметки композиции. На её холсте можно нарисовать прямоугольники, выбрать для каждого тип `obj` или `text`, вписать описание, текст и до пяти цветов. После выполнения нода возвращает сразу три представления одной разметки: изображение для проверки, пиксельные рамки `BOUNDING_BOX` и массив элементов для структурированного промпта Ideogram.

Это не детектор объектов и не сегментатор. Нода ничего не распознаёт в изображении: положение и смысл каждой области задаёт пользователь либо готовый вход `bboxes`.

## 2. Место в графе

Чаще всего ноду ставят перед `BuildJsonPromptIdeogram`: выход `elements` соединяют с его входом `element`. Выход `bboxes` подходит и другим нодам, которые принимают `BOUNDING_BOX`, например для построения слоёв или обработки выбранных областей. `preview` нужен для визуальной проверки и не заменяет исходное изображение.

Если требуется один прямоугольник с числовыми полями `x`, `y`, `width` и `height`, проще взять `PrimitiveBoundingBox`. `CreateBoundingBoxes` оправдана, когда рамок несколько, важен их порядок или нужны подписи и палитры.

## 3. Входы

`width` и `height` задают координатную сетку: от 64 до 16 384 с шагом 16, по умолчанию 1024 × 1024. `editor_state` хранит нарисованные рамки. В интерфейсе это сам редактор, а не обычное поле.

Необязательный `background` показывает изображение под рамками. Серверная часть берёт только первый кадр пакета. `bboxes` принимает пиксельные рамки, массив элементов Ideogram либо JSON-строку с одним из этих форматов. Если пиксельные рамки пришли как несколько внешних кадров `BOUNDING_BOX`, нода использует только первый. Внутренний `last_incoming` запоминает, какое внешнее значение уже было применено; клиентская часть 1.48.7 скрывает этот виджет.

При подключённом `background` интерфейс скрывает `width` и `height`. Синхронизация с изображением происходит только тогда, когда браузер получил URL предпросмотра от предыдущей ноды: его натуральные размеры округляются до ближайшего числа, кратного 16. Если URL нет, скрытые поля сохраняют прежние значения. Клиентский код ограничивает результат снизу числом 16, но не приводит его к серверному диапазону 64–16 384. Поэтому для очень маленького или слишком большого фона размеры лучше проверить вручную до запуска. При вызове через API автоматической синхронизации нет.

## 4. Выходы

`preview` — один RGB-кадр `IMAGE` с затемнённым фоном, контурами, номерами и текстом областей. Длинная сторона не превышает 1024 пикселей, поэтому это контрольное изображение, а не полноразмерный результат.

`bboxes` содержит рамки в пикселях: `x`, `y`, `width`, `height`. При наличии рамок серверная часть оборачивает их в один кадр списка. `elements` использует схему Ideogram: `bbox` записывается как `[ymin, xmin, ymax, xmax]` в сетке 0–1000; у текстовой области добавляется `text`, у обеих разновидностей — `desc` и, если она непуста, `color_palette`.

Порядок выходных элементов совпадает с порядком областей. В подсказке интерфейса рекомендуют сначала описывать фон, затем передний план: код сам элементы не сортирует.

## 5. Как работает

Сначала `bboxes` приводится к списку рамок. JSON разбирается строго; элемент Ideogram переводится из сетки 0–1000 в пиксели. Если пришёл непустой новый набор, отличный от `last_incoming`, он инициализирует холст. Когда набор уже применён, побеждает `editor_state`, поэтому ручные правки не исчезают при каждом запуске.

Пустой внешний список не считается новым значением и не очищает существующую разметку. Очистку делает кнопка на холсте: она одновременно сбрасывает редактор и `last_incoming`.

Для `elements` координаты ограничиваются диапазоном 0–1000, отрицательная ширина или высота разворачивается. Пиксельный выход не получает такого общего ограничения: рамка, поданная программно за пределами холста, может остаться с отрицательной координатой. На выходе `preview` она будет обрезана границами изображения.

## 6. Параметры редактора

Сетка включена по умолчанию. Её базовый шаг — 32 пикселя, но на большой стороне используется более крупный шаг, чтобы не превысить 64 ячейки. Очень маленькая рамка, занимающая меньше 0,5% стороны, удаляется после отпускания указателя. Палитра одной области ограничена пятью цветами.

Фон для `preview` проходит через центральный процессор и Pillow: первый кадр переводится в 8-битное изображение, уменьшается фильтром Lanczos и затемняется до четверти яркости. Без фона создаётся тёмно-серый холст заданных пропорций. Сам `editor_state` сериализуется в рабочий процесс, поэтому разметка сохраняется вместе с графом.

## 7. Проверенный пример

В официальном графе `api_ideogram_p_image_t2i` нода работает на холсте 1024 × 1024 и содержит пять областей журнальной обложки: крупный заголовок, центральный объект, две боковые подписи и нижнюю строку. Связь идёт точно так:

`CreateBoundingBoxes.elements → BuildJsonPromptIdeogram.element`.

Рецепт Wizard сохраняет безопасную часть официального графа вместе с `PreviewAny`, чтобы увидеть словарь до обращения к платному API. Сам запрос к Ideogram и сохранение результата в рецепт не входят.

## 8. Ошибки и диагностика

Сообщение о неверном JSON означает, что `bboxes` нельзя разобрать. Для элемента Ideogram нужен `bbox` ровно из четырёх чисел в порядке `ymin, xmin, ymax, xmax`. У пиксельной рамки обязательны четыре ключа: `x`, `y`, `width`, `height`.

Если внешний набор не появляется на холсте, сравните его с `last_incoming`: уже применённое значение намеренно не перетирает ручные изменения. Чтобы повторно инициализировать редактор теми же данными, очистите внутреннее состояние кнопкой холста.

Несовпадение рамок и фонового изображения обычно связано с разными `width`/`height` и реальным размером `background`. При программном запуске проверяйте их отдельно. Сервер принимает непустые строки палитры и лишь переводит их в верхний регистр; корректность шестнадцатеричного цвета надёжнее обеспечить до выполнения.

## 9. Ограничения и производительность

Отрисовка выполняется на центральном процессоре и создаёт новый тензор `preview`. Большой исходный кадр сначала копируется с устройства, но длинная сторона результата ограничена 1024 пикселями. В пакетном `background` используются только данные кадра с индексом 0.

Интерактивность зависит от клиентской части 1.48.7: минимальный размер ноды, скрытые поля, сетка, выбор рамок и синхронизация фоновых размеров реализованы на стороне браузера. Серверную часть можно вызвать без браузера, но тогда `editor_state` и `last_incoming` придётся сформировать самостоятельно.

Синтетическая проверка Wizard выполнила точные функции преобразования словаря, JSON и нескольких кадров рамок, а также построила предварительный просмотр без модели. Условия загрузки фонового URL и ограничения синхронизации размеров сверены с закреплённым исходником интерфейса. События указателя в браузере и полный граф Ideogram не запускались.
