# Preview Mask: посмотреть маску без постоянного файла

## Что делает нода

`MaskPreview` показывает входную `MASK` прямо в интерфейсе ComfyUI. Для показа одноканальная маска разворачивается в три одинаковых цветовых канала, поэтому значение `0` выглядит чёрным, `1` — белым, а мягкие края — серыми.

Нода одновременно возвращает исходную `MASK` без изменений. Её можно поставить в середине ветки: увидеть результат и продолжить работу с тем же tensor через выход `mask`.

## Когда использовать

Подключайте `MaskPreview` после сегментации, порога, инверсии, расширения или feathering, когда нужно проверить форму и границы маски до дорогой операции inpainting или compositing.

Нода особенно полезна для сравнения нескольких вариантов. В официальном примере базовых масочных операций отдельные preview стоят после `ImageToMask`, `InvertMask`, `ThresholdMask`, `FeatherMask` и разных режимов `MaskComposite`.

Для постоянного изображения используйте `MaskToImage` вместе с `SaveImage`. `MaskPreview` предназначена для временного просмотра и не заменяет явное сохранение результата.

## Вход

`mask` принимает tensor типа `MASK`, обычно формы `[B, H, W]`. Каждый элемент batch будет подготовлен как отдельный серый preview.

Нода ничего не нормализует, не инвертирует и не применяет порог. Видимое изображение напрямую отражает значения входа. Если downstream-нода трактует белое как выбранную область, preview покажет её белой; если конкретная нода использует обратное соглашение, `MaskPreview` это соглашение не исправляет.

В runtime также объявлены скрытые поля `prompt` и `extra_pnginfo`. Пользовательских настроек и поля `filename_prefix` в schema ComfyUI 0.32.0 нет.

## Выход и UI-результат

Обычный выход `mask` — тот же tensor, который поступил на вход. Synthetic-проверка подтвердила точное `torch.equal`: просмотр не меняет форму, значения, dtype или batch.

Отдельно `NodeOutput` содержит UI-результат со списком временных изображений. На диске файл получает случайный префикс вида `ComfyUI_temp_…`, тип `temp` и затем показывается frontend.

`MaskPreview` помечена как output node. Поэтому ветка может завершаться на ней и участвовать в выполнении prompt, даже если выход `mask` никуда не подключён.

## Как создаётся preview

Helper `UI.PreviewMask` преобразует `[B, H, W]` в `[B, H, W, 1]` и расширяет последний размер до трёх одинаковых каналов. Это представление передаётся общему `PreviewImage`.

`PreviewImage` сохраняет PNG в temp-каталог ComfyUI с уровнем сжатия `1`. Это временный служебный файл, а не запись в пользовательский каталог `output`. После очистки temp такой preview может исчезнуть.

Embedded docs 0.5.9 утверждают, что файл сохраняется в output и имеет настраиваемый prefix. Для ComfyUI 0.32.0 оба утверждения неверны: точный путь задаёт `FolderType.temp`, а prefix не выставлен в пользовательской schema.

## Работа с пакетами и мягкими масками

Если вход содержит batch из нескольких масок, helper сохраняет отдельный preview для каждого элемента. Это удобно после `BatchMasksNode`, но на длинной видеопоследовательности создаёт много временных PNG.

Мягкие значения не округляются перед показом. Например, край со значением `0.5` выглядит средне-серым. Так можно проверить feathering и заметить ступеньки до композитинга.

Расширение до RGB нужно только UI-helper. Обычный выход остаётся `MASK`; для подключения к IMAGE-входу всё равно требуется `MaskToImage`.

## Проверенные примеры

В `basic_mask_operations_and_compositing` находятся 14 `MaskPreview`. Среди них — исходный red-канал после `ImageToMask`, его инверсия, порог `0.41`, feathering слева на `200` пикселей, несколько операций `MaskComposite` и итоговая мягкая маска перед `ImageCompositeMasked`.

Нода встречается ещё в шести официальных workflow: удаление фона BiRefNet, сегментация изображения и видео SAM3, оценка глубины MoGe, Anima inpainting и Qwen inpainting ControlNet. Во всех случаях она служит контрольной точкой, а не преобразователем данных.

Рецепт Wizard принимает внешнюю MASK и завершает ветку на `MaskPreview`. Runtime-выход сохранён, чтобы пользователь мог продолжить граф. В отдельном исполнении был создан реальный temp PNG, но полный fragment через UI ещё не запускался.

## Частые ошибки

**Preview ищут в `output`.** Он записывается в temp. Для постоянного файла соберите IMAGE и используйте `SaveImage`.

**После ноды ожидается IMAGE.** Обычный выход имеет тип MASK. Для IMAGE нужен `MaskToImage`.

**Белое и чёрное кажутся перепутанными.** `MaskPreview` показывает сами числа. Проверяйте соглашение той ноды, которая будет использовать маску дальше.

**После просмотра ветка стала выполняться.** Это ожидаемо: `MaskPreview` зарегистрирована как output node.

**Большой video batch создаёт много файлов.** Каждый элемент получает отдельный временный PNG.

## Ограничения и производительность

Для каждого кадра маски создаётся RGB-представление и выполняется PNG-кодирование. На единичной маске это дёшево, но сотни кадров добавляют время, дисковые операции и объём temp-каталога.

Нода не показывает значения за пределами обычного диапазона как числа и не строит histogram. Для точной диагностики tensor нужны специализированные inspect-ноды или отдельный анализ.

Удаляйте лишние preview из длинного рабочего графа после отладки. Они не меняют данные, но остаются output nodes и заставляют соответствующие ветки участвовать в prompt.
