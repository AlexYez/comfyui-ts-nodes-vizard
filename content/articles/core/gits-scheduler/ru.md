# GITSScheduler: табличное расписание GITS

`GITSScheduler` выбирает заранее рассчитанный ряд уровней шума по коэффициенту `coeff` и числу шагов. Для 2–20 шагов в исходнике есть отдельные таблицы; более длинное расписание получается log-linear интерполяцией двадцатишагового ряда.

## Что делает нода

Нода выдаёт `SIGMAS` для custom sampling. Она не принимает `MODEL`, не создаёт noise и не вызывает sampler. Три параметра определяют таблицу, её длину и хвост, который останется после частичного denoise.

`GITS` здесь — конкретный способ расставить уровни шума, а не название sampler. Алгоритм перехода по этим уровням выбирается отдельной нодой с выходом `SAMPLER`.

## Место в графе

Подключите `SIGMAS` к `SamplerCustomAdvanced`, а `NOISE`, `GUIDER`, `SAMPLER` и `LATENT` подайте на остальные входы этой ноды. `GITSScheduler` не связывается с моделью напрямую, поэтому граф не проверяет соответствие числового диапазона sampling-конфигурации guider.

Если модель модифицирована через `ModelSampling…`, сравните ожидаемый диапазон её sigma с таблицей GITS до длинного запуска. Формально несовместимая пара всё равно соединяется: несоответствие семантическое, а не типовое.

## Входы

- `coeff` — число от 0,80 до 1,50, по умолчанию 1,20; интерфейс предлагает шаг 0,05 и прячет параметр в advanced-настройках.
- `steps` — целое число от 2 до 1000, по умолчанию 10.
- `denoise` — число от 0 до 1 с шагом 0,01, по умолчанию 1.

Входа `MODEL` и выбора sampler нет. `coeff` служит ключом набора таблиц, а не непрерывным коэффициентом в формуле каждого значения.

## Выход

Единственный выход — CPU `FloatTensor` типа `SIGMAS`. При полном denoise длина равна `steps + 1`: последнее положительное значение таблицы заменяется нулём.

При `0 < denoise < 1` остаётся хвост длиной `round(steps * denoise) + 1`. `denoise <= 0` возвращает пустой тензор. Если положительное значение настолько мало, что `round(steps * denoise)` равно нулю, результат состоит из одного нуля.

## Как работает расписание

В `NOISE_LEVELS` хранятся ключи от `0.80` до `1.50` с шагом 0,05. Для каждого ключа есть девятнадцать рядов: от двух до двадцати переходов. При `steps <= 20` реализация берёт ряд с индексом `steps - 2` без интерполяции.

Для `steps > 20` выбирается последний, двадцатишаговый ряд того же коэффициента и log-linearly растягивается до `steps + 1` точек. Затем применяется хвост по denoise, а последний элемент заменяется нулём. Ключ ищется как `NOISE_LEVELS[round(coeff, 2)]`: это существенно для вызова через API.

## Параметры и настройка

В обычном интерфейсе шаг `coeff = 0,05` ведёт по существующим ключам. Через программный вызов runtime допускает любое число в диапазоне; например, `1,23` проходит числовые границы, но после округления остаётся `1.23`, которого в словаре нет, и выполнение завершается `KeyError`. Используйте только значения 0,80; 0,85; …; 1,50.

До двадцати шагов каждое значение `steps` выбирает самостоятельный ряд. После двадцати меняется механизм: новая сетка интерполируется из одной базовой таблицы. Поэтому 19, 20 и 21 шаг — не просто соседние размеры одного вычисления.

## Проверенный пример

Рецепт Wizard задаёт `coeff = 1,20`, `steps = 10`, `denoise = 1` и ведёт выход в `SamplerCustomAdvanced`. Все дорогие и модельно-зависимые компоненты оставлены внешними входами. Fragment проверен по runtime-схеме и точным типам связей.

Прямой просмотр 512 JSON официальных шаблонов 0.1.42, включая все `definitions.subgraphs`, не нашёл ни одной ноды `GITSScheduler`. Поэтому пример честно помечен как source-derived. Метод из закреплённого исходника проверен для табличного ряда, интерполяции после 20 шагов, частичного denoise, нуля и недопустимого словарного ключа 1,23. Полный sampling не запускался. Редактор пока не проверил материал вручную.

## Частые ошибки

- Через API передан `coeff = 1,23`: диапазон формально соблюдён, но ключа в таблице нет.
- `coeff` воспринимается как непрерывная формула: реализация выбирает один готовый набор.
- Ожидается одинаковая логика для 20 и 21 шага: на 21 включается интерполяция.
- `denoise = 0` ожидается как завершающий ноль: результат пуст.
- Очень малый положительный denoise ожидается как полноценный переход: возможен только `[0]`.
- Таблица применяется к модели без проверки её sampling-шкалы.

## Ограничения и производительность

До двадцати шагов работа сводится к копированию короткого списка. Более длинный ряд интерполируется на CPU через NumPy; эта операция всё равно намного дешевле model-вызовов sampler.

Реальная стоимость определяется числом переходов, а не расчётом таблицы. Максимум 1000 разрешён runtime-схемой, но тысяча model-оценок может быть непрактичной. Нода не оценивает память, время и качество и не подтверждает происхождение таблицы для конкретного checkpoint.
