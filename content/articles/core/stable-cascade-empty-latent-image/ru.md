# StableCascade_EmptyLatentImage: парные пустые latent для Stage C и Stage B

## Что делает нода

`StableCascade_EmptyLatentImage` создаёт сразу два словаря `LATENT`. Оба содержат только ключ `samples` и нулевой тензор:

- `stage_c` имеет форму `batch_size × 16 × (height // compression) × (width // compression)`;
- `stage_b` имеет форму `batch_size × 4 × (height // 4) × (width // 4)`.

Эти выходы относятся к разным стадиям Stable Cascade. Stage C строит компактный 16-канальный prior — грубое представление будущего изображения. Stage B работает с более крупной четырёхканальной сеткой и восстанавливает детали. Нода не кодирует чёрное изображение через VAE и не запускает sampling: она лишь выделяет два заполненных нулями тензора согласованного размера.

В ComfyUI 0.32.0 оба `torch.zeros` создаются без явных `device` и `dtype`. При обычных настройках PyTorch это CPU и `float32`. Это точное поведение данной реализации, а не общий контракт всех пустых latent-нод.

## Когда использовать и когда не использовать

Нода нужна для генерации Stable Cascade с нуля. В официальном text-to-image примере `stage_c` идёт в sampler модели Stage C, а `stage_b` — в отдельный sampler модели Stage B. Результат Stage C дополнительно передаётся в conditioning второй стадии.

Для img2img берите `StableCascade_StageC_VAEEncode`: её первый выход содержит структуру исходного изображения, тогда как эта нода всегда начинает с нулей. Для обычных SD1, SDXL или SD3-графов используйте пустую latent-ноду соответствующего семейства. Совпадение типа сокета `LATENT` не делает внутренние форматы взаимозаменяемыми.

`compression` меняет только сетку Stage C. Размер Stage B всегда вычисляется делением исходной ширины и высоты на четыре. Поэтому произвольное уменьшение `compression` не увеличивает обе стадии одинаково и резко меняет стоимость Stage C sampling.

## Короткий рецепт подключения

Приложенный fragment повторяет центральную ветвь официального `stable_cascade__text_to_image.png`:

1. Оставьте `1024 × 1024`, `compression = 42`, batch `1`.
2. Подайте `stage_c` на `latent_image` sampler с моделью Stage C.
3. Передайте результат этого sampler вместе с исходным positive conditioning в `StableCascade_StageB_Conditioning`.
4. Подайте `stage_b` на `latent_image` второго sampler, а подготовленное conditioning — на его positive.
5. Декодируйте результат Stage B через VAE из checkpoint Stage B.

В официальном графе Stage C использует 20 шагов и CFG `4`, Stage B — 10 шагов и CFG `1.1`; оба sampler настроены на `euler_ancestral`, `simple` и denoise `1`. Эти значения перенесены в fragment как воспроизводимый пример, а не как универсальный оптимум.

## Входы, выходы и параметры

- `width` — целевая ширина в пикселях: от `256` до `16384`, шаг UI `8`, default `1024`.
- `height` — целевая высота с теми же границами, шагом и default.
- `compression` — делитель сетки Stage C: от `4` до `128`, шаг `1`, default `42`. В интерфейсе параметр помечен как advanced, но в runtime schema он обязательный.
- `batch_size` — число пар latent: от `1` до `4096`, default `1`.

Выход `stage_c` — 16-канальный `LATENT`; выход `stage_b` — четырёхканальный `LATENT`. Ни один словарь не получает `noise_mask`, `batch_index` или служебный коэффициент масштаба.

Размеры вычисляются через целочисленное деление. Шаг `8` у width и height не гарантирует делимость на default `42`: для `1024` сетка Stage C равна `24 × 24`, поскольку `1024 // 42 = 24`. Остаток не округляется вверх. Stage B при том же разрешении получает ровно `256 × 256`.

## Типовые связки

В workflow wheel 0.1.42 точных Stable Cascade нод нет: проверены 512 JSON, 496 корневых графов и 768 графов с учётом вложенных subgraph. Поэтому связи нельзя приписывать этому набору шаблонов.

Отдельная официальная подборка `ComfyUI_examples` содержит шесть Stable Cascade PNG. Пустая нода встречается в пяти из них: text-to-image, два image-remixing примера, canny ControlNet и inpaint ControlNet. Во всех пяти оба выхода используются параллельно. `stage_c` питает первый `KSampler`, `stage_b` — второй, а результат первого sampler проходит через `StableCascade_StageB_Conditioning`.

В четырёх квадратных примерах widgets равны `[1024, 1024, 42, 1]`. Inpaint-пример использует `[1024, 768, 42, 1]`. Это реальные настройки конкретных графов, а не ограничение ноды.

## Практический пример

Для `1024 × 1024`, `compression = 42`, batch `1` нода создаёт:

- Stage C: `1 × 16 × 24 × 24`, то есть 9 216 значений;
- Stage B: `1 × 4 × 256 × 256`, то есть 262 144 значения.

В `float32` первый тензор занимает 36 КиБ, второй — 1 МиБ. Это память только под исходные zeros, без noise, промежуточных активаций и весов моделей.

Безопасная проба точного метода с `width = 1000`, `height = 770`, `compression = 42`, batch `2` дала формы `2 × 16 × 18 × 23` и `2 × 4 × 192 × 250`. Оба тензора оказались нулевыми, на CPU и в `float32`; каждый выход содержал только `samples`. Нечётные остатки были отброшены именно целочисленным делением.

## Частые ошибки и способы проверки

**Модели стадий перепутаны.** Проверьте, что первый sampler получает checkpoint Stage C, второй — Stage B. Тип `MODEL` одинаков, но архитектуры и latent-форматы различаются.

**Stage B не учитывает результат Stage C.** Одного подключения `stage_b` к sampler недостаточно. Результат первого sampler должен попасть в `StableCascade_StageB_Conditioning`, а её выход — в positive второго sampler.

**Размер Stage C кажется меньше ожидаемого.** Посчитайте `height // compression` и `width // compression` без округления. При default `42` разрешение `1024` даёт 24, а не 25.

**После смены compression резко вырос расход памяти.** Малый делитель увеличивает площадь Stage C. Сравните `(height // compression) × (width // compression)` до и после изменения.

**Img2img потерял исходную композицию.** Эта нода создаёт нули. Для кодирования картинки нужна `StableCascade_StageC_VAEEncode` и denoise ниже единицы в sampler Stage C.

**Большой batch завершается нехваткой памяти.** Верхняя граница `4096` описывает допустимое значение schema, а не безопасный объём для конкретного компьютера. Начните с batch `1`.

## Производительность и внутреннее поведение

Работа самой ноды сводится к двум выделениям памяти и заполнению нулями. Число элементов Stage C растёт как `batch × 16 × height/compression × width/compression`; для Stage B — как `batch × 4 × height/4 × width/4`. Удвоение width и height примерно вчетверо увеличивает каждую сетку.

При default `compression = 42` Stage B latent обычно намного крупнее Stage C prior. Уменьшение compression постепенно переносит часть нагрузки на Stage C. Настоящий расход sampling всё равно существенно выше размера пустых тензоров: sampler создаёт noise и промежуточные состояния, а модели держат свои веса и активации.

Нода не переносит zeros на устройство модели. Перемещение и приведение типа происходят дальше по цепочке. Если custom-node ожидает вход уже на GPU либо полагается на конкретный dtype до sampling, это отдельный контракт, которого здесь нет.

## Совместимость, изменения и устаревание

Контракт проверен для ComfyUI 0.32.0 и frontend 1.48.7. Нода активна, не experimental, не deprecated, не `api_node` и не `dev_only`. В снимке Node Replacement API для неё нет alias или формальной замены.

Runtime fingerprint закрепляет четыре обязательных входа, их диапазоны, два именованных выхода и флаги. При обновлении особенно нужно пересмотреть формулы размеров, default compression и способ выбора `device`/`dtype`: любое из этих изменений повлияет на рецепты и оценку памяти.

Официальная embedded-документация 0.5.9 верно приводит формы тензоров, но ошибочно помечает `batch_size` как необязательный. Живой `/object_info` относит его к `required`, поэтому статья следует runtime-контракту.

## Связанные ноды и источники

- `StableCascade_StageB_Conditioning` передаёт готовый prior Stage C во вторую стадию.
- `StableCascade_StageC_VAEEncode` заменяет нулевой старт на кодирование исходного изображения.
- `KSampler` выполняет denoising отдельно для Stage C и Stage B.
- `ModelSamplingStableCascade` вручную меняет sampling shift модели; это отдельная нода и не часть пустого latent.

Формы и значения параметров сверены с `nodes_stable_cascade.py`; коэффициенты форматов — с `latent_formats.py`. Реальная топология взята из workflow-метаданных официальных PNG на commit `f9431bb000ce792094ff345446e22cac1ea6cef3`. Отсутствие cases в wheel установлено полным рекурсивным просмотром версии 0.1.42.
