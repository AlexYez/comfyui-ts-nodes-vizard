# KSampler: управление сэмплированием

`KSampler` получает модель, два набора условий и исходный `LATENT`, затем выполняет сэмплирование — пошагово удаляет шум по выбранному алгоритму и расписанию. Результат остаётся в latent-пространстве, поэтому перед сохранением изображения его обычно передают в `VAEDecode`.

## Назначение и место в графе

Это основной узел вычислительной части обычного workflow. До него граф подготавливает модель, conditioning и начальный latent; после него декодер превращает результат в изображение. `KSampler` не загружает веса, не кодирует prompt и не записывает файл, поэтому каждую из этих обязанностей выполняет отдельная нода.

## Входы

| Вход | Роль |
| --- | --- |
| `model` | Модель, которая используется на каждом шаге удаления шума |
| `positive` | Условие с признаками, к которым должна двигаться генерация |
| `negative` | Условие с признаками, от которых генерация должна отклоняться |
| `latent_image` | Начальный `LATENT`: пустой для txt2img или закодированное изображение для img2img |
| `seed` | Число, из которого строится начальный шум |
| `steps` | Число шагов сэмплирования |
| `cfg` | Масштаб classifier-free guidance — сила влияния разницы между условиями |
| `sampler_name` | Алгоритм, который рассчитывает очередное состояние latent |
| `scheduler` | Расписание уровней шума по шагам |
| `denoise` | Доля полного процесса удаления шума, от `0.0` до `1.0` |

Нода выдаёт один `LATENT`. Она не создаёт готовые пиксели и сама не сохраняет файл.

## Выход и сохранение структуры

Выходной словарь сохраняет latent-структуру, которую возвращает общий sampling helper после замены поля `samples`. Дополнительные поля входного latent могут оставаться частью словаря. Для просмотра подайте результат в совместимый `VAEDecode`; прямое соединение с `SaveImage` невозможно из-за разных типов.

## Как читать основные параметры

`seed` позволяет повторить тот же начальный шум при неизменной цепочке. Для сравнения двух настроек зафиксируйте seed и меняйте один параметр за раз. Совпадение seed само по себе не гарантирует одинаковое изображение после смены checkpoint, prompt, размера, sampler, scheduler или окружения вычислений.

`steps` задаёт длину процесса. Большее число шагов означает больше вычислений, но не обещает постоянного улучшения: полезный диапазон зависит от модели, sampler и scheduler. Начинайте с значения, рекомендованного для конкретной модели, а не с максимума поля.

`cfg` усиливает влияние условий. Слишком высокое значение может ухудшить изображение — это ограничение прямо отмечено в подсказке ноды. Универсального «правильного CFG» нет; сравнивайте его на фиксированном seed.

`sampler_name` и `scheduler` образуют пару. Sampler определяет алгоритм шага, scheduler — последовательность уровней шума. Поэтому оценивать их лучше вместе, сохраняя остальные входы неизменными.

`denoise = 1.0` проходит полный процесс. Это обычный выбор для генерации из `EmptyLatentImage`. При img2img меньшее значение сильнее сохраняет структуру исходного изображения; одновременно оно оставляет модели меньше пространства для изменений.

## Воспроизводимость

При неизменном графе `seed` задаёт начальный шум, но итог также зависит от версии модели, вычислительного backend, точности и доступных оптимизаций. Для сравнения параметров сохраняйте workflow и окружение вместе с изображением. Разница между устройствами не всегда означает, что seed был проигнорирован.

## Диагностический шаблон

Следующие значения подходят как нейтральная отправная точка для проверки связей, но не как рекомендация для любой модели:

```text
seed: 42
steps: 20
cfg: 7.0
sampler_name: euler
scheduler: normal
denoise: 1.0
```

Сначала убедитесь, что workflow выполняется. Затем фиксируйте `seed` и сравнивайте по одному параметру. Если меняются сразу `steps`, `cfg`, sampler и scheduler, причину разницы установить трудно.

## Производительность

Стоимость растёт прежде всего с числом шагов, размером latent, batch и сложностью модели. Смена sampler также может менять число обращений к модели на один видимый шаг. Поэтому сравнивайте не только `steps`, но и фактическое время и потребление памяти на одном и том же графе.

## Частые ошибки

**На `latent_image` подан `IMAGE`.** Эти типы не взаимозаменяемы. Для исходной картинки сначала используйте `VAEEncode`; для чистой генерации — ноду, создающую пустой latent.

**Выход подключён прямо к `SaveImage`.** `KSampler` возвращает `LATENT`, а `SaveImage` принимает `IMAGE`. Между ними нужен `VAEDecode` с подходящим `VAE`.

**Уменьшили `denoise` при пустом latent и получили слабый результат.** Низкий denoise рассчитан прежде всего на сохранение уже существующей структуры. Для пустого latent обычно требуется полный процесс.

**Ожидается точное повторение после замены модели.** Seed описывает шум, а не готовую композицию. Выход зависит от всех входов и реализаций, участвующих в расчёте.

## Когда нужен KSamplerAdvanced

`KSamplerAdvanced` открывает управление добавлением шума, начальным и конечным шагом и остаточным шумом. Он полезен для разделённого сэмплирования и более сложных цепочек. Для обычного полного прохода `KSampler` короче и легче проверяется.
