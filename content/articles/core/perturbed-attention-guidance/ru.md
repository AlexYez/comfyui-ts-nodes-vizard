# Perturbed Attention Guidance: guidance через отключённое self-attention

## Что делает нода

`PerturbedAttentionGuidance` принимает `MODEL`, клонирует его и добавляет post-CFG hook. Обычный проход модели сначала даёт conditional-прогноз и результат CFG. Затем нода запускает тот же conditional ещё раз, но меняет self-attention в `middle`-блоке `0`: вместо смешивания токенов по весам, полученным из `query` и `key`, attention-функция возвращает проекции `value`. После этого ComfyUI всё ещё применяет штатную выходную проекцию attention.

Дополнительный прогноз обозначим `pag`. Итог ноды на каждом шаге таков:

```text
result = cfg_result + scale × (conditional_prediction − pag)
```

Иными словами, sampling отталкивается от прогноза модели с ослабленным пространственным взаимодействием. Это соответствует основной идее Perturbed-Attention Guidance: получить намеренно ухудшенный прогноз с identity-подобным self-attention и направить результат в противоположную сторону. Нода не меняет веса checkpoint и не создаёт отдельный `GUIDER`; она возвращает пропатченную копию модели.

Реализация ComfyUI намеренно узкая. Она фиксирует один UNet-блок и один тип attention, не даёт выбрать диапазон шагов и не переносит все настройки сторонней реализации, на которую ссылается исходный файл.

## Когда использовать и когда не использовать

PAG уместно проверять, когда композиция распадается, объекты сливаются или обычное CFG недостаточно хорошо удерживает пространственные отношения. Сравнение имеет смысл только при неизменных seed, prompt, sampler, sigmas, размере и остальных model patches. Начните с контрольного кадра без PAG, затем добавьте ноду и меняйте только `scale`.

Не считайте `scale = 3` универсальной рекомендацией. Это значение интерфейса ComfyUI 0.32.0, а не результат проверки всех архитектур. В официальном workflow-пакете 0.1.42 точный `PerturbedAttentionGuidance` не встречается ни в одном из 512 JSON и вложенных subgraph, поэтому официальной model-specific топологии или набора параметров для него нет.

Нода привязана к `attn1` среднего блока `0`. У модели с другой внутренней разметкой нужный участок может отсутствовать либо играть иную роль. Если результат не меняется, это ещё не доказывает ошибку графа: сначала проверьте совместимость архитектуры и сравните ненулевой `scale` с полностью исключённой нодой.

Для быстрого чернового прогона PAG может оказаться слишком дорогим: при любом ненулевом `scale` он добавляет полный conditional-вызов модели на каждом sampling step. Если нужна только исходная картинка или минимальное время итерации, временно обходите ноду либо задайте `scale = 0`.

## Короткий рецепт подключения

1. Подайте исходный `MODEL` в `PerturbedAttentionGuidance`.
2. Для первой проверки оставьте runtime default `scale = 3`.
3. Передайте выходной `MODEL` в тот же sampling path, где раньше использовалась исходная модель: например, в `CFGGuider` и совместимый scheduler.
4. Зафиксируйте seed, prompt, CFG, sampler и sigmas.
5. Сравните три варианта: без ноды, с `scale = 0` и с `scale = 3`.
6. Если отличие слишком сильное, снижайте `scale`; диапазон интерфейса допускает значения от `0` до `100`, но большой верхний предел не означает безопасный рабочий диапазон для каждой модели.

Fragment «PAG: source-derived runtime default» содержит одну patch-ноду и внешний вход `MODEL`. Он восстановлен из точной схемы и реализации ComfyUI 0.32.0. Это не официальный workflow: wheel 0.1.42 не даёт реального PAG-кейса, а полный model run для fragment не выполнялся.

## Входы, выходы и параметры

`model` — обязательный вход типа `MODEL`. Исходный объект не меняется: `execute` вызывает `clone()`, ставит hook на копию и возвращает её.

`scale` — `FLOAT`, default `3.0`, минимум `0.0`, максимум `100.0`, шаг и округление `0.01`. Параметр умножает разность обычного conditional-прогноза и дополнительного PAG-прогноза. При `scale = 0` post-CFG hook сразу возвращает готовый `cfg_result`; дополнительный model call и attention replacement не выполняются. Значение `1` добавляет одну такую разность, `3` — три. Отрицательные значения runtime-схема не разрешает.

Выход — один `MODEL`. Это клон с post-CFG function. Тип conditioning, sampler и sigmas нода не принимает, поэтому сама она не определяет, какой prompt, schedule или метод интегрирования будет использован.

Системное имя — строго `PerturbedAttentionGuidance`, модуль — `comfy_extras.nodes_pag`, категория — `model/patch/unet`. Отображаемое название и alias в `/object_info` не заданы; связывать статью по сокращению PAG нельзя.

## Типовые связки

Прозрачная цепочка для custom sampling выглядит так: `MODEL → PerturbedAttentionGuidance → CFGGuider`. Ту же пропатченную модель следует передать в scheduler, если выбранный scheduler читает параметры sampling из модели. Затем `GUIDER`, `SIGMAS`, `SAMPLER`, noise и latent сходятся в `SamplerCustomAdvanced`.

PAG можно поставить в обычный `KSampler`-путь через вход модели. Однако при последовательности нескольких model patches важен порядок: каждый следующий patch клонирует уже изменённую модель, а несколько post-CFG hooks выполняются согласно контракту их регистрации. Перестановка PAG, Epsilon Scaling, SAG или другого post-CFG patch способна изменить результат.

`SelfAttentionGuidance` относится к той же группе self-attention guidance, но механизм иной. SAG сохраняет карту внимания безусловной ветви, размывает выделенные участки latent и делает дополнительный unconditional-прогон. PAG заменяет attention на передачу `value` и делает дополнительный conditional-прогон. Эти ноды связаны по назначению, но не являются взаимозаменяемыми aliases.

## Практический пример

Безопасный tensor-probe исполнил точный класс из `nodes_pag.py` с подставным model patcher. В контрольном примере `cfg_result = 2`, conditional-прогноз равен `3`, дополнительный `pag = 1.25`, а `scale = 3`. Hook вернул:

```text
2 + (3 − 1.25) × 3 = 7.25
```

Probe также перехватил ключ replacement: `attn1`, `middle`, `0`. Переданная patch-функция вернула тот же объект `v`, не обращаясь к `q` и `k`. При `scale = 0` hook отдал исходный `cfg_result` и не вызвал дополнительный conditional batch.

Эта проверка подтверждает формулу, ветвление и точку patch, но не качество изображения. Чтобы оценить ноду на практике, возьмите сцену с несколькими объектами и чёткими пространственными отношениями. Сохраните baseline, затем повторите генерацию с тем же seed. Смотрите не только на общую выразительность, но и на соответствие prompt, мелкие детали, фон и признаки чрезмерного усиления guidance.

## Частые ошибки и способы проверки

**`scale = 0` и нода удалена дали разные результаты.** В pinned реализации нулевой scale сразу возвращает `cfg_result`, поэтому сам PAG-update отсутствует. Проверьте, не меняется ли порядок других model patches, model input или cached execution при перестройке графа.

**Время шага заметно выросло.** Это ожидаемо при `scale > 0`: post-CFG function вызывает `calc_cond_batch` ещё раз для conditional. Сравните длительность с `scale = 0`; такой тест отделяет стоимость PAG от остального графа.

**Кадр почти не изменился.** Убедитесь, что sampling получает именно выход PAG. Затем проверьте архитектуру: replacement зафиксирован на `attn1` среднего блока `0`. Не повышайте scale сразу до десятков, пока не исключены ошибка подключения и несовместимая точка attention.

**Появились жёсткие контуры или потеря деталей.** Вернитесь к меньшему scale и сравнивайте по одному параметру. PAG усиливает разность с намеренно ухудшенным прогнозом; слишком сильное отталкивание не обязано улучшать кадр.

**Ожидался отдельный negative prompt.** Нода не принимает conditioning. Conditional ветвь приходит из уже работающего sampling path; PAG меняет способ расчёта дополнительного прогноза, а не интерфейс prompt.

## Производительность и внутреннее поведение

Основная цена — один дополнительный conditional model call на sampling step при ненулевом scale. Само вычитание и умножение малы по сравнению с UNet/диффузионной моделью. Дополнительный проход использует тот же `x` и `sigma`, копию `model_options` и только positive/conditional conditioning из аргументов post-CFG hook.

В этой копии `model_options` функция `set_model_options_patch_replace` регистрирует replacement для `attn1` в `middle`, блок `0`. Attention-модуль сначала строит `q`, `k`, `v`; replacement возвращает `v`, после чего применяется штатный `to_out`. Поэтому корректнее говорить об устранении q-k-зависимого смешивания токенов, а не о полном удалении всего attention-блока.

Нода не хранит состояние между шагами и не меняет тензор исходной модели на месте. Память всё же может вырасти из-за дополнительного forward и его временных активаций. Конкретный пик зависит от модели, attention backend, размера latent, batching и настроек offload.

## Совместимость, изменения и устаревание

Статья проверена по ComfyUI 0.32.0, source commit `c2bcbecd…`, frontend 1.48.7 и `/object_info` этой установки. Runtime помечает ноду как обычную backend-ноду: `experimental`, `deprecated`, `dev_only` и `api_node` равны `false`. В pinned Node Replacement API записи для `PerturbedAttentionGuidance` нет.

Зависимость от внутреннего ключа `middle/0` делает поведение чувствительным к архитектуре модели и будущим изменениям attention patch contract. После обновления ComfyUI сверяйте module, schema fingerprint и реализацию, а не только наличие знакомого названия в меню.

Embedded docs 0.5.9 правильно указывают диапазон scale и value-only упрощение, но не заменяют чтение кода: точный conditional extra call, patch key и формула результата видны в реализации. Официальный workflow wheel 0.1.42 не содержит этой ноды, поэтому fragment в Wizard остаётся source-derived и имеет статус draft.

## Связанные ноды и источники

`SelfAttentionGuidance` использует карту self-attention и размытую unconditional-ветвь; это близкий по теме, но другой алгоритм. `CFGGuider` формирует conditional/unconditional sampling contract, в котором работает post-CFG hook. `SamplerCustomAdvanced` позволяет явно собрать guider, sigmas и sampler вокруг пропатченной модели.

Факты сверены с `comfy_extras/nodes_pag.py`, attention replacement contract ComfyUI 0.32.0, embedded docs 0.5.9 и статьёй [Self-Rectifying Diffusion Sampling with Perturbed-Attention Guidance](https://arxiv.org/abs/2403.17377). Полный recursive census официального workflow wheel 0.1.42 дал ноль точных экземпляров ноды. Tensor-probe проверил только код без весов; визуальное сравнение моделей и человеческое утверждение статьи ещё не выполнены.
