# TextToUppercase: устаревшее приведение текста к верхнему регистру

## Что делает нода

`TextToUppercase` вызывает Python-метод `str.upper()` для одной строки. Буквы меняют регистр по правилам Unicode, а цифры, пробелы и знаки препинания обычно сохраняются.

Операция способна изменить длину: немецкая `ß` превращается в `SS`. Нода не знает выбранный язык и не принимает локаль.

Общий `TextProcessingNode` помещает строку в одноэлементный список. Одновременно `/object_info` оставляет `output_is_list = null`, поэтому реальная форма значения и машинное описание расходятся.

## Когда использовать и когда не использовать

Нода нужна прежде всего для совместимости со старым графом. Для нового графа исходник рекомендует `CaseConverter` с режимом `UPPERCASE`.

Верхний регистр можно применять перед формированием метки или сравнением, если именно такое Unicode-преобразование входит в правила данных. Не используйте его как универсальную языковую нормализацию.

Перед соединением со следующим обычным `STRING`-узлом проверьте форму выхода. В закреплённой версии дополнительный список мешает прямой цепочке двух старых преобразователей.

## Короткий рецепт подключения

1. Подключите одну строку к `texts`.
2. Откройте результат в просмотре, где видна фактическая строка и её структура.
3. Проверьте языковые символы, для которых регистр может расширить строку.
4. В новом графе сравните результат с `CaseConverter(UPPERCASE)`.

Фрагмент «Преобразовать одну строку в верхний регистр» состоит из одной ноды и внешнего `STRING`. Он построен по runtime-контракту, не найденному в официальных шаблонах, и после импорта не запускался.

## Входы, выходы и параметры

`texts` — обязательный `STRING` с `multiline = false`. `is_input_list = false`: множественное имя не означает списочный вход.

Выход `texts` имеет тип `STRING` и `output_is_list = null`. Метод исполнения фактически возвращает `NodeOutput([result])`.

Параметров режима нет. Нода всегда вызывает `.upper()` и не позволяет выбрать язык, нормализацию или сохранение отдельных символов.

## Типовые связки

Проверенный преемник — `CaseConverter` с `mode = UPPERCASE`. Он использует тот же `str.upper()` и в синтетическом прогоне дал ту же строку.

Старый преобразователь можно поставить перед точным буквальным поиском, если верхний регистр входит в правила всей цепочки. Это source-derived применение: официального workflow с нодой нет.

Не соединяйте несколько старых `TextProcessingNode` вслепую. После `TextToLowercase` модель исполнения сформировала вложенный список, и прямой вызов `TextToUppercase` завершился `AttributeError`.

## Практический пример

Для строки `straße ı σς` точный класс вернул список со значением `STRASSE I ΣΣ`. `ß` расширилась до `SS`, безточечная латинская `ı` стала `I`, а обе конечные формы греческой сигмы — `Σ`.

`CaseConverter(UPPERCASE)` вернул ту же текстовую последовательность. Пример подтверждает операцию класса на Unicode, но не считается выполнением recipe fragment на холсте.

Case-sensitive census всех 512 JSON, 496 корневых workflow и 272 subgraph не нашёл ни точный тип `TextToUppercase`, ни такую строку в любом JSON.

## Частые ошибки и способы проверки

**Длина строки выросла.** Это допустимое поведение Unicode `upper()`: один символ может стать несколькими.

**Следующий узел получил список.** Проверьте `NodeOutput`; старый base class возвращает `[result]`, а выход не объявлен списочным явно.

**Результат не соответствует языковому правилу.** Нода не принимает локаль. Если правила зависят от языка, стандартного `.upper()` может быть недостаточно.

**Машинный deprecated-флаг отсутствует.** Атрибут класса равен `True`, но общий `define_schema()` его не передаёт. Display name при этом содержит `(DEPRECATED)`.

## Производительность и внутреннее поведение

Вычисление локальное и линейное по размеру текста. Метод создаёт новую строку, не обращается к диску, сети или модели.

Расширения вроде `ß → SS` увеличивают объём результата. Для коротких подписей разница мала, но фиксированный предел длины лучше проверять после смены регистра, если он относится к выходу.

Base class выбирает индивидуальный режим по `_process`, вызывает его один раз и оборачивает значение в список независимо от `output_is_list = null`.

## Совместимость, изменения и устаревание

Материал сверён с ComfyUI `0.32.0`, frontend `1.48.7` и `comfy_extras.nodes_dataset`. Отпечаток: `sha256:86a8e2fdd26c62bebbe03426b56891294975d1a932e876388c1524022d6d1b71`.

Runtime сообщает `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Код и display name считают ноду deprecated и указывают на `CaseConverter`; официальный replacement snapshot эту связь не регистрирует.

EN embedded docs предупреждает об устаревании. RU-документ предупреждение удаляет, начинает со служебной фразы «Вот перевод…» и использует `text` вместо точного входа `texts`.
