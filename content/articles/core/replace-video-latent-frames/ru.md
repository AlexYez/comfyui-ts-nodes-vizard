# ReplaceVideoLatentFrames: заменить кадры внутри video latent

`ReplaceVideoLatentFrames` копирует кадры из одного `LATENT` в заданную позицию другого. Она рассчитана на пятиосевой video latent и всегда работает по оси 2 — предполагаемой временной оси.

## 1. Что делает нода

Вход `destination` задаёт тензор, внутри которого заменяется непрерывный диапазон. Необязательный `source` содержит новые кадры. При корректной форме и позиции нода клонирует tensor назначения и присваивает в него весь временной отрезок source.

Она не меняет число кадров, не растягивает source и не смешивает значения. Если source не подключён, возвращается исходный destination без копирования.

## 2. Место в графе

Ноду ставят после подготовки двух совместимых video latent: базовой последовательности и короткого участка для замены. Результат можно передать в sampler, latent-обработку или VAE Decode.

В официальном Kandinsky 5 I2V subgraph destination и source приходят из разных выходов подготовительной video-ноды; `ReplaceVideoLatentFrames(index = 0)` подменяет начало перед следующей веткой. Для добавления кадров без сохранения длины нужна `LatentConcat`; для выбора участка — `LatentCut`.

## 3. Входы

- `destination` — основной `LATENT`, обязательный.
- `source` — необязательный `LATENT` с кадрами замены.
- `index` — стартовая позиция на оси 2, целое от `-16384` до `16384`.

Batch, каналы и spatial-размеры source должны быть совместимы с destination для tensor assignment. Нода не выполняет resize, rebatch или channel conversion.

## 4. Выход

При успешной замене выходной словарь начинается с поверхностной копии `source`, но поле `samples` получает clone тензора `destination` с заменёнными кадрами. Следовательно, форма и большая часть значений приходят от destination, а `noise_mask`, `batch_index` и другие metadata — от source.

Это необычная асимметрия: downstream видит destination-тензор, сопровождаемый source-метаданными. Если source отсутствует либо проверка диапазона не проходит, нода возвращает исходный destination, и происхождение metadata уже другое.

## 5. Как работает

Число кадров destination берётся как `destination["samples"].shape[2]`, source — так же. Для отрицательного `index` код один раз прибавляет длину destination. Затем он проверяет, что старт не правее последнего кадра и что весь source помещается до конца.

При успехе выполняется `destination_samples.clone()`, а срез `[:, :, index:index + source_frames]` заменяется source-тензором. Никакого blend нет.

Слишком отрицательный индекс после однократного сложения может остаться отрицательным. Проверка не отклоняет его отдельно; Python-срез назначения тогда может иметь неожиданную длину, и assignment способен завершиться `RuntimeError`. Exact-source probe воспроизвёл этот случай.

На четырёхосевом image latent ось 2 — высота, а не время. Нода всё равно попытается заменить строки изображения, поскольку runtime проверяет только общий тип `LATENT`.

## 6. Параметры и настройка

`index = 0` заменяет начало, `index = -1` — последний кадр, но только если source содержит ровно один кадр. Для source длиной `N` безопасный отрицательный старт последнего блока — `-N`.

До запуска проверьте форму обоих `samples`: одинаковые batch, channels, height и width; source_frames не больше доступного диапазона. Если metadata source не подходят ко всей последовательности назначения, очистите или пересоберите их отдельной нодой.

## 7. Проверенный пример

Recipe `Заменить начало video latent` повторяет topology официального Kandinsky 5 I2V subgraph: два внешних LATENT подключаются к `destination` и `source`, а `index` равен `0`. В оригинальном subgraph выход Replace идёт в следующую latent-ветку.

Класс, порты, настройка и три официальные связи сверены по workflow package 0.1.42. Exact-source tensor-проба заменила два кадра внутри пятикадровой последовательности и подтвердила, что metadata берутся из source. Полный Kandinsky workflow с моделями не запускался, поэтому recipe остаётся структурно проверенным fragment.

## 8. Частые ошибки

- Подключают image latent и считают ось 2 временем; для 4D это высота.
- Ожидают resize или broadcast source. Присваиваемые размеры должны совпасть.
- Задают старт так поздно, что source не помещается. Нода пишет warning и возвращает исходный destination.
- Используют слишком отрицательный индекс и получают tensor assignment error вместо clamp.
- Считают, что metadata результата принадлежат destination. При успешной замене они копируются из source.
- Ожидают изменение длины видео. Нода только перезаписывает существующие позиции.

## 9. Ограничения и производительность

Успешная операция клонирует весь тензор destination, даже если меняется один кадр. Для длинного video latent это требует памяти примерно под ещё одну полную последовательность. Source дополнительно остаётся в памяти до завершения операции.

Нода не валидирует ранг, семантику оси и metadata. Ветви ошибки возвращают исходный объект, тогда как успех создаёт новый tensor и словарь от source; код downstream не должен полагаться на одинаковое владение объектами во всех случаях.
