# TextToLowercase: устаревшее приведение текста к нижнему регистру

## Что делает нода

`TextToLowercase` вызывает Python-метод `str.lower()` для одной входной строки. Буквы переводятся в нижний регистр по правилам Unicode, остальные символы остаются как есть.

Это не транслитерация и не нормализация Unicode. Длина и набор кодовых точек иногда меняются: например, латинская заглавная `İ` превращается в `i` и отдельную комбинируемую точку.

Общий `TextProcessingNode` возвращает обработанную строку внутри списка. В закреплённой runtime-схеме выход `STRING` при этом имеет `output_is_list = null`, а не явный списочный флаг.

## Когда использовать и когда не использовать

Старый граф можно открыть с этой нодой, если нужно сохранить его поведение. Для нового графа исходник ComfyUI 0.32.0 рекомендует `CaseConverter` с режимом `lowercase`.

Нижний регистр полезен перед точным сравнением или группировкой, когда различие регистра намеренно не учитывается. Он не решает все задачи языкового сопоставления: метод не принимает локаль и не выполняет `casefold()`.

Не ставьте ноду в новую длинную цепочку без проверки выхода. Из-за дополнительной списочной оболочки следующий обычный текстовый узел может получить `list` вместо строки.

## Короткий рецепт подключения

1. Подключите одну строку к `texts`.
2. Передайте выход в просмотр или другую проверку, способную показать точную форму значения.
3. Сравните Unicode-результат на языках, которые встречаются в данных.
4. Для нового графа повторите задачу через `CaseConverter(lowercase)` и выберите вариант с корректным контрактом выхода.

Фрагмент «Преобразовать одну строку в нижний регистр» содержит только `TextToLowercase` и внешний вход `STRING`. Официального workflow-примера нет; фрагмент не импортировался на холст и не выполнялся.

## Входы, выходы и параметры

`texts` — обязательный однострочный вход `STRING`: в `/object_info` указано `multiline = false`. Несмотря на имя во множественном числе, `is_input_list = false`, поэтому класс обрабатывает один текст за вызов.

Выход называется `texts`, имеет тип `STRING`, а его `output_is_list` равен `null`. Сам `execute` возвращает `NodeOutput([result])`, то есть аргумент выхода содержит одноэлементный Python-список.

Других параметров нет. Нода не принимает язык, локаль, режим нормализации или правила исключений.

## Типовые связки

Исторически такую операцию ставили между источником строки и точным поиском, сравнением либо формированием имени. Здесь это лишь вывод по типам и действию кода: официальный пакет шаблонов 0.1.42 не содержит ноду.

Проверенный преемник по комментарию исходника — `CaseConverter` из `comfy_extras.nodes_string` с режимом `lowercase`. Оба класса дали одинаковую преобразованную строку в изолированном прогоне.

Прямая цепочка `TextToLowercase → TextToUppercase` в точной модели исполнения 0.32.0 не прошла: первая нода оставила вложенный список, а вторая вызвала `.upper()` у списка и получила `AttributeError`.

## Практический пример

Точный класс получил строку `ПрИВЕТ İ Σ ẞ` и вернул одноэлементный список со значением `привет i̇ σ ß`. Кириллица изменила регистр; `İ` разложилась на `i` и комбинируемую точку; греческая сигма стала строчной; `ẞ` превратилась в `ß`.

`CaseConverter` в режиме `lowercase` вернул ту же строку без дополнительной оболочки старого base class. Это подтверждает арифметику регистра, но не заменяет проверку фрагмента на холсте.

Полный case-sensitive поиск по 512 JSON, 496 корневым workflow и 272 подграфам не нашёл `TextToLowercase` ни как тип, ни как точную строку.

## Частые ошибки и способы проверки

**Следующая нода сообщает, что у `list` нет строкового метода.** Проверьте фактическую форму выхода. В 0.32.0 старый base class оборачивает строку в список, хотя runtime не объявляет выход списочным.

**Текст не совпал после смены регистра.** `lower()` не выполняет Unicode-нормализацию и не удаляет диакритику. Сравните последовательности кодовых точек, а не только вид на экране.

**Турецкие I обработались не по локальным правилам.** У ноды нет параметра локали; она использует стандартное поведение Python Unicode.

**Нода не отмечена deprecated в машинной карточке.** Display name и исходник говорят `DEPRECATED`, но `TextProcessingNode.define_schema()` не передаёт `cls.is_deprecated` в `io.Schema`, поэтому `/object_info` показывает `deprecated = false`.

## Производительность и внутреннее поведение

Метод проходит по строке и создаёт новую строку. Время и память растут с её длиной; внешних моделей, сети и файлового ввода-вывода нет.

Unicode-преобразование может заменить один символ несколькими кодовыми точками. Поэтому нельзя считать, что длина результата всегда совпадает с длиной входа.

Base class автоматически определяет индивидуальный режим по переопределённому `_process`, извлекает одноэлементные списки дополнительных параметров и затем создаёт `NodeOutput([result])`.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7` и `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:1a945d2dbe351d8451ed4355ad5a9e46835bddb61af38a68028eb27703e73873`.

Runtime-флаги: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Исходник и display name считают ноду устаревшей и называют преемником `CaseConverter`, но Node Replacement API не содержит такого перехода. Поэтому `replacedBy` в manifest не задан до появления проверенной статьи и формальной связи.

EN embedded docs 0.5.9 сообщает об устаревании; RU-версия предупреждение опускает и ошибочно называет вход `text`, а выход — переводным `тексты` вместо точных `texts`.
