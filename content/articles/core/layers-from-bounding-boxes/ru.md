# Layers From Bounding Boxes

## Что делает нода

`LayersFromBoundingBoxes` превращает batch `IMAGE` в документ `LAYERS`: каждый кадр становится отдельным raster-слоем со своей позицией. Bounding box задаёт `x`, `y` и, когда они положительны, целевые `width`, `height` слоя.

Нода может перенести маску прозрачности, имя, описание, `z_index` и область фактического содержимого. Новый набор слоёв можно добавить к уже существующему документу.

## Когда она нужна и когда не нужна

Нода нужна, когда batch хранит несколько вырезанных объектов, но каждому объекту требуется собственное положение на общем полотне. Обычный image batch не умеет хранить разные координаты кадров; `LAYERS` сохраняет их как метаданные.

Она не создаёт итоговый `IMAGE`. После неё нужен потребитель `LAYERS`, например core-композитор. Для задачи «вырезать объект и привести его к фиксированному размеру» подходит `CropByBBoxes`.

## Короткий рецепт подключения

Подайте `IMAGE` и `BOUNDING_BOX` от `PrimitiveBoundingBox`. Для предсказуемого полотна задайте одновременно `canvas_width = 1024` и `canvas_height = 1024`. Выход `LAYERS` подключите к узлу сборки слоёв.

В рецепте рамка `x = 128`, `y = 96`, `width = 512`, `height = 512`. Параметр `crop_to_content = true` ничего не обрежет без `metadata.content_rect`; слой просто получит заданное положение и размер.

## Входы и выход

Обязательный `image` принимает batch `IMAGE`. `bboxes` допускает `BOUNDING_BOX`, `ARRAY` или JSON-строку. Обычные рамки используют пиксельные `x`, `y`, `width`, `height`; normalized elements с полем `bbox` требуют ненулевые размеры canvas.

Необязательный `mask` выравнивается с batch. Однокадровая маска повторяется для всех изображений; многокадровая берётся по тому же индексу, а при нехватке кадров маска для слоя отсутствует. В этой структуре значение маски `1` означает прозрачность по соглашению `LoadImage`.

`layers` принимает существующий документ. `crop_to_content`, `canvas_width` и `canvas_height` необязательны. Выход — один объект `LAYERS`, не список и не image batch.

## Как строится документ LAYERS

Нода копирует список прежних слоёв и вычисляет базовый порядок: максимальный существующий `z_index` плюс один. Для каждого кадра создаётся словарь с `image`, `type = raster`, `x`, `y` и новым `z_index`.

Если у кадра нет соответствующей рамки, он располагается в `(0, 0)`. `metadata.z_index` рамки переопределяет автоматический порядок; `metadata.name`, а при его отсутствии `metadata.desc`, становится именем слоя.

Положительные `width` и `height` записываются как целевой размер слоя. Сам tensor на этом этапе не ресайзится: масштаб применит потребитель документа.

## Content rect, canvas и строки JSON

При `crop_to_content = true` поле `metadata.content_rect = [left, top, width, height]` обрезает tensor кадра и соответствующую маску. Позиция слоя сдвигается на `left`, `top`, а целевые `w`, `h` не записываются: слой сохраняет нативный размер обрезанного содержимого.

Явный canvas устанавливается только когда обе стороны положительны. Если одна сторона равна нулю, пара не используется; при наличии входного `layers` наследуется его корректный canvas. Без этих данных размер сможет вывести следующий узел по размещённым слоям.

JSON-строка разбирается до обработки. Ошибка синтаксиса вызывает `ValueError`. Нормализованные элементы нельзя перевести в пиксели без обеих сторон canvas, и код сообщает об этом отдельно.

## Проверенный практический пример

Синтетическая проверка добавила два кадра к документу с прежним слоем `z_index = 4`. Рамки с `metadata.z_index = 7` и `6` сохранили эти значения, а однокадровая маска повторилась для обоих кадров.

У первого кадра `content_rect` сдвинул позицию с `(10, 20)` до `(11, 21)` и обрезал image и mask до `3 × 2`. У второго rect отсутствовал, поэтому в документ вошли его `w = 50`, `h = 60`.

Проверены также JSON-рамка, явный canvas `320 × 240`, наследование `640 × 480` и отсутствие рамок: кадры получили позиции `(0, 0)`. В 496 официальных workflow нода не встретилась.

## Частые ошибки и диагностика

**После ноды нет картинки.** Выход имеет тип `LAYERS`. Подключите узел, который собирает документ слоёв в `IMAGE`.

**Normalized bbox вызывает ошибку canvas.** Задайте обе стороны canvas положительными. Одного `canvas_width` или `canvas_height` недостаточно.

**Маска пропала на части batch.** Многокадровая маска не повторяет последний кадр. Повторяется только маска с batch size 1; для остальных индексов нужна соответствующая маска.

**Слой не обрезался.** `crop_to_content` работает только с `metadata.content_rect`. Обычные поля `x`, `y`, `width`, `height` задают размещение и масштаб, а не tensor crop.

**Порядок слоёв не тот.** Проверьте `metadata.z_index`. Явное значение имеет приоритет над автоматически назначенным порядком.

## Ограничения и производительность

Без `content_rect` нода не копирует и не ресайзит image tensor: она собирает словари и ссылки на кадры. С crop создаются tensor-срезы. Основные расходы появятся у последующего композитора, особенно при большом canvas и многих слоях.

Сопоставление рамок и кадров идёт по индексу; последняя рамка не повторяется автоматически, в отличие от `CropByBBoxes`. Формат `LAYERS` экспериментальный, поэтому структуру и поведение следует перепроверять при обновлении ComfyUI.
