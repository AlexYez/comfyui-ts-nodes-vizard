# LTXVScheduler: расписание по форме latent для LTX-Video

## Что делает нода

`LTXVScheduler` строит `SIGMAS` для LTX-Video и LTX 2. В отличие от scheduler, которые получают width и height отдельными числами, эта нода умеет читать размер задачи из необязательного `LATENT`.

Если latent подключён, число токенов равно произведению `latent["samples"].shape[2:]`. Для обычного видео-тензора `[B, C, T, H, W]` это `T × H × W`; batch и channels не входят. Без latent используется фиксированное значение `4096`.

Сдвиг линейно задаётся двумя опорными точками: при 1024 токенах он равен `base_shift`, при 4096 — `max_shift`. После time-SNR преобразования список можно растянуть так, чтобы последняя ненулевая сигма стала `terminal`. Отдельный ноль в самом конце остаётся.

Выход всегда имеет `steps + 1` элементов, если вычисления дали конечные значения.

## Когда использовать и когда не использовать

Подключайте latent во всех реальных LTX workflow. Хотя порт объявлен optional, все семь официальных случаев 0.1.42 его используют. Это позволяет scheduler учитывать длительность и пространственный размер конкретного видео.

Для legacy LTXV официальные корневые графы используют 30 шагов. Пять LTX 2 subgraph используют 20 шагов, кроме distilled LoRA варианта с 12. Во всех случаях `max_shift = 2.05`, `base_shift = 0.95`, `stretch = true`, `terminal = 0.1`.

Не трактуйте `max_shift` как жёсткий максимум. Линейная формула не содержит clamp: при количестве токенов больше 4096 сдвиг становится выше `max_shift`, а ниже 1024 — ниже `base_shift`.

Не оставляйте latent отключённым в размерно-зависимом видео и не рассчитывайте, что fallback угадает форму. Значение 4096 эквивалентно ровно одной опорной точке и может не совпасть с реальным `T × H × W`.

## Короткий рецепт подключения

1. Создайте `EmptyLTXVLatentVideo` с официальными значениями `768 × 512`, `length = 97`, `batch_size = 1`.
2. Подключите его `LATENT` к optional-входу `latent` у `LTXVScheduler`.
3. Для официального legacy text-to-video случая задайте `steps = 30`, `max_shift = 2.05`, `base_shift = 0.95`, `stretch = true`, `terminal = 0.1`.
4. Передайте `SIGMAS` в `SamplerCustom` из совместимого LTXV workflow.
5. Подайте тот же latent в sampler, чтобы размерная ветвь и sampling работали с одной формой.

Fragment «LTXV 768 × 512 × 97» содержит первые две ноды этой официальной цепочки. Модель, conditioning и sampler не добавлены; поле полного workflow отсутствует.

В LTX 2 AV-графах scheduler получает объединённый latent от `LTXVConcatAVLatent` и передаёт сигмы в `SamplerCustomAdvanced`. Для такого графа не заменяйте nested latent отдельной произвольной формой.

## Входы, выходы и параметры

`steps` — `INT` от `1` до `10000`, по умолчанию `20`. Начальная сетка содержит `steps + 1` точек от `1` до `0`.

`max_shift` — `FLOAT` от `0` до `100`, по умолчанию `2.05`, шаг `0.01`. Это значение линейной функции в точке 4096 токенов.

`base_shift` — `FLOAT` с теми же пределами, по умолчанию `0.95`. Это значение при 1024 токенах. Если оба shift равны, размер latent перестаёт влиять на кривую; probe подтвердил это.

`stretch` — advanced `BOOLEAN`, по умолчанию `true`. При включении все ненулевые значения линейно преобразуются: первое остаётся около единицы, последнее ненулевое становится `terminal`. Нулевой последний элемент не входит в маску и сохраняется.

`terminal` — advanced `FLOAT` от `0` до `0.99`, по умолчанию `0.1`. При `stretch = false` код его не читает. При `terminal = 0` предпоследняя и последняя сигмы обе равны нулю.

`latent` — optional `LATENT`. Используется только форма `samples`; значения, `noise_mask` и прочие metadata не участвуют.

## Типовые связки

Legacy text-to-video: `EmptyLTXVLatentVideo → LTXVScheduler → SamplerCustom`. Image-to-video использует `LTXVImgToVideo` вместо пустого latent, но также подключает его к scheduler.

LTX 2: `LTXVConcatAVLatent → LTXVScheduler → SamplerCustomAdvanced`. Nested AV tensor сообщает `.shape` первого, то есть video-потока; реализация `NestedTensor` возвращает shape первого внутреннего tensor. Аудиоформа отдельно в token product scheduler не входит.

Один и тот же latent должен идти в scheduler и sampling-ветвь. Если после расчёта сигм форма была обрезана, rebatch-нута или заменена, размерная адаптация относится уже не к фактической задаче.

`Ideogram4Scheduler` и `Flux2Scheduler` получают пиксельные размеры, а не latent. Они показывают похожую идею адаптации к разрешению, но их формулы и модели другие.

## Практический пример

`EmptyLTXVLatentVideo(768, 512, 97, 1)` создаёт samples формы `[1, 128, 13, 16, 24]`: временная длина равна `((97 − 1) // 8) + 1 = 13`, пространственные размеры — `512 // 32` и `768 // 32`. Scheduler видит `13 × 16 × 24 = 4992` токена.

С настройками по умолчанию shift для 4992 равен примерно `2.37083`, то есть выше `max_shift = 2.05`: это обычная линейная экстраполяция. Официальный legacy workflow затем растягивает кривую к `terminal = 0.1`.

Exact-source probe для fallback 4096 и четырёх шагов получил до stretch:

```text
[0.99999994, 0.9588540, 0.8859477, 0.7213942, 0]
```

После stretch тот же список стал:

```text
[0.99999982, 0.8670831, 0.6315688, 0.1000000, 0]
```

Latent с формой `[1, 128, 3, 16, 16]` даёт 768 токенов и другую середину: приблизительно `[1, 0.80096, 0.52139, 0.1, 0]` после stretch.

## Частые ошибки и способы проверки

**Latent не подключён.** Scheduler молча использует 4096 токенов. Сравните реальное произведение `samples.shape[2:]` с fallback.

**`max_shift` оказался не максимальным.** Опорные имена относятся к 1024 и 4096 токенам. Вне интервала функция экстраполирует без ограничения.

**После stretch ожидался последний элемент `0.1`.** `terminal` применяется к последней ненулевой сигме. За ней остаётся отдельный ноль, поэтому хвост равен примерно `[0.1, 0]`.

**При `terminal = 0` появились два нуля.** Это прямой результат растяжения: предпоследняя точка становится нулём, исходный конечный ноль сохраняется.

**Один шаг дал `[0.1, 0]`, а не `[1, 0]`.** При default shift единственная ненулевая точка после stretch отображается в `terminal`. Отключите stretch для сырого `[≈1, 0]`. При shift, который даёт ровно единицу, та же одношаговая формула может разделить `0 / 0`; probe с обоими shift, равными нулю, получил `NaN`.

**Весь список содержит `NaN`.** Разрешённые интерфейсом shift до 100 могут переполнить float32 time-SNR формулу. Probe с `max_shift = base_shift = 100` дал `NaN` во всех ненулевых точках. Проверяйте `isfinite`.

## Производительность и внутреннее поведение

Нода читает только shape и выполняет несколько CPU-операций над `steps + 1` числами. Она не просматривает значения большого latent и не копирует его, поэтому собственная стоимость мала.

Для обычного tensor token count равен произведению осей после channels. Batch не влияет. Для `NestedTensor.shape` используется первый внутренний tensor, поэтому в AV-графе schedule ориентируется на video-часть.

При `stretch = true` операция меняет ненулевые элементы tensor на месте. Scale factor строится по последней ненулевой точке и `1 − terminal`; runtime не выполняет отдельную проверку нулевого делителя или конечности.

Очень большое `steps` создаёт небольшой по памяти список, но downstream sampler может выполнить тысячи model-вызовов. Основная нагрузка находится там.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7`, модулем `comfy_extras.nodes_lt`. Runtime fingerprint: `sha256:3a9ccf123d51f77df10833dd508daf46393b00eef14cc87af0289d56904372df`.

Нода не помечена как deprecated, experimental, dev-only или API node. Search aliases и replacement-запись отсутствуют.

Embedded docs 0.5.9 фиксируют optional latent, fallback 4096 и назначение stretch. Они не раскрывают опорные точки 1024/4096, линейную экстраполяцию, nested video shape, двойной ноль и численные крайние случаи.

Форма LTX latent и устройство `NestedTensor` могут меняться независимо от node schema. После обновления нужно перепроверять scheduler, конструкторы latent и официальный workflow census, а не только fingerprint.
