# FluxKVCache

## Назначение
Экспериментальная нода кэширует key/value токенов опорных изображений в Flux, чтобы не пересчитывать их на следующих шагах.
## Место в графе
Подайте `MODEL` до sampler в графе, где conditioning действительно задаёт `reference_image_num_tokens`. Без референсов оптимизация почти ничего не делает.
## Вход и выход
Единственный вход — модель; возвращается её клон с attention- и post-input patches.
## Ключ кэша
Записи разделяются строкой `block_type_block_index`. При первом обращении сохраняются последние ref_toks по оси токенов для K и V.
## Повторное обращение
При повторном обращении K/V подгоняются к текущему размеру batch через `repeat_to_batch_size`, а затем присоединяются по оси токенов. Патч после входа удаляет из `img` последние reference tokens только если кэш уже непуст и текущая сумма `reference_image_num_tokens` больше нуля.
## Метод референса
Патч устанавливает `default_ref_method = index_timestep_zero`; путь объекта различается для моделей с полем `params` и без него.
## Очистка
Объект attention patch имеет `cleanup`, очищающий словарь. Статья не предполагает сохранение кэша между независимыми запусками sampling.
## Крайние случаи
Пустой список `reference_image_num_tokens` возвращает пустой набор изменений и не заполняет кэш. Ключ не включает число reference tokens, форму, `dtype` или устройство. Если эти свойства меняются в рамках одного прохода, патч сам это не обнаружит.
## Ограничения и качество
Нода рассчитана на Flux reference-image путь, а не произвольный attention. Выигрыш зависит от числа референсных токенов; реальный benchmark не выполнялся.
## Совместимость и источники
Проверено по ComfyUI 0.32.0. Нода experimental; численное совпадение и очистка в полном Flux workflow ещё требуют исполнения.
