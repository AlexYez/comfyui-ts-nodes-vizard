# CustomCombo

## Что делает нода

`CustomCombo` создаёт редактируемый список вариантов. Пользователь добавляет строки `option1`, `option2` и далее, выбирает один вариант в combo, а нода возвращает его как `STRING` и позицию как `INDEX` типа `INT`.

Это совместная backend/frontend-нода. Backend нужен для prompt validation и выполнения, но сам список формирует расширение frontend 1.48.7.

## Когда она нужна и когда не нужна

Нода подходит для собственного небольшого enum: категория prompt, preset качества, ориентация, режим обработки. В официальных subgraph встречаются `Music/Instrument/SFX/One-shot`, `Quality/Default/Turbo`, соотношения сторон и способы смешивания.

Не используйте CustomCombo как список установленных моделей: он не сканирует папки и не обновляется от backend. Для свободного текста проще `PrimitiveString`; для вычисляемого выбора нужна отдельная логика.

## Короткий рецепт подключения

Официальный Stable Audio subgraph использует выбранную строку как ключ `JsonExtractString`:

1. Создайте варианты `Music`, `Instrument`, `SFX`.
2. Подключите выход `STRING` к входу `key` JSON-ноды.
3. В `json_string` задайте словарь с такими же ключами.
4. Используйте извлечённый текст как preset.

Рецепт каталога сохраняет эту топологию в укороченном безопасном словаре.

## Поля, выходы и сериализация

Runtime показывает обязательный `choice: COMBO` с пустым `options: []`. Frontend добавляет скрытый `index` и строковые поля `option1`, `option2`… Последнее пустое поле служит местом для нового варианта.

В `widgets_values` сохраняются выбранная строка, индекс, варианты и завершающая пустая строка. `INDEX` начинается с нуля: первый непустой вариант имеет индекс 0.

## Роль frontend

`onCustomComboCreated` собирает непустые option-поля в reactive-массив. Если текущего выбора больше нет, значение сбрасывается к первому варианту либо к пустой строке.

Скрытый индекс вычисляется через `findIndex` среди option-виджетов. При одинаковых строках будет найден первый дубль. Пустые варианты не входят в список выбора.

## Как работает backend

Backend-схема объявляет пустой combo и `accept_all_inputs=True`. `validate_inputs` всегда возвращает true, потому что варианты известны только frontend и обычная серверная проверка сочла бы их недопустимыми.

`execute(choice, index=0, **kwargs)` возвращает `(choice, index)`. Дополнительные option-поля принимаются через `**kwargs`, но сами по себе не меняют выбранное значение на сервере.

## Практический пример

Вставьте рецепт JSON-key и переключайте категорию. Выход `JsonExtractString` должен меняться вместе с `STRING`, а `INDEX` — принимать 0, 1, 2.

Затем удалите выбранный option. Frontend должен выбрать первый оставшийся вариант. Сохраните и заново откройте workflow, чтобы проверить сериализацию динамических виджетов.

## Частые ошибки и проверка

- Ожидают список моделей из папки. Options задаются вручную.
- Считают INDEX нумерацией с единицы. Он zero-based.
- Создают дубликаты и ждут разные индексы. `findIndex` возвращает первый совпавший вариант.
- Передают STRING как ключ, которого нет в JSON. Это ошибка следующей ноды.
- Запускают старый frontend: без core extension динамические option-поля не соответствуют задуманному контракту.

## Ограничения и производительность

Нода очень дешёвая; основная сложность — состояние UI и переносимость workflow. Большие списки неудобно редактировать и проверять, а ручные варианты не синхронизируются с внешним источником.

`validate_inputs=True` сознательно ослабляет обычную проверку входов этой ноды. Не трактуйте CustomCombo как границу доверия для данных, пришедших от пользователя.

## Совместимость, изменения и источники

Проверено на backend `0.32.0`, frontend `1.48.7`, docs `0.5.9`, templates `0.1.42`. Найдено 22 экземпляра, все внутри subgraph и mode 0. В закреплённом frontend exact integration находится в `customWidgets.ts`; backend называет класс frontend node with backend representation.

Редактор пока не проверил материал вручную. Backend choice/index и правила frontend изучены по коду; интерактивный браузерный сценарий всех 22 шаблонов не выполнялся.
