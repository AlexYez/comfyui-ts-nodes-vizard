# Video Slice: обрезка VIDEO по времени

## Что делает нода

`Video Slice` создаёт временное окно внутри `VIDEO`. Начало и длительность задаются в секундах, после чего нода вызывает `video.as_trimmed(start_time, duration, strict_duration=...)`.

Точный NodeId содержит пробел: `Video Slice`. В интерфейсе нода подписана `Trim Video`. Для файлового `VideoFromFile` результат остаётся ссылкой на тот же файл с другими границами.

## Когда использовать и когда не использовать

Нода нужна, когда границы известны во времени: пропустить начало, взять первые пять секунд или оставить всё от заданной секунды до конца. Официальные шаблоны используют её между `LoadVideo` и обработчиком видео.

Для точных индексов кадров используйте `VideoTemporalCrop`; для случайного окна — `VideoRandomTemporalCrop`. На видео с переменными временными интервалами секунды и номера кадров не взаимозаменяемы.

## Короткий рецепт подключения

1. Подайте один `VIDEO` в `video`.
2. Для первых пяти секунд задайте `start_time = 0` и `duration = 5`.
3. Оставьте `strict_duration = false`, если короткий исходник можно принять целиком.
4. Включите строгий режим, если недостающая длительность должна останавливать граф.

Фрагмент «Оставить первые пять секунд» повторяет самую частую настройку из официального wheel. Он оставляет `VIDEO` внешним, не загружался на холст и не исполнялся как полный workflow.

## Входы, выходы и параметры

`video` — обязательный одиночный вход `VIDEO`. `start_time` — обязательный `FLOAT` с default `0.0`, диапазоном от `-100000.0` до `100000.0` и шагом `0.001` секунды.

`duration` — обязательный `FLOAT` с default `0.0`, минимумом `0.0` и шагом `0.001`. Ноль означает «до конца». Верхний предел в runtime не задан.

`strict_duration` — обязательный `BOOLEAN` с default `false`. Если запрошенной длины не хватает, `VideoFromFile.as_trimmed` в строгом режиме возвращает `None`, а нода превращает это в `ValueError`. Единственный выход `VIDEO` не является списком.

## Типовые связки

В официальном пакете 0.1.42 найдено восемь нод `Video Slice`: шесть в корневых workflow и две внутри subgraph. Шесть корневых экземпляров получают `VIDEO` напрямую от `LoadVideo`.

В сериализованных настройках пять раз встречается `0, 5, false`, два раза — `0, 0, false`, один раз — `0, 15, false`. У двух subgraph `start_time` и `duration` также выведены наружу, поэтому сохранённые widget-значения служат начальными значениями, а не обязательными границами каждого запуска.

После slice официальный граф передаёт видео в `GetVideoComponents`, API-редактор или subgraph обработки. Это реальные топологии wheel, хотя сами шаблоны в рамках исследования не исполнялись.

## Практический пример

Двухсекундный AVI был подан в `Video Slice` с `start_time = 0`, `duration = 5`, `strict_duration = false`. Объект сохранил запрошенное окно `0–5`, но его фактическая доступная длительность составила две секунды.

С `strict_duration = true` тот же запрос завершился `ValueError`. При `start_time = 0,5` и `duration = 0` результат длился `1,5` секунды — от половины секунды до конца.

На исходном `VideoFromFile` значение `start_time = -0,5` означало последние полсекунды. Все наблюдения получены в изолированной проверке закреплённого исходника, а не при исполнении recipe-fragment.

## Частые ошибки и способы проверки

**Смотрели только на сохранённое окно.** При нестрогом запросе `get_active_trim_window()` может содержать исходную `duration`, а `get_duration()` — меньшую доступную длину. Проверяйте фактический результат у потребителя.

**Поля приняли за optional.** Embedded docs помечает виджеты с default как необязательные. В `/object_info` все четыре входа находятся в `required`.

**Повторно обрезали `VideoFromFile`.** В закреплённом `VideoFromFile.as_trimmed` новый старт прибавляется к прежнему, но прежняя duration не ограничивает дочернее окно. В изолированной проверке родитель `0,5–1,0` секунды после дочернего `duration = 0` расширился до `0,5–2,0`.

**Ожидали одинаковое поведение всех VIDEO.** Конкретный тип входа предоставляет свою реализацию `as_trimmed`. `VideoFromComponents` может сначала записать поток и проверяет границы иначе, чем `VideoFromFile`.

## Производительность и внутреннее поведение

Сама `Video Slice` выполняет один вызов `as_trimmed` и не перебирает кадры. `VideoFromFile` создаёт ещё один объект с тем же источником, новым start и duration; файл открывается при запросе длительности или данных.

Строгая проверка вызывает `trimmed.get_duration()`, поэтому может открыть контейнер ради метаданных. При `strict_duration = false` файловый путь возвращается без этой проверки.

Для `VideoFromComponents` общий `get_stream_source()` может сначала закодировать компоненты в `BytesIO`. Поэтому отложенная работа подтверждена для файлового сценария от `LoadVideo`, но не для всех реализаций `VIDEO`.
