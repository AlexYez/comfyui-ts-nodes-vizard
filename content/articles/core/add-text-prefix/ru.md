# AddTextPrefix: устаревшее добавление префикса

## Что делает нода

`AddTextPrefix` ставит значение `prefix` перед одной входной строкой `texts`. В закреплённом исходнике операция записана буквально как `prefix + text`: разделитель, пробел или пунктуацию нода не добавляет сама.

Пустой `prefix` оставляет текст без изменений. Любые символы в префиксе, включая пробелы и переводы строк, входят в результат без дополнительной обработки.

Старый `TextProcessingNode` возвращает строку внутри списка. При этом `/object_info` сообщает `output_is_list = null`, а не явный списочный выход, поэтому фактическую форму значения нужно учитывать отдельно.

## Когда использовать и когда не использовать

Нода нужна прежде всего для открытия старого графа, в котором префикс уже настроен и его поведение должно сохраниться. Для новой схемы исходник ComfyUI 0.32.0 называет преемником `StringConcatenate`, который в интерфейсе подписан как `Concatenate Text`.

Префикс подходит для фиксированной метки, общего начала подписи или другой буквальной строки. Нода не разбирает шаблоны, не проверяет путь к файлу и не добавляет разделитель по правилам языка.

Не соединяйте её вслепую с обычной текстовой нодой. Дополнительная оболочка старого базового класса может передать дальше `list` вместо ожидаемого `str`.

## Короткий рецепт подключения

1. Подключите одну строку к `texts`.
2. Задайте в `prefix` весь нужный префикс вместе с пробелом или знаком-разделителем.
3. Просмотрите точное значение и его форму до следующего соединения.
4. Для нового графа повторите операцию через `StringConcatenate`: префикс в `string_a`, исходный текст в `string_b`, пустая строка в `delimiter`.

Фрагмент «Добавить фиксированный префикс к одной строке» задаёт `prefix = "dataset: "` и оставляет `texts` внешним входом. Официального workflow-примера нет; фрагмент не импортировался на холст и не выполнялся.

## Входы, выходы и параметры

`texts` — обязательный вход `STRING` с `multiline = false`. Несмотря на имя во множественном числе, `is_input_list = false`: исполнитель вызывает класс отдельно для одного элемента.

`prefix` — второй обязательный `STRING`, тоже однострочный. У виджета есть значение по умолчанию `""`; это не делает поле optional в схеме. Если исполнитель передаёт параметр одноэлементным списком, базовый класс извлекает его единственный элемент.

Выход называется `texts` и имеет тип `STRING`. `execute` создаёт `NodeOutput([result])`, а точный прогон `merge_result_data` для одного вызова дал вложенную структуру `[[[result]]]` на уровне массива выходов исполнения.

## Типовые связки

Источник строки можно направить в `AddTextPrefix`, а результат — в просмотрщик, который показывает Python-тип и содержимое. Это безопаснее прямой цепочки со старой текстовой нодой, пока форма выхода не проверена.

Для нового графа `StringConcatenate` повторяет операцию при пустом `delimiter`. В изолированном прогоне оба класса получили `→ ` и `текст`, после чего вычислили одну и ту же строку `→ текст`; у преемника нет старой дополнительной оболочки.

Готовых связок в официальном пакете шаблонов 0.1.42 нет. Поэтому рецепт описывает только действие закреплённого исходника, а не найденный пользовательский workflow.

## Практический пример

При `texts = "portrait 01"` и `prefix = "dataset: "` выражение `prefix + text` возвращает `dataset: portrait 01`. Если убрать пробел из конца префикса, получится `dataset:portrait 01` — нода не вставит его автоматически.

Изолированный прогон закреплённого исходника также проверил строку `текст` с префиксом `→ `. Результат внутри прямого аргумента выхода был `['→ текст']`; одноэлементный список в параметре `prefix` базовый класс развернул до той же строки.

Полный case-sensitive поиск по 512 JSON, 496 корневым workflow, 4083 корневым нодам, 272 подграфам и 4037 нодам внутри них не нашёл `AddTextPrefix` ни как тип, ни как точную строку.

## Частые ошибки и способы проверки

**Префикс слипся с текстом.** Добавьте нужный пробел или знак в конец `prefix` и сравните строку посимвольно.

**Следующая нода получила список.** Проверьте фактическое значение после исполнения. Runtime объявляет `output_is_list = null`, но старый базовый класс оборачивает результат в список.

**Поле `prefix` сочли необязательным.** В embedded docs оно названо optional из-за пустого значения по умолчанию. В `/object_info` оба входа находятся в `required`.

**Wizard показывает конфликт устаревания.** Display name содержит `(DEPRECATED)`, а класс задаёт `is_deprecated = True`; общий `define_schema()` не переносит этот признак в `io.Schema`, поэтому runtime сообщает `deprecated = false`.

## Производительность и внутреннее поведение

Операция создаёт новую Python-строку длиной `len(prefix) + len(text)`. Время и дополнительная память растут вместе с общей длиной; моделей, сети и файлового ввода-вывода здесь нет.

Нода не меняет регистр и не нормализует Unicode. Она просто копирует последовательности символов в порядке «префикс, затем текст».

Автоопределение базового класса выбирает индивидуальный режим по переопределённому `_process`. После вычисления результат попадает в `NodeOutput([result])`, потому что `is_output_list` остаётся равным `None` и условие списка считается ложным.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, интерфейсом `1.48.7` и модулем `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:011507fe0631aee062f38fd0991ca3da3144a8ae8edba592016cb1b9868d731d`.

Runtime-флаги: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Исходник и отображаемое имя считают ноду устаревшей и рекомендуют `Concatenate Text`, однако Node Replacement API не содержит такого соответствия.

Поэтому манифест оставляет `replacedBy = null`: статьи для преемника в текущем каталоге ещё нет, а формальная карта замен переход не подтверждает.
