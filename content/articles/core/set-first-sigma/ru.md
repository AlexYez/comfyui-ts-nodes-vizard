# SetFirstSigma: заменить начальную сигму

## Что делает нода

`SetFirstSigma` клонирует входной тензор `SIGMAS` и записывает параметр `sigma` в элемент с индексом `0`. Остальные элементы, длина, dtype и устройство сохраняются.

Нода меняет только одну точку расписания. Она не пересчитывает соседние уровни, не сортирует последовательность и не проверяет, осталась ли первая сигма выше второй.

Начальное значение влияет на масштаб шума в custom sampler, но число само по себе не имеет универсального смысла для всех моделей. Рабочая шкала определяется объектом model sampling.

## Когда использовать и когда не использовать

Используйте ноду, когда проверенный workflow требует заменить начало уже построенного расписания. В официальных случаях 0.1.42 она стоит между `BasicScheduler` и `SamplerCustomAdvanced` в одношаговых depth/control ветках.

Подход уместен для точного воспроизведения модельно-зависимой схемы. Сохраните исходную первую сигму и источник нового значения: это помогает отличить намеренный override от случайного числа.

Не выбирайте `136`, `999` или `10000` только потому, что они встречаются в интерфейсе либо чужом workflow. Диапазон виджета сообщает технически допустимый ввод, а не безопасные рекомендации для каждой модели.

Если нужно построить всё расписание вручную, используйте `ManualSigmas`. Для изменения направления служит `FlipSigmas`; Set не разворачивает и не нормализует список.

## Короткий рецепт подключения

1. Подайте совместимую `MODEL` в `BasicScheduler`.
2. Для воспроизведения официального Lotus-паттерна выберите `scheduler = normal`, `steps = 1`, `denoise = 1`.
3. Соедините `SIGMAS` scheduler с `SetFirstSigma`.
4. Задайте `sigma = 10000` только для той же Lotus depth-схемы или подтверждённого аналога.
5. Подайте результат в `SamplerCustomAdvanced` и сравните с исходным расписанием.

Fragment «Официальный одношаговый Lotus-паттерн» содержит `BasicScheduler → SetFirstSigma`, внешний вход `MODEL` и точные widgets из `flux_depth_lora_example`. Sampler, VAE, conditioning и полный workflow не включены.

## Входы, выходы и параметры

`sigmas` принимает `SIGMAS`. `sigma` — `FLOAT` со значением по умолчанию `136`, минимумом `0`, максимумом `20000`, шагом интерфейса `0.001` и отключённым округлением виджета. Выход один — `SIGMAS`.

Реализация выполняет `sigmas.clone()`, затем `sigmas[0] = sigma`. Поэтому входной тензор не меняется. Новое число приводится к dtype входа; при низкой точности фактическое сохранённое значение может округлиться.

Пустой вход вызывает `IndexError`, потому что элемента `0` нет. Нода не содержит отдельной проверки длины. Последовательность из одного элемента допустима: её единственное значение заменяется, но sampling-переходов по-прежнему нет.

Последняя сигма остаётся прежней. Set не добавляет конечный ноль и не меняет число шагов, равное `len(sigmas) − 1`.

## Типовые связки

Подтверждённая цепочка: `BasicScheduler → SetFirstSigma → SamplerCustomAdvanced`. Она встречается во всех пяти официальных экземплярах этой ноды.

После `ManualSigmas` Set позволяет заменить первое число без повторного редактирования строки. После `FlipSigmas` он задаёт начало уже развёрнутого списка. Если поменять порядок нод, заданное значение уйдёт в конец после Flip.

Перед `SplitSigmas` override попадёт только в `high_sigmas`, кроме случая `step = 0`, когда весь исходный список одновременно остаётся в `low_sigmas`. После Split можно менять начало каждой части отдельно, но тогда легко нарушить общую границу.

## Практический пример

В пакете workflow templates JSON 0.1.42 найдено пять `SetFirstSigma`, все в subgraphs. Два виджета хранят `10000`, три — `999.0000000000002`. В каждом случае `BasicScheduler` подаёт `SIGMAS`, выход идёт в `SamplerCustomAdvanced`, а параметр `sigma` также вынесен на внешний вход subgraph.

`flux_depth_lora_example` использует `BasicScheduler` с `normal`, одним шагом и `denoise = 1`, затем `SetFirstSigma` со значением виджета `10000`. Похожие значения `999.0000000000002` встречаются в Lotus и Qwen Image ControlNet-подграфах. Они относятся к конкретной модели и не образуют общий preset.

Exact-source probe заменил начало `[5, 3, 0]` на `7.5`: выход равен `[7.5, 3, 0]`, исходный тензор не изменился и имеет другое хранилище. `[1]` превратился в `[9]`; пустой тензор вызвал `IndexError`. Реальные модели не загружались.

## Частые ошибки и способы проверки

**Пустое расписание вызвало `IndexError`.** Проверьте длину до Set. Источником пустого списка может быть `ManualSigmas` без распознанных чисел или `SplitSigmas` с границей за концом.

**Первое значение стало ниже второго.** Set не исправляет порядок. Выведите первые две сигмы и убедитесь, что выбранный сэмплер поддерживает получившуюся последовательность.

**Большое число принято за универсальный high-noise режим.** Сравните его с `sigma_max` именно этой модели и с официальным workflow. Верхний предел `20000` не подтверждает качество или устойчивость.

**Ожидался пересчёт всей кривой.** Меняется только индекс `0`. Если нужна другая форма schedule, постройте её scheduler-ом или задайте весь список вручную.

**Исчез конечный ноль.** Сама Set его не трогает. Ищите изменение в предыдущей `FlipSigmas`, ручной строке или другой операции.

**Значение после сохранения слегка отличается.** Оно приводится к dtype входного тензора. Проверяйте фактический выход, особенно для `float16` и больших чисел.

**Одноэлементный список прошёл без ошибки.** Это валидно для Set, но даёт ноль переходов. Пригодность для сэмплера проверяется отдельно.

## Производительность и внутреннее поведение

`clone()` копирует весь тензор, а запись первого элемента занимает постоянное время. Для обычного короткого schedule затраты малы; веса модели не затрагиваются.

Копия сохраняет device и dtype. Вход можно использовать в контрольной ветке: последующий override на выходе не перепишет его значения.

Нода не строит новую кривую и не обращается к model sampling. Из-за этого её стоимость не зависит от модели, но и корректность нового значения она оценить не может.

Длина не меняется, поэтому число вызовов сэмплера остаётся прежним. Изменяется стартовый уровень шума и, возможно, величина первого перехода ко второй сигме.
