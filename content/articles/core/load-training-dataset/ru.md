# LoadTrainingDataset: загрузка сохранённых shard-файлов

## Что делает нода

`LoadTrainingDataset` выбирает каталог внутри настроенных корней `datasets`, находит в нём файлы, чьи имена начинаются с `shard_` и заканчиваются на `.pkl`, и читает их по очереди. Из каждого файла извлекаются `latents` и `conditioning`; одноимённые списки объединяются через `extend`.

Результат — два отдельных списочных выхода. Нода не восстанавливает единый объект dataset и не читает изображения или подписи в исходном виде.

## Когда использовать и когда не использовать

Нода подходит для набора, который ранее записала совместимая `SaveTrainingDataset`, если файлы не менялись и каталог проверен. Так не приходится повторять VAE- и CLIP-кодирование.

Не считайте её валидатором или безопасным просмотрщиком произвольного `.pkl`. Флаг `weights_only = true` сужает возможности десериализации, но код не проверяет происхождение, размер, схему и согласованность данных. Не открывайте неизвестные файлы только потому, что они лежат в `datasets`.

## Короткий рецепт подключения

1. Сначала сохраните набор в отдельный каталог и проверьте его содержимое.
2. Обновите список нод или интерфейс, если новый каталог ещё не появился в `folder_name`.
3. Выберите реальный каталог из `COMBO`; не оставляйте служебный placeholder рецепта.
4. После загрузки сравните длины и формы обоих выходов до обучения.

Фрагмент «Выбрать ранее сохранённый набор» содержит `SELECT_SAVED_DATASET`, потому что список каталогов зависит от локальной установки. Это инструкция для ручного выбора, не готовое значение. Официального workflow-примера нет; fragment не импортировался и не выполнялся.

## Входы, выходы и параметры

`folder_name` — единственный обязательный `COMBO`. Его варианты строит `list_dataset_folders()`: каталог попадает в список, если содержит `metadata.json` либо хотя бы один `.safetensors`. В чистом закреплённом runtime список вариантов пуст.

Поиск идёт по настроенным корням `datasets` в их порядке и выбирает первый существующий каталог с таким относительным именем. Выходы `latents` типа `LATENT` и `conditioning` типа `CONDITIONING` имеют `output_is_list = true`.

`is_input_list = false`: выбранное имя поступает обычной строкой. Других настроек, включая шаблон имени shard, нода не предлагает.

## Типовые связки

Обычная пара — `SaveTrainingDataset` и последующая `LoadTrainingDataset` с тем же каталогом. Загруженные списки можно передать в `ResolutionBucket` или другую ноду, которая явно принимает списочные `LATENT` и `CONDITIONING`.

`metadata.json` участвует в обнаружении каталога, но не в самой загрузке. Поэтому каталог с одними метаданными появится в `COMBO`, а затем завершится ошибкой из-за отсутствия shard-файлов. Обратная граница тоже неожиданна: каталог только с `.pkl`, без метаданных и `.safetensors`, не попадёт в список, хотя прямой вызов метода способен его прочитать.

В официальных шаблонах 0.1.42 такой связки нет; рекомендации получены из закреплённого кода.

## Практический пример

Каталог с `shard_0000.pkl`, `shard_0001.pkl` и `shard_0002.pkl` читается в лексикографическом порядке. Если каждый файл содержит согласованные срезы, результат сохраняет порядок образцов внутри каждого среза.

В изолированном временном каталоге первоначальный набор вернул идентификаторы `0, 1, 2, 3, 4`. После короткой перезаписи сохранились старые `shard_0001.pkl` и `shard_0002.pkl`, поэтому загрузка дала `99, 2, 3, 4`, хотя метаданные говорили об одном образце.

Этот прогон проверял точный метод на синтетических тензорах. Он не был полным workflow и не подтверждает пригодность файлов от другой версии.

## Частые ошибки и способы проверки

**Каталог есть, но его нет в списке.** Проверьте корень `datasets` и наличие `metadata.json` либо `.safetensors`. Простого `shard_0000.pkl` для функции обнаружения недостаточно.

**Каталог выбран, но нода пишет `No shard files found`.** Метаданные или `.safetensors` сделали его видимым, однако загрузчик требует хотя бы один файл с префиксом `shard_` и суффиксом `.pkl`.

**Доверились `metadata.json`.** Загрузчик этот файл не открывает и не сверяет `num_samples`, `num_shards` или `shard_size`. Сравните фактические файлы и выходные длины.

**Пары разъехались.** В закреплённом коде нет проверки длины `latents` против `conditioning` ни внутри shard, ни после объединения. Синтетический shard с двумя latent и одним conditioning был принят как есть.

## Производительность и внутреннее поведение

Сначала `os.listdir` отбирает имена по простому условию: строка должна начинаться с `shard_` и заканчиваться на `.pkl`. Затем Python сортирует их как строки. Имя вроде `shard_backup.pkl` тоже подходит. Для естественного порядка числовые части должны иметь одинаковую ширину, как у `SaveTrainingDataset`.

Каждый файл загружается целиком через `torch.load(..., weights_only=True)`, после чего его списки добавляются к общим. Пиковая память включает накопленный результат и текущий shard. Метаданные, контрольная сумма и предел размера не проверяются; повреждение или неожиданная структура приводят к ошибке исходной операции.

Обход каталогов для `COMBO` умеет следовать символическим ссылкам и отслеживает inode, чтобы не зациклиться. Проверка реального пути не позволяет выйти за выбранный корень через `..`, абсолютный путь или symlink.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7` и модулем `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:bbcd14ef24bf0157948739d4f0b9caefb79cc9075bb6d102a78590bee92e6df3`.

Runtime-флаги: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Node Replacement API не содержит соответствия для `LoadTrainingDataset`.

Embedded docs 0.5.9 ошибочно помещает набор в output directory и описывает `folder_name` как `STRING` с default. Закреплённый runtime использует динамический `COMBO` из `datasets` без default. Формат экспериментальный, поэтому межверсионную загрузку следует проверять отдельно.
