# MergeImageLists: проходное объединение списков IMAGE

## Что делает нода

`MergeImageLists` принимает списочный вход `images` и возвращает список `IMAGE` в том же порядке. Собственная `_group_process` ничего не переставляет и не меняет в изображениях: она возвращает полученный список как есть.

Перед этим базовый `ImageProcessingNode` нормализует вход. Один тензор `[B,H,W,C]` превращается в `B` элементов `[1,H,W,C]`; список четырёхмерных тензоров разворачивается таким же образом. Поэтому видимое «объединение» происходит на этапе подготовки списочного входа, а не внутри метода ноды.

У ноды один системный порт `images`. Исходный комментарий предполагает, что несколько подключённых списков попадут в него уже объединёнными, но отдельного набора именованных входов или автодобавляемых портов в схеме нет.

## Когда использовать и когда не использовать

Нода пригодна для старого графа, где нужен списочный проходной узел или где исполнитель уже собирает несколько веток в один вход `images`. Она также явно разворачивает пакеты изображений в отдельные элементы списка.

Для нового графа исходник рекомендует `CreateList`. У этой ноды есть автодобавляемые входы одного согласованного типа, поэтому намерение объединить несколько веток видно прямо на холсте.

Не используйте `MergeImageLists`, чтобы склеить изображения по ширине, собрать сетку или получить один тензорный пакет одинакового размера. Она возвращает список и не выполняет ни пространственного монтажа, ни `torch.cat`.

## Короткий рецепт подключения

1. Подключите списочный `IMAGE` ко входу `images`.
2. Передайте выход в ноду, которая понимает списочную семантику.
3. Проверьте количество и порядок элементов после выполнения.
4. Для нового объединения нескольких веток сначала проверьте `CreateList`.

Фрагмент «Проверить разворачивание списка без изменения порядка» содержит только `MergeImageLists` и внешний `IMAGE`. Он не обещает несколько соединений с одним сокетом и после импорта на холст не запускался.

## Входы, выходы и параметры

`images` — обязательный `IMAGE`. Поскольку `is_input_list = true`, нода получает весь список одним вызовом. Базовый класс принимает четырёхмерный тензор или список четырёхмерных тензоров; трёхмерный `[H,W,C]` вызывает ошибку.

Выход тоже называется `images`, имеет тип `IMAGE` и помечен как список. Каждый элемент после нормализации имеет форму `[1,H,W,C]`. Разные элементы могут иметь разные высоту и ширину: код их не складывает в общий тензор.

Настраиваемых параметров нет. Порядок элементов сохраняется, пустой вход возвращает пустой список.

## Типовые связки

`LoadImageDataSetFromFolder → MergeImageLists` соответствует списочным типам. После ноды можно подключить `ShuffleDataset`, `ImageDeduplication`, `ImageGrid` или сохранение, если следующая нода действительно принимает список.

Для нескольких независимых веток исходник называет преемником `CreateList`. В закреплённой версии у него автодобавляемые входы `input1`…`input10` и согласуемый тип выхода.

Эти связки следуют исходному коду и портам. В официальных шаблонах 0.1.42 нет готового графа с `MergeImageLists`, поэтому конкретная топология нескольких соединений не подтверждена.

## Практический пример

Полная проверка 512 файлов JSON, 496 корневых графов и 272 подграфов не нашла `MergeImageLists`. Официального пользовательского сценария или набора настроек в этом пакете нет.

В точном синтетическом прогоне на вход подали два тензора: `[3,1,1,1]` со значениями 0–2 и `[5,1,1,1]` со значениями 3–7. Базовый класс развернул их в восемь элементов `[1,1,1,1]`; выход сохранил порядок `0,1,2,3,4,5,6,7`. Пустой список остался пустым.

Этот прогон проверяет метод закреплённого исходника, но не является запуском фрагмента на холсте и не проверяет несколько графовых соединений с одним сокетом.

## Частые ошибки и способы проверки

**Ожидался один тензорный пакет.** Выход помечен как список. Проверьте `output_is_list` следующей ноды и не путайте список элементов с формой `[B,H,W,C]`.

**Ожидалось объединение по ширине или высоте.** В коде нет изменения пикселей. Для монтажа нужна нода сетки, композиции или склейки изображений.

**Отдельный `[H,W,C]` вызывает `Expected 4D image tensor`.** Добавьте размер пакета, чтобы форма стала `[1,H,W,C]`.

**Нода подписана как DEPRECATED, но Wizard не показывает флаг `deprecated`.** Это расхождение закреплённой версии: исходный класс задаёт `is_deprecated = True`, а общий `define_schema` не передаёт этот признак в `/object_info`.

**Автоматическая замена не предлагается.** В исходнике указан `CreateList`, но в закреплённом Node Replacement API записи для `MergeImageLists` нет.

## Производительность и внутреннее поведение

Нода не копирует пиксели и не вызывает Pillow. Она создаёт плоский Python-список представлений тензоров и затем возвращает его.

Время работы линейно по числу элементов после разворачивания. Дополнительная память нужна для списка ссылок; сами тензоры не пересчитываются.

Разворачивание пакета использует срезы `images[i:i+1]`. Они сохраняют данные и устройство исходного тензора, а итоговый список удерживает ссылки на эти представления.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, интерфейсом `1.48.7` и модулем `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:9c83a6ff9cc25dfe2c84cd0e33ec932bf2e7c9182f4e011eff2e9b5a96f0600f`.

В `/object_info` нода имеет `experimental = true`, но `deprecated = false`, `dev_only = false` и `api_node = false`. При этом её отображаемое имя содержит `(DEPRECATED)`, а исходный класс задаёт `is_deprecated = True` и называет преемником `CreateList`.

Из-за конфликта Wizard оставляет статью в черновом статусе и показывает предупреждение в тексте, но не подменяет машинный флаг. В API замен точного соответствия нет.
