# RandomNoise: воспроизводимый шум для custom sampler

`RandomNoise` не создаёт готовый тензор в момент выполнения ноды. Она возвращает объект `NOISE`, который хранит `noise_seed`. Когда `SamplerCustomAdvanced` или `AddNoise` передаёт этому объекту конкретный `LATENT`, шум строится по его форме и с учётом `batch_index`.

## 1. Что делает нода

Нода упаковывает целое значение `noise_seed` в `Noise_RandomNoise`. Метод `generate_noise(input_latent)` позже читает `input_latent["samples"]` и вызывает `comfy.sample.prepare_noise`. Поэтому один выход `NOISE` можно подключить только туда, где принимающая нода знает целевую форму.

При одинаковом seed, форме, dtype, `batch_index` и версии генератора результат воспроизводим. Сам объект не содержит большого массива и почти не занимает памяти до вызова `generate_noise`.

## 2. Место в графе

Обычная связка custom sampling выглядит так: `RandomNoise → SamplerCustomAdvanced`. В sampler отдельно приходят `GUIDER`, `SAMPLER`, `SIGMAS` и начальный `LATENT`; уже там NOISE получает форму этого latent.

`RandomNoise` также можно подать в экспериментальную `AddNoise`, если нужно получить явно зашумленный `LATENT` до sampling. Если начальный случайный шум не нужен, альтернативой служит `DisableNoise`, который создаёт нули той же формы.

## 3. Входы

- `noise_seed` — целое от `0` до `18446744073709551615`. Значение по умолчанию — `0`.

Флаг `control_after_generate` относится к интерфейсу: frontend может после очереди оставить seed фиксированным, увеличить, уменьшить или рандомизировать его. В backend-контракт входит только получившееся число; строка `fixed` или `randomize`, сохранённая в widget workflow, не передаётся методу ноды.

## 4. Выход

Выход имеет тип `NOISE`. Это объект с полем `seed` и методом генерации, а не `LATENT` и не tensor. Его нельзя напрямую декодировать или просмотреть.

При генерации обычного тензора шум сначала создаётся на CPU в `float32`, затем приводится к dtype входного latent. Итоговая форма совпадает с `samples`. Для nested latent каждый вложенный тензор обрабатывается последовательно тем же генератором.

## 5. Как работает

`prepare_noise` создаёт CPU-генератор через `torch.manual_seed(seed)`. Без `batch_index` выполняется один `torch.randn` сразу для всей формы. Поэтому разные batch-позиции получают разные случайные значения из одной последовательности.

Если в LATENT есть `batch_index`, код берёт уникальные индексы. Он последовательно генерирует одно шумовое изображение для каждого номера от нуля до максимального индекса, сохраняет нужные и собирает batch в указанном порядке. Одинаковые индексы получают одинаковый шум. Например, `[0, 0, 2]` даёт одинаковые первые два элемента и третий рисунок из третьего шага генератора; шум для индекса 1 вычисляется и отбрасывается.

Так поддерживается согласованный шум после batch-операций: позиции с общей исходной меткой остаются одинаковыми. Однако очень большой разреженный индекс заставляет сгенерировать все промежуточные варианты.

## 6. Параметры и настройка

Для повторяемого сравнения зафиксируйте seed и не меняйте форму LATENT. Для серии вариантов включите frontend-режим `randomize` либо `increment`, но помните: это управление очередью, не часть Python-ноды.

Если workflow собирает batch из разных источников, проверьте поле `batch_index`. Оно может намеренно связать шум нескольких позиций, а может остаться устаревшим после пользовательской latent-операции. Удаление либо пересборка этого поля изменит рисунок даже при том же seed.

## 7. Проверенный пример

Recipe `Воспроизводимый шум для SamplerCustomAdvanced` ставит `RandomNoise(noise_seed = 42)` перед `SamplerCustomAdvanced`. Остальные четыре входа sampler оставлены внешними. Значение 42 с режимом fixed встречается в официальных LTX 2.3 workflow; сама topology `RandomNoise → noise` подтверждена во всех изученных template-семьях.

Полный recursive census 512 JSON нашёл 79 нод: 12 в root и 67 в subgraph, в 52 файлах. Exact-source проба подтвердила повторяемость, CPU/dtype и случай `[0, 0, 2]`. Модельный fragment не исполнялся целиком, поэтому `exampleExecuted` остаётся `false`.

## 8. Частые ошибки

- Ищут tensor на выходе самой ноды. Шум строится позже под форму LATENT.
- Считают frontend-строку `randomize` дополнительным Python-входом. Backend получает только число.
- Меняют размер, dtype или `batch_index` и ждут прежний рисунок при том же seed.
- Ожидают разный шум для двух batch-позиций с одинаковым `batch_index`.
- Используют огромный разреженный `batch_index`: код генерирует и отбрасывает все промежуточные позиции.
- Подключают `NOISE` к порту `LATENT`; это разные типы.

## 9. Ограничения и производительность

Генерация идёт на CPU, после чего sampler переносит данные по своему пути. Для большого video latent это означает заметное выделение CPU-памяти и передачу тензора. Nested latent генерируется частями, но использует одну последовательность RNG.

Стоимость с `batch_index` определяется не только batch size, но и максимальным индексом. Список `[0, 10000]` потребует 10001 случайную заготовку, хотя в выход попадут две. Значения индексов должны быть согласованными неотрицательными метками; реализация не предназначена для произвольных отрицательных идентификаторов.
