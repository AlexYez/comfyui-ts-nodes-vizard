# AddTextSuffix: устаревшее добавление суффикса

## Что делает нода

`AddTextSuffix` дописывает `suffix` после одной строки `texts`. Её `_process` вычисляет `text + suffix`, не вставляя пробел, точку или иной разделитель от себя.

Пустой суффикс возвращает исходное содержимое. Символы внутри `suffix` сохраняются дословно и в том же порядке, включая пробел в начале значения.

Результат проходит через общий `TextProcessingNode` и попадает в одноэлементный список. Одновременно `/object_info` оставляет `output_is_list = null`, поэтому схема не помечает эту оболочку как списочный выход.

## Когда использовать и когда не использовать

Используйте ноду, когда нужно воспроизвести старый граф с уже заданным суффиксом. В новом графе закреплённый исходник рекомендует `StringConcatenate`, отображаемый как `Concatenate Text`.

Операция подходит для буквальной пометки в конце строки: расширения условного имени, служебного маркера или общего окончания подписи. Она не знает о форматах файлов, грамматике и шаблонных переменных.

Если следом стоит обычная строковая нода, сначала проверьте форму выхода. Старая обёртка может превратить ожидаемую строку в список и вызвать ошибку строкового метода у следующего класса.

## Короткий рецепт подключения

1. Передайте одну строку во вход `texts`.
2. Запишите в `suffix` всё окончание вместе с ведущим пробелом или знаком-разделителем.
3. Проверьте не только вид строки, но и тип фактического результата.
4. Для новой схемы перенесите текст в `string_a`, суффикс в `string_b`, а `delimiter` у `StringConcatenate` оставьте пустым.

Фрагмент «Добавить фиксированный суффикс к одной строке» хранит `suffix = " [draft]"` и один внешний вход `texts`. Пример построен по исходнику, а не взят из официального workflow; он не импортировался и не выполнялся на холсте.

## Входы, выходы и параметры

`texts` — обязательный однострочный `STRING`. В `/object_info` у ноды `is_input_list = false`, поэтому имя во множественном числе не означает обработку всего списка одним вызовом.

`suffix` также находится в разделе `required`, имеет тип `STRING`, `multiline = false` и значение по умолчанию `""`. Базовый класс извлекает скаляр, если параметр пришёл как список ровно из одного элемента.

Выход `texts` имеет тип `STRING`, а его `output_is_list` равен `null`. Прямой `execute` возвращает `[result]` в первом аргументе `NodeOutput`; после `merge_result_data` единственный запуск образует `[[[result]]]` на уровне структуры выходов.

## Типовые связки

Перед `AddTextSuffix` обычно нужен источник строки, после неё — просмотр точного значения. Такой минимальный участок отделяет проверку операции от проблем со старым выходным контрактом.

`StringConcatenate` повторяет порядок «текст, затем суффикс», если подключить их к `string_a` и `string_b` и указать пустой `delimiter`. Изолированный прогон закреплённого исходника дал одинаковую строку `текст ←` для обоих классов.

Официальный workflow wheel 0.1.42 не показывает реальных соседей этой ноды. Другие связки в статье выводятся только из типов и реализации и не выдаются за найденный граф.

## Практический пример

Для `texts = "caption 07"` и `suffix = " [draft]"` результат равен `caption 07 [draft]`. Если leading-пробел убрать, получится `caption 07[draft]`.

В безопасном прогоне закреплённого класса строка `текст` и суффикс ` ←` дали `['текст ←']` внутри прямого аргумента выхода. Передача суффикса как `[' ←']` сработала так же, потому что общий класс разворачивает одноэлементные параметры.

Полная проверка охватила 512 JSON, 496 корневых workflow и 272 подграфа — всего 8120 нод в обеих областях. Точного `AddTextSuffix` не найдено ни в поле `type`, ни в сыром регистрозависимом тексте.

## Частые ошибки и способы проверки

**Суффикс приклеился без пробела.** Включите разделитель в начало `suffix`; нода не добавляет его автоматически.

**Значение выглядит строкой, но следующая нода падает на `list`.** Посмотрите реальный Python-тип. Причина — `NodeOutput([result])` при `output_is_list = null`.

**Embedded docs называют `suffix` необязательным.** Пустой default позволяет не менять виджет, но runtime всё равно относит вход к `required`.

**Флаг deprecated не совпадает с названием.** Класс и display name помечают ноду устаревшей, однако базовый schema builder не передаёт `is_deprecated`, и `/object_info` возвращает `false`.

## Производительность и внутреннее поведение

Python создаёт новую строку из двух последовательностей символов. Затраты времени и памяти линейны по сумме длин `text` и `suffix`; внешние ресурсы не используются.

Код не анализирует суффикс и не приводит строку к нормальной форме Unicode. Даже пустая строка проходит через оператор `+` и общую обёртку результата.

Режим обработки определяется по наличию `_process` у дочернего класса. Он индивидуальный, тогда как `is_output_list` остаётся `None`; ложность этого значения направляет результат в ветку `NodeOutput([result])`.

## Совместимость, изменения и устаревание

Материал проверен на ComfyUI `0.32.0`, интерфейсе `1.48.7` и `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:fd0c6f384b67e53c02e9e123b47cfc87c9cbfef64e8d2bdb71fd10064df945f3`.

В runtime указаны `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`. Исходник содержит `is_deprecated = True` и комментарий о переходе на `Concatenate Text`.

Node Replacement API не регистрирует этот переход. До появления проверенной статьи преемника манифест не ставит формальную связь `replacedBy`.
