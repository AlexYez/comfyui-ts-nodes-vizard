# Painter

## Что делает нода

`Painter` даёт интерактивный холст с кистью и ластиком. Рисовать можно поверх входного `IMAGE` либо на новом полотне выбранного размера и фонового цвета.

Перед выполнением frontend сохраняет нарисованный RGBA-слой как PNG во входное хранилище. Backend накладывает его на основу и возвращает два tensors: итоговый `IMAGE` и alpha рисунка как `MASK`.

## Когда она нужна и когда не нужна

Нода подходит для быстрой inpainting-маски, пометки области, дорисовки цветом и ручного прототипа прямо в графе. Оба выхода удобно проверить через `PreviewImage` и `MaskPreview`.

Для точного сложного выделения, многослойной живописи или векторного контура лучше внешний редактор. `Painter` работает с одним canvas и не заменяет layer editor `ImageCompositor`.

## Короткий рецепт подключения

Подключите базовый `IMAGE` к `Painter`. Выберите кисть, размер, цвет, opacity и hardness, нарисуйте область. Выход `MASK` отправьте в `MaskPreview`, `IMAGE` — в `PreviewImage`.

В официальном `image_anima_lllite_image_inpainting` `LoadImage` № 91 идёт в `Painter` № 694, его `MASK` — в `MaskPreview` № 695, а `IMAGE` — в inpainting-подграф. Фрагмент Wizard добавляет оба preview для безопасной проверки перед моделью.

## Входы и выходы

`image` необязателен. При подключении берётся только первый кадр `image[:1]`; его ширина и высота становятся размером canvas. Остальной batch отбрасывается.

`mask` — socketless-строка с именем загруженного RGBA PNG, а не вход типа `MASK`. Скрытые `width` и `height` задают пустое полотно от 64 до 4096 с шагом 64. `bg_color` используется только без базового изображения.

Выход `IMAGE` всегда имеет batch size 1. Выход `MASK` равен alpha нарисованного PNG: `1` — полностью нарисованная область, `0` — нет штриха. Это противоположно значению маски прозрачности в `ImageCompositor`.

## Кисть, ластик и сохранение

В Nodes 2.0 доступны brush size 1–200, цвет, opacity 0–100% и hardness 0–100%. Ластик использует canvas-операцию `destination-out` и удаляет alpha слоя рисунка.

Настройки инструмента сохраняются в properties ноды. Сам рисунок сериализуется иначе: canvas превращается в PNG, отправляется POST-запросом на `/upload/image`, а widget получает строку вида `painter-<node>-<time>.png [input]`.

Если рисунок не менялся, существующая ссылка используется повторно. Кнопка `Очистить` удаляет содержимое canvas и очищает значение mask. При открытии workflow frontend загружает сохранённый PNG через `/view`.

## Как backend собирает изображение

Без входного IMAGE создаётся однотонный RGB tensor. Цвет `#336699`, например, становится float-компонентами `0.2`, `0.4`, `0.6`. Без рисунка MASK заполняется нулями, а IMAGE возвращает основу.

При наличии PNG backend открывает его как RGBA. Если размеры отличаются от canvas, слой меняется через Pillow Lanczos. Затем вычисляется `paint_rgb × alpha + base × (1 − alpha)`.

Входное изображение не включается в загружаемый PNG: frontend показывает его отдельным нижним `<img>`, а прозрачный canvas хранит только штрихи. Поэтому backend может заново собрать результат из основы и overlay.

## Проверенные практические случаи

В 496 официальных workflow найдено четыре `Painter` в трёх корневых графах. `api_bytedance_seedream_5_0_pro_image_edit` использует пустую маску и canvas `1024 × 1024`; IMAGE Painter идёт в edit API и параллельно в preview.

`image_anima_lllite_image_inpainting` хранит temp-файл рисунка, размеры `1024 × 1024` и чёрный фон. `video_wan2_1_infinitetalk` содержит две Painter-ноды `1216 × 960`, их MASK подключены к отдельным масочным входам подграфа.

Синтетическая backend-проверка наложила красный RGBA-слой на синий batch. Результат использовал только первый кадр, изменил покрытые пиксели и вернул alpha после Lanczos-resize. Пустой canvas `128 × 64` точно воспроизвёл цвет `#336699` и нулевую маску.

## Частые ошибки и диагностика

**Рисование недоступно в классическом canvas.** Painter-widget frontend 1.48.7 реализован только для Nodes 2.0. LiteGraph показывает предупреждение о Vue-only widget.

**Входной batch сократился до одного кадра.** Это задано backend-кодом `image[:1]`. Обрабатывайте кадры отдельно, если каждому нужна своя ручная разметка.

**После запуска маска стала мягче.** Сохранённый PNG был другого размера и прошёл Lanczos-resize. Рисуйте при конечном размере canvas или проверьте `MaskPreview`.

**Ожидалось, что белая кисть создаст только MASK.** Painter одновременно смешивает RGB кисти с основой. Для неизменённого изображения используйте исходную ветку отдельно, а MASK — как управляющую.

**Запуск сообщает об upload error.** Frontend не смог сохранить dirty canvas. Пока PNG не загружен, backend не получит новое значение `mask`.

## Ограничения и производительность

Canvas PNG загружается при сериализации изменённого widget. Большие размеры увеличивают сетевой обмен между frontend и локальным сервером, объём input-файлов и стоимость Pillow-композиции.

Backend переводит PNG через NumPy и создаёт результат на CPU. Цветовая композиция выполняется напрямую в значениях RGB, без отдельного линейного цветового преобразования. Рисунок один, слоёв и истории штрихов в backend-формате нет.
