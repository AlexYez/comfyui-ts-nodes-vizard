# ComfyAndNode

## Что делает нода

`ComfyAndNode` принимает от одного до десяти autogrow-значений и возвращает результат Python `all(values.values())`. Выход true только тогда, когда каждый подключённый элемент truthy.

Входы имеют AnyType, выход всегда `BOOLEAN`. Число входов меняется в интерфейсе по мере подключения.

## Когда она нужна и когда не нужна

AND подходит для условия «всё выполнено»: включён флаг, строка непустая, счётчик ненулевой. Его результат удобно передавать в switch.

Для сравнения конкретных значений сначала создайте отдельные boolean-условия. AND не знает, что такое допустимый размер, существующий файл или положительное число; он применяет общую truthiness.

## Короткий рецепт подключения

Source-derived рецепт создаёт два truthy-входа:

1. Непустая строка `ready` идёт в `values.value0`.
2. `ComfyNotNode` превращает пустую строку в true.
3. Этот BOOLEAN идёт в `values.value1`.
4. AND возвращает true.

Удалите текст `ready`, и первый вход станет falsy — результат сменится на false.

## Autogrow-входы

Runtime описывает контейнер `values: COMFY_AUTOGROW_V3`. Template создаёт AnyType-входы с prefix `value`, min 1 и max 10. В fragment они адресуются как `values.value0`, `values.value1` и далее.

Schema не позволяет штатно оставить ноль входов. Прямой Python-вызов с пустым dict дал бы `all([]) == true`, но это не нормальная конфигурация UI.

## Правила truthiness

Ложными считаются False, None, 0, 0.0, пустая строка и пустые коллекции. Все остальные обычные значения истинны. Строка `"0"` непустая и потому truthy.

Многoэлементный tensor может отказать при bool conversion. AnyType сообщает совместимость сокета, а не универсальную логическую интерпретацию.

## Как работает внутри

Метод получает autogrow mapping и передаёт iterator `values.values()` во встроенный `all`. Python останавливает truth-проверку на первом falsy элементе.

Это short-circuit внутри метода, но не обещание ленивого графа. Autogrow-входы не объявлены lazy, поэтому upstream-узлы могут быть выполнены до вызова AND.

## Практический пример

Создайте `PrimitiveBoolean(true)`, `PrimitiveString("ready")` и `PrimitiveInt(1)`, подключите все три к AND. Результат true. По очереди замените значения на false, пустую строку и 0 — каждый вариант должен сделать результат false.

Проверяйте условие через preview до подключения к дорогостоящей ветви. Так видны ошибки типов и неожиданные правила truthiness.

## Частые ошибки и проверка

- Ждут lazy-пропуска остальных ветвей после первого false. Входы AND не lazy.
- Подключают строку `"false"`; она truthy.
- Оставляют только tensor и получают ambiguous boolean error.
- Путают AND с объединением данных. Нода возвращает только BOOLEAN.
- Рассчитывают на больше десяти входов, хотя runtime template ограничивает max 10.

## Ограничения и производительность

Сам `all` дешёвый, число входов ограничено десятью. Стоимость upstream-вычислений не сокращается одним Python short-circuit, если граф уже запросил данные.

Для тяжёлых альтернатив сначала вычислите дешёвые boolean-флаги, затем используйте их результат в lazy `ComfySwitchNode`.
