# CLIPTextEncodeLumina2

## Назначение
Локальная нода готовит текстовое условие для Lumina 2. Перед пользовательским запросом она всегда вставляет одну из двух жёстко заданных английских системных инструкций; сеть и API не используются.

## Место в графе
Подайте совместимый `CLIP`, выберите системный вариант и передайте `CONDITIONING` в ветвь семплирования Lumina 2.

## Входы
`system_prompt` принимает `superior` или `alignment`. `user_prompt` — пользовательский текст; `clip` — совместимый текстовый кодировщик.

## Выход
Нода возвращает один `CONDITIONING`, созданный методом `encode_from_tokens_scheduled`.

## Как работает
Выбранный ключ заменяется точной английской системной инструкцией. Затем строится строка `system text <Prompt Start> user text` с одиночными пробелами вокруг маркера, токенизируется целиком и передаётся в `encode_from_tokens_scheduled`. Нода не создаёт отдельные сегменты system/user.

## Выбор режима
`superior` просит о «superior images», а `alignment` — о высоком качестве и максимальном соответствии тексту. Это разные префиксы, а не числовые уровни качества.

## Проверенный пример
Проверка исходника подтверждает точную сборку строки и различие двух вариантов. В 512 официальных JSON `CLIPTextEncodeLumina2` не встречается, поэтому Wizard не называет редакционный фрагмент официальным примером. Полный запуск Lumina 2 с весами не выполнялся.

## Ошибки
Если `clip` равен `None`, исходник выдаёт отдельную понятную ошибку. Несовместимый кодировщик может принять строку, но не создать пригодное модели условие.

## Ограничения и ресурсы
Системную инструкцию нельзя отредактировать через интерфейс этой ноды. Динамические подстановки обрабатываются в пользовательском поле до выполнения backend.

## Совместимость и источники
Проверено по ComfyUI 0.32.0, frontend 1.48.7, `nodes_lumina2.py`, `/object_info` и полному пакету workflow 0.1.42. Точный идентификатор — `CLIPTextEncodeLumina2`; человеческое утверждение ожидается.
