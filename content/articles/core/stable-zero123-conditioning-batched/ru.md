# StableZero123_Conditioning_Batched: ряд ракурсов в одном пакете

## Что делает нода

`StableZero123_Conditioning_Batched` готовит пакет ракурсов для модели Stable Zero123. Одно опорное изображение кодируется через CLIP Vision и VAE, после чего для каждого элемента `batch_size` строится отдельный camera embedding.

Первый элемент использует исходные `elevation` и `azimuth`. Перед каждым следующим элементом код прибавляет `elevation_batch_increment` и `azimuth_batch_increment`. Positive conditioning получает повторённые признаки изображения и соответствующий угол камеры. Negative conditioning содержит нулевые признаки и нулевой reference latent.

Нулевой выходной latent имеет форму `[batch_size, 4, height // 8, width // 8]`. В его метаданные записывается `batch_index: [0, 0, …]`, поэтому sampler с одним seed создаёт одинаковый исходный шум для всех ракурсов.

## Когда использовать и когда не использовать

Нода нужна для последовательного ряда видов одного объекта: например, восьми направлений по горизонту с шагом 45°. Одинаковый исходный шум позволяет сравнивать влияние камеры без отдельной шумовой реализации для каждого элемента.

Если всем элементам нужен один угол, проще использовать `StableZero123_Conditioning`. Для временной последовательности SV3D с встроенным маршрутом 0–360° применяйте `SV3D_Conditioning`. Эта нода формирует batch независимых изображений, а не временной video latent.

`init_image` должен содержать один элемент. Несколько опорных изображений дают несовместимые размеры pooled CLIP tensor и camera tensor в закреплённой реализации. Нода также не проверяет, соответствует ли модель Stable Zero123: совместимость компонентов остаётся обязанностью графа.

## Короткий рецепт подключения

1. Получите `MODEL`, `CLIP_VISION` и VAE из совместимого checkpoint через `ImageOnlyCheckpointLoader`.
2. Подайте одно `IMAGE` в `init_image`.
3. Задайте начальные углы, число ракурсов и шаги. Для полного круга без повторения конечной точки можно взять `batch_size = 8`, `azimuth = 0`, `azimuth_batch_increment = 45`.
4. Подключите три выхода к sampler вместе с `MODEL` из того же checkpoint.
5. Декодируйте sampled latent тем же VAE.

`recipe.stable-zero123-conditioning-batched-orbit` вставляет только conditioning-ноду с этим угловым рядом. Фрагмент составлен по исходному коду и runtime-схеме. Официальным workflow он не считается: в пакете workflow 0.1.42 точных примеров ноды нет.

## Входы, выходы и параметры

Runtime относит все десять входов к `required`. Два параметра приращения отмечены `advanced`, но остаются обязательными полями схемы с нулевым значением по умолчанию.

| Имя | Тип | Поведение в ComfyUI 0.32.0 |
| --- | --- | --- |
| `clip_vision` | `CLIP_VISION` | Извлекает признаки одного опорного изображения. |
| `init_image` | `IMAGE` | Опорное изображение; безопасный контракт этой реализации — batch из одного элемента. |
| `vae` | `VAE` | Кодирует центрально обрезанную и масштабированную RGB-копию. |
| `width`, `height` | `INT` | По умолчанию 256; 16–16384, шаг 8. |
| `batch_size` | `INT` | Число ракурсов, 1–4096, по умолчанию 1. |
| `elevation` | `FLOAT` | Вертикальный угол первого элемента, −180…180°, по умолчанию 0°. |
| `azimuth` | `FLOAT` | Горизонтальный угол первого элемента, −180…180°, по умолчанию 0°. |
| `elevation_batch_increment` | `FLOAT` | Добавка к elevation на один индекс, −180…180°, по умолчанию 0°, advanced. |
| `azimuth_batch_increment` | `FLOAT` | Добавка к azimuth на один индекс, −180…180°, по умолчанию 0°, advanced. |

Выходы называются `positive`, `negative` и `latent`. Их типы — `CONDITIONING`, `CONDITIONING`, `LATENT`; ни один выход не является list-выходом ComfyUI.

## Типовые связки

`ImageOnlyCheckpointLoader` → `_Batched` сохраняет соответствие между model, vision encoder и VAE. Это надёжнее, чем выбирать произвольный `CLIPVisionLoader` отдельно от checkpoint.

`_Batched` → `KSampler` передаёт угловой ряд в positive conditioning, а `batch_index` нулевого latent — в подготовку шума. Функция `prepare_noise` строит шум только для уникальных индексов; четыре нуля дают четыре копии одного noise tensor.

`KSampler` → `VAEDecode` возвращает batch изображений. После декодирования его можно разложить по элементам или собрать в обзорную сетку. Не называйте такой batch видео: нода не задаёт fps и не создаёт временных связей модели.

CLIP Vision обрабатывает исходное изображение один раз. VAE получает отдельную RGB-копию после `common_upscale(..., "bilinear", "center")`. Reference latent остаётся с batch исходного изображения; model-side код приводит его к batch sampler.

## Практический пример

Параметры `batch_size = 8`, `elevation = 0`, `elevation_batch_increment = 0`, `azimuth = 0`, `azimuth_batch_increment = 45` дают углы:

`0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°`.

Значение 360° не добавляется, поэтому первая камера не дублируется в конце. Это арифметический пример по точному циклу ноды, а не настройки из официального workflow.

Закреплённый метод проверен на четырёх элементах: elevation `10°, 5°, 0°, −5°` и azimuth `−45°, −15°, 15°, 45°`. Последние четыре компонента positive conditioning совпали с camera-формулой из кода. Latent получил форму `[4, 4, 5, 7]`, `batch_index` оказался `[0, 0, 0, 0]`, а точная функция `prepare_noise` вернула четыре одинаковых noise tensor.

## Частые ошибки и способы проверки

- **Виджеты increments не видны.** Они помечены `advanced`; раскройте расширенные параметры ноды.
- **Получились одинаковые ракурсы.** Проверьте, что хотя бы один increment отличен от нуля. При нулевых шагах все camera embeddings равны.
- **Ожидалась автоматическая нормализация углов.** Цикл просто прибавляет шаг. Накопленный elevation не ограничивается диапазоном виджета; azimuth попадает в `sin` и `cos`, поэтому периодически повторяется через 360°.
- **Все элементы начали с одного шума.** Это задано `batch_index` из нулей. Если нужен независимый шум, после ноды можно осознанно изменить поведение через `LatentBatchSeedBehavior`, понимая, что сравнение ракурсов изменится.
- **Несколько опорных изображений вызывают ошибку формы.** Выберите один элемент `IMAGE` до этой ноды.
- **Объект обрезан.** CLIP и VAE используют центральные crop с разными целевыми пропорциями. Оставьте поля вокруг объекта.
- **Большой batch не помещается в память.** Уменьшите число ракурсов или разрешение, затем соберите круг несколькими запусками с согласованными начальными углами.

## Производительность и внутреннее поведение

CLIP Vision и VAE выполняются один раз. Признаки изображения затем повторяются до `batch_size`, а camera embeddings строятся обычным циклом Python. Затраты самого цикла малы по сравнению с семплированием; память sampler и пустого latent растёт линейно с числом ракурсов.

Для каждого элемента camera vector содержит `−elevation` в радианах, `sin(azimuth)`, `cos(azimuth)` и константу `π/2`. Elevation накапливается линейно без оборачивания. Azimuth математически периодичен из-за синуса и косинуса, хотя сохранённое число само по себе не нормализуется.

Нода повторяет pooled CLIP tensor до размера batch, но не повторяет reference latent. `Stable_Zero123.extra_conds` приводит reference latent к batch noise. Negative conditioning остаётся с одним нулевым pooled tensor; дальше размерности согласует conditioning-система модели.
