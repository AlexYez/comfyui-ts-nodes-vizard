# Porter-Duff Image Composite: композитинг по alpha

## Что делает нода

`PorterDuffImageComposite` объединяет два слоя: `source` и `destination`. У каждого слоя есть собственная маска прозрачности. Нода вычисляет итоговый цвет и итоговую прозрачность, затем возвращает их раздельно как `IMAGE` и `MASK`.

Здесь `destination` задаёт полотно результата, а `source` — слой, который участвует в выбранной операции. Это не обычное смешение двух RGB по одному коэффициенту: режим учитывает alpha обоих слоёв и может оставить пересечение, вырезать его, поменять порядок наложения или очистить результат.

## Когда использовать

Нода нужна, когда у обоих изображений уже есть осмысленная прозрачность и требуется управлять тем, как два слоя занимают общую область. Типичные задачи — собрать вырезанный объект с фоном, сохранить только пересечение масок, получить части слоёв вне пересечения или сравнить несколько правил композитинга.

Для простого размещения прямоугольного source по координатам удобнее `ImageCompositeMasked`: у неё есть `x`, `y` и флаг изменения размера. `PorterDuffImageComposite` не предоставляет координат и приводит source к размеру destination целиком.

## Входы

`source` и `destination` имеют тип `IMAGE`. До изменения размера число каналов у них должно совпадать. RGB нельзя напрямую смешать с RGBA: реализация остановится на проверке формы. Если alpha хранится внутри RGBA, сначала разделите изображение через `SplitImageWithAlpha`.

`source_alpha` и `destination_alpha` имеют тип `MASK`, несмотря на слово `alpha` в имени. Внутри ноды они преобразуются по формуле `alpha = 1 − mask`. Поэтому `MASK = 0` означает непрозрачный пиксель, а `MASK = 1` — прозрачный. Выход `MASK` у `SplitImageWithAlpha` уже использует именно это соглашение.

`mode` выбирает одну из 18 операций. Значение по умолчанию в ComfyUI 0.32.0 — `DST`, то есть вернуть destination.

## Выходы

Первый выход — непреумноженный `IMAGE` результата. Второй — `MASK`, равная `1 − итоговая alpha`. Полностью прозрачный пиксель получает чёрный цвет и значение маски `1`; полностью непрозрачный — значение маски `0`.

Выходную пару можно снова собрать в RGBA через `JoinImageWithAlpha`. Если нужна только визуальная проверка прозрачности, подключите `MASK` к `MaskPreview`.

Размер результата равен размеру `destination`. Размер пакета равен минимуму из четырёх batch-размеров: лишние элементы более длинных входов не повторяются и не попадают в результат.

## Как выполняется композитинг

Сначала обе маски инвертируются в alpha, затем RGB умножается на alpha. Все формулы режимов работают с premultiplied color. После операции код делит цвет на итоговую alpha, если она больше `1e-5`, обнуляет цвет почти прозрачных пикселей и ограничивает результат диапазоном `0…1`.

Геометрию определяет destination. Его alpha при необходимости масштабируется до destination image. Source image приводится к той же высоте и ширине через `common_upscale` с bicubic и center crop; source alpha затем приводится к форме destination alpha тем же способом.

Обработка идёт по одному элементу пакета в Python-цикле. Для каждого индекса используются соответствующие source image, source mask, destination image и destination mask.

## Режимы

`SRC` и `DST` оставляют один из слоёв. `SRC_OVER` кладёт source поверх destination, `DST_OVER` меняет порядок. `SRC_IN` и `DST_IN` сохраняют часть выбранного слоя внутри alpha другого; `SRC_OUT` и `DST_OUT` — часть снаружи. `SRC_ATOP` и `DST_ATOP` ограничивают один слой областью другого, а `XOR` оставляет неперекрывающиеся участки.

`CLEAR` делает результат прозрачным. `ADD` складывает premultiplied colors и alpha с ограничением сверху. `DARKEN`, `LIGHTEN`, `SCREEN` и `OVERLAY` используют отдельные формулы смешения вместе с alpha.

У `MULTIPLY` в этой реализации итоговая alpha равна произведению alpha двух слоёв. Это уже, чем привычный вариант multiply поверх объединённой alpha: вне пересечения результат становится прозрачным. При переносе рецепта из графического редактора сначала проверьте именно alpha, а не только цвет.

## Проверенный пример

В рецепте source и destination вместе с двумя MASK поступают в `PorterDuffImageComposite` с режимом `SRC_OVER`. Цвет показывается через `PreviewImage`, прозрачность — через `MaskPreview`. Полный fragment не запускался в интерфейсе, но типы его портов и настройки проверены по `/object_info`.

В отдельном tensor-тесте непрозрачность source была `0.75`, destination — `0.5`; source был красным, destination — синим. `SRC_OVER` дал итоговую alpha `0.875`, то есть `MASK = 0.125`, и цвет примерно `[0.857, 0, 0.143]`. Все 18 режимов исполнены на той же паре, а изменение размера и правило минимального batch проверены отдельно.

В official workflow templates JSON 0.1.42 эта нода не встретилась. Рецепт основан на коде и runtime-контракте, а не объявлен официальным workflow.

## Частые ошибки

**Белая маска неожиданно скрывает слой.** Вход называется alpha, но принимает ComfyUI `MASK`: белое здесь превращается в alpha `0`.

**RGB и RGBA завершают выполнение ошибкой.** Сначала приведите оба IMAGE к одинаковому числу каналов. Для RGBA отделите alpha и работайте с RGB плюс MASK.

**Source растянулся или обрезался.** Нода всегда подгоняет source к destination. Координат размещения у неё нет.

**Пропала часть batch.** Выход использует минимальную длину четырёх входов. Подготовьте одинаковое число элементов заранее.

**`MULTIPLY` дал прозрачность вне пересечения.** Это следует из формулы кода, где output alpha равна `source alpha × destination alpha`.

## Ограничения и производительность

На каждый элемент пакета создаются premultiplied tensors и итоговые tensors; при несовпадении геометрии добавляются bicubic-resize операции. Большой batch из кадров высокого разрешения расходует заметно больше памяти, чем одно простое наложение.

Реализация не выравнивает каналы, не повторяет короткий batch и не предоставляет координаты. Она также делает clamp цвета, поэтому значения IMAGE за пределами `0…1` после композитинга будут потеряны.

Если задача сводится к одной маске поверх прямоугольного изображения, `ImageCompositeMasked` проще. Если нужна корректная прозрачность двух слоёв и операции `IN`, `OUT`, `ATOP` или `XOR`, Porter-Duff даёт нужный контракт напрямую.
