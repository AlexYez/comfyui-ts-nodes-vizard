# Extract Text from JSON

## 1. Назначение

`JsonExtractString` разбирает JSON и возвращает значение указанного ключа верхнего уровня как строку.

## 2. Место в графе

Нода подходит после LLM или API, если ответ содержит небольшой JSON-объект. Она не поддерживает JSONPath и вложенные пути.

## 3. Входы

`json_string` — полный JSON-текст, `key` — точное имя свойства. Регистр ключа значим; точка в key остаётся обычным символом.

## 4. Выход

Если верхний объект содержит key, значение преобразуется через Python `str`. JSON `null` возвращает пустую строку.

## 5. Типы значений

Строка возвращается без JSON-кавычек, число — десятичным текстом, boolean — `True` или `False` с заглавной буквы. Список и объект получают Python-представление с одинарными кавычками, которое уже не обязано быть допустимым JSON.

## 6. Пустой результат

Пустая строка возвращается для `null`, отсутствующего ключа, верхнего массива, неверного JSON и входа неподходящего типа. Эти причины не различаются отдельным статусом.

## 7. Проверенный пример

Официальные шаблоны извлекают `positive_prompt`, `negative_prompt`, `prompt`, `mu` и выбранные presets. Рецепт читает `positive_prompt` из простого объекта. Всего найдено 14 `JsonExtractString`.

## 8. Ошибки и диагностика

При пустом выходе сначала проверьте JSON-парсером вход, затем тип верхнего значения и точное имя ключа. Для вложенного объекта сначала нужна другая нода или подготовка JSON вне этого контракта.

## 9. Ограничения и производительность

Весь JSON разбирается в память. Глубокие пути, индексы массивов и сохранение JSON-формата вложенного значения не поддерживаются. Ошибки намеренно превращаются в пустую строку.

## 10. Совместимость и источники

Контракт проверен на ComfyUI 0.32.0/frontend 1.48.7 по `json.loads`, embedded docs 0.5.9 и workflow-пакету 0.1.42. Человеческое утверждение ожидается.
