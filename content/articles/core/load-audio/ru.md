# LoadAudio: открыть аудиофайл из input

## Что делает нода

`LoadAudio` читает аудиодорожку из файла в каталоге `input` ComfyUI и выдаёт значение `AUDIO`. Внутри него находятся тензор `waveform` формы `[B, C, T]` и число `sample_rate`: batch, каналы, отсчёты и частота дискретизации.

Нода берёт первый аудиопоток контейнера, декодирует все его кадры и добавляет batch-ось. Поэтому обычный файл становится waveform формы `[1, C, T]`. Исходное число каналов и частота сохраняются: автоматического сведения в mono, преобразования в stereo или resample здесь нет.

Файл может быть как аудио, так и видео с аудиодорожкой. Если подходящего потока нет либо декодер не получил ни одного аудиокадра, выполнение завершается ошибкой.

## Когда использовать и когда не использовать

Используйте `LoadAudio`, когда звук уже лежит на диске и должен попасть в граф: как референс для audio-модели, дорожка для `CreateVideo`, вход кодировщика либо один из источников для монтажа и сведения.

Нода не записывает звук с микрофона и не скачивает файл по URL. Она также не приводит материал к требованиям следующей ноды. Если downstream-операция ожидает конкретную частоту, число каналов, длительность или batch, добавьте соответствующую обработку после загрузки.

Для нескольких независимых файлов нужны несколько `LoadAudio` либо отдельная batch-логика. Одна нода всегда читает один выбранный путь и создаёт один batch-элемент, даже если контейнер содержит несколько аудиопотоков.

## Короткий рецепт подключения

1. Поместите аудиофайл в каталог `input` или загрузите его через виджет ноды.
2. Выберите имя в поле `audio`.
3. Подключите `AUDIO` к `PreviewAudio`, чтобы сначала проверить содержимое.
4. После проверки направьте тот же выход в обработчик, кодировщик или видеоноду.

Fragment «Загрузить файл и создать временное прослушивание» показывает связку `LoadAudio → PreviewAudio`. В нём стоит имя `voice_demo.mp3`, которое встречается в официальных шаблонах; перед использованием замените его своим существующим файлом. Сам файл в каталог не входит, поэтому fragment не считается выполненным end-to-end.

## Входы, выходы и параметры

Единственный обязательный вход `audio` — выбор файла с поддержкой upload. Список строится по содержимому каталога `input` и фильтруется как audio/video. В чистом runtime snapshot список пуст: имена файлов являются локальными динамическими данными и намеренно не входят в schema fingerprint.

Выход называется `AUDIO`. После декодирования нода возвращает словарь вида `{"waveform": tensor[1,C,T], "sample_rate": int}`. Для целочисленного PCM `int16` делится на `2^15`, а `int32` — на `2^31`; float-данные возвращаются без дополнительного масштабирования.

Путь разрешается относительно `input` и проверяется на выход за пределы каталога. При вычислении fingerprint нода читает байты всего файла и считает SHA-256: замена содержимого по тому же имени должна инвалидировать прежний результат.

## Типовые связки

`LoadAudio → PreviewAudio` даёт быстрый контроль выбранного файла. `LoadAudio → VAEEncodeAudio` переводит waveform в латентное представление совместимого audio-VAE. `LoadAudio → CreateVideo` добавляет готовую дорожку к последовательности кадров.

Для последовательного монтажа два выхода `LoadAudio` можно подать в `AudioConcat`. Для одновременного наложения — в `AudioMerge`, предварительно проверив batch и каналы. Эти ноды по-разному работают со временем: concat увеличивает длительность, merge подгоняет второй источник под длину первого.

Если аудио служит только референсом модели, не пропускайте его через сохраняющую ноду без необходимости. `SaveAudioAdvanced` кодирует новый файл, но его подключаемый выход передаёт исходный `AUDIO`, а не повторно декодированную копию.

## Практический пример

Полный просмотр wheel `comfyui-workflow-templates-json 0.1.42` нашёл 23 `LoadAudio` в 20 файлах: все в корневых графах, ни одного в subgraph. Из них 18 имеют mode `Always`, четыре — `Bypass`, один — `Never`. В сохранённых widget values встречаются 22 имени MP3 и одно WAV.

В официальном `video_humo.json`, workflow UUID `428ebf59-f870-43e5-b3a9-ad0c0b7b33f4`, нода № 58 загружает `video_humo_input_audio.wav`. Её `AUDIO` разветвляется к `CreateVideo.audio` и `AudioEncoderEncode.audio`: один декодированный источник одновременно прикрепляется к видео и подаётся в модельную ветку.

Изолированный запуск точной реализации прочитал FLAC, который перед этим записал штатный `SaveAudioAdvanced`. Stereo-файл с 800 отсчётами на канал и частотой 8 кГц вернулся как `[1, 2, 800]` при 8 кГц; SHA-256 из `fingerprint_inputs` совпал с хешем файла. Прослушивание и полный пользовательский fragment в этой проверке не выполнялись.

## Частые ошибки и способы проверки

**Файл виден на диске, но отсутствует в списке.** Проверьте, что он находится в настроенном `input`, имеет распознаваемый audio/video content type и доступен процессу ComfyUI. Обновите определение ноды после добавления файла.

**Ошибка `No audio stream found`.** Видео может не содержать звука. Откройте сведения о потоках в медиаплеере или `ffprobe` и выберите контейнер с аудиодорожкой.

**Ошибка `No audio frames decoded`.** Поток объявлен, но декодер не получил кадров. Перекодируйте файл в обычный PCM WAV, FLAC, MP3 или другой формат, который поддерживает установленный FFmpeg/PyAV.

**Следующая нода сообщает о форме.** `LoadAudio` не согласует каналы, batch или частоту. Сначала посмотрите `[B,C,T]` и `sample_rate`, затем подготовьте данные под контракт consumer-ноды.

**Выбран не тот язык или комментарий из многодорожечного контейнера.** Реализация всегда берёт `streams.audio[0]`. Отдельного выбора потока в schema 0.32.0 нет.

## Производительность и внутреннее поведение

PyAV декодирует файл покадрово, после чего все части объединяются через `torch.cat` по временной оси. Итоговый waveform целиком находится в памяти. Длинный многоканальный материал требует объёма, примерно пропорционального `C × T`, а не размеру сжатого файла на диске.

Fingerprint также читает файл целиком одним вызовом. Для большого медиа это отдельная дисковая операция при проверке изменений. Нода не использует модель и не требует GPU; основные затраты приходятся на декодирование, чтение и память CPU.

Форма packed-кадров нормализуется к `[C,T]`: если первая ось массива не равна числу каналов потока, данные перестраиваются и транспонируются. Необычный dtype, отличный от float, int16 и int32 после декодирования, будет отвергнут helper-функцией.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7` и модулем `comfy_extras.nodes_audio`. Runtime ID — `LoadAudio`; fingerprint — `sha256:491299352b2854e4515d49ad290212903b3bb853b303d6b4c129f3d510b992f4`.

Нода не помечена как experimental, deprecated, dev-only или API node. Она зарегистрирована через V3 extension `AudioExtension`. Динамические имена файлов исключены из структурного fingerprint, поэтому изменение локального `input` не означает изменение контракта ноды.

Embedded docs 0.5.9 правильно описывают чтение из `input` и выход `AUDIO`, но не фиксируют выбор только первого потока, форму `[1,C,T]`, правила dtype и полный SHA-256 файла. Эти детали проверены по закреплённому исходнику и изолированному прогону.
