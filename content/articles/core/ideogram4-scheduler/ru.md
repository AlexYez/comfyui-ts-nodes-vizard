# Ideogram4Scheduler: эталонное расписание Ideogram 4

## Что делает нода

`Ideogram4Scheduler` строит расписание `SIGMAS` для Ideogram 4. В расчёт входят число шагов, размеры будущего изображения и два параметра logit-normal сетки — `mu` и `std`. Модель на вход не подаётся.

Сначала к `mu` прибавляется поправка по площади:

```text
mean = mu + 0.5 × ln((width × height) / (512 × 512))
```

Затем `steps + 1` равномерных квантилей от `0` до `1` проходят через probit `ndtri`, logistic `expit` и ограничение logSNR. Полученный список разворачивается, переводится из float64 во float32, а последний элемент принудительно заменяется нулём.

Выход содержит `steps + 1` значений и задаёт `steps` переходов. При корректных runtime-параметрах сигмы убывают от уровня чуть меньше единицы к нулю.

## Когда использовать и когда не использовать

Scheduler нужен в графе Ideogram 4 вместе с preset-параметрами, которые соответствуют выбранному режиму модели. В официальных workflow 0.1.42 записаны три набора:

- Quality: `steps = 48`, `mu = 0`, `std = 1.5`;
- Default: `steps = 20`, `mu = 0`, `std = 1.75`;
- Turbo: `steps = 12`, `mu = 0.5`, `std = 1.75`.

Размеры должны совпадать с latent и итоговым изображением. Площадь входит прямо в формулу, поэтому расписание для 512 × 512 и 2048 × 2048 различается даже при одинаковом preset.

Не переносите эти наборы на другую архитектуру только из-за совместимого порта `SIGMAS`. Нода не читает `MODEL` и не проверяет, что загружен Ideogram 4. Для другого семейства используйте его собственный scheduler или подтверждённый workflow.

Если нужны произвольные художественные эксперименты с `mu` и `std`, сохраните preset как контрольную точку. Одновременное изменение размеров, числа шагов и двух параметров затрудняет разбор результата.

## Короткий рецепт подключения

1. Добавьте `Ideogram4Scheduler`.
2. Для официального Default preset задайте `steps = 20`, `mu = 0`, `std = 1.75`.
3. Установите `width` и `height` равными размерам Ideogram latent; в простом примере это `1024 × 1024`.
4. Подайте `SIGMAS` в `SamplerCustomAdvanced` из совместимого Ideogram 4 workflow.
5. Оставшиеся входы sampler — noise, guider, sampler и latent — возьмите из того же model-specific графа.

Fragment «Ideogram 4 Default 1024 × 1024» вставляет одну ноду с точным Default-набором. Полный workflow не приложен: веса, conditioning и sampling-компоненты зависят от конкретной поставки модели.

Официальные subgraph сначала округляют ширину и высоту вверх до кратности 16 с минимумом 256, затем подключают их к scheduler. В самом node-коде такого округления нет, поэтому при ручном вводе подготовьте размеры заранее.

## Входы, выходы и параметры

`steps` — `INT` от `1` до `200`, по умолчанию `20`. Выход имеет длину `steps + 1`. При одном шаге остаются только два крайних значения; из-за clamp и принудительного нуля внутренние параметры практически не проявляются.

`width` и `height` — `INT` от `256` до `8192`, по умолчанию `1024`, шаг виджета `16`. Формула использует только произведение. Пары 1024 × 512 и 512 × 1024 дают одинаковое расписание. Соотношение сторон отдельно не учитывается.

`mu` — `FLOAT` от `-10` до `10`, по умолчанию `0`, шаг `0.05`. Это базовая локация до resolution correction. Увеличение `mu` сдвигает внутренние сигмы вверх.

`std` — `FLOAT` от `0.1` до `5`, по умолчанию `1.75`, шаг `0.05`. Он умножает probit-квантиль и меняет распределение промежуточных точек.

Выход `SIGMAS` — CPU tensor float32. Внутренний расчёт выполняется в float64. Последний элемент всегда `0.0`, даже если ограничение logSNR оставило бы малое положительное число.

## Типовые связки

Официальная цепочка заканчивается как `Ideogram4Scheduler → SamplerCustomAdvanced`. В двух найденных subgraph — обычном и int8 — выход scheduler подключён к порту `sigmas` именно этого sampler.

Ширина и высота в официальном графе приходят через `PrimitiveInt` и `ComfyMathExpression`, которое вычисляет `max(((a + 15) // 16) × 16, 256)`. `steps`, `mu` и `std` извлекаются из JSON выбранного Quality, Default или Turbo preset и преобразуются в числа.

`GetImageSize` можно использовать в image-edit ветке, если размеры исходного изображения совпадают с целевым latent. Для text-to-image обычно надёжнее одна общая пара размерных параметров, подключённая и к latent-конструктору, и к scheduler.

`SplitSigmas` технически может разделить готовую последовательность на две стадии, но официальные Ideogram 4 шаблоны 0.1.42 этого не делают. Такая модификация требует отдельной проверки.

## Практический пример

Exact-source probe построил короткий четырёхшаговый список для 1024 × 1024, `mu = 0`, `std = 1.75`:

```text
[0.9998766, 0.8668633, 0.6666667, 0.3805511, 0]
```

При `mu = 0.5`, который относится к официальному Turbo preset, но здесь оставлен с четырьмя шагами только для сравнения, внутренние значения выросли:

```text
[0.9998766, 0.9147844, 0.7673035, 0.5031975, 0]
```

Для 512 × 512 средние точки probe составили примерно `0.7650, 0.5, 0.2350`; для 2048 × 2048 — `0.9287, 0.8, 0.5513`. Первая сигма одинакова из-за ограничения logSNR, последняя принудительно равна нулю.

Поворот размера с 1024 × 512 на 512 × 1024 не изменил ни одного значения. Это подтверждает зависимость от площади, а не от ориентации.

## Частые ошибки и способы проверки

**Выбран Turbo, но оставлены двадцать шагов и `mu = 0`.** Сверьте все три поля с preset целиком. Turbo — это `12 / 0.5 / 1.75`, а не только название режима модели.

**Scheduler получил исходный размер, latent — округлённый.** Повторите официальное выравнивание до кратности 16 и подайте одну пару значений в обе ветви.

**Поворот изображения должен был изменить кривую.** Формула видит только `width × height`. Если площадь та же, расписание совпадает.

**`steps = 1` не реагирует на `mu` и `std`.** Одноточечных внутренних квантилей нет: остаются ограниченный верхний край и принудительный ноль. Для исследования формы используйте хотя бы четыре шага.

**Первая сигма не равна ровно единице.** В закреплённой реализации верхний logSNR clamp даёт примерно `0.9998766`. Это ожидаемо.

**Параметры совпадают, но результат модели другой.** Проверьте checkpoint, guider, sampler, conditioning и seed. Scheduler задаёт только последовательность шумовых уровней.

## Производительность и внутреннее поведение

Расчёт выполняется на CPU над `steps + 1` числами. `ndtri`, `expit`, clamp и flip стоят мало по сравнению с одним model-вызовом. Максимум 200 шагов означает небольшой tensor, но downstream sampler может выполнить до 200 дорогих итераций.

Float64 используется для квантилей и ограничений, затем результат переводится во float32. Это снижает ошибки на концах распределения. Квантили `0` и `1` дают бесконечные значения probit, но последующий clamp удерживает расписание в конечном диапазоне.

Размерная поправка использует натуральный логарифм площади. Удвоение обеих сторон увеличивает площадь в четыре раза и добавляет к `mean` величину `ln(2)`. Значения пикселей изображения не читаются.

Scheduler детерминирован, не зависит от seed и не использует VRAM модели.

## Совместимость, изменения и устаревание

Статья проверена для ComfyUI `0.32.0`, frontend `1.48.7` и модуля `comfy_extras.nodes_ideogram4`. Runtime fingerprint: `sha256:77868508520a318f416104a08d57a672a88c175654495660969ef37ea0b61772`.

Нода не помечена как deprecated, experimental, dev-only или API node. Search aliases и запись в Node Replacement API отсутствуют. Display name равен `Ideogram 4 Scheduler`, а точный class type — `Ideogram4Scheduler`.

Embedded docs 0.5.9 верно указывают длину `steps + 1`, конечный ноль и назначение размеров. Формула resolution correction, logSNR-ограничители и официальные preset-наборы восстановлены по source и workflow wheel.

После обновления ComfyUI следует сверить как fingerprint, так и JSON preset в официальных шаблонах: schema ноды может не измениться, а рекомендованные `steps`, `mu` и `std` — измениться.
