# SaveTrainingDataset: сохранение LATENT и CONDITIONING по частям

## Что делает нода

`SaveTrainingDataset` записывает два параллельных списка — `latents` и `conditioning` — в подкаталог корня `datasets`. Данные делятся на файлы `shard_0000.pkl`, `shard_0001.pkl` и далее; рядом создаётся `metadata.json`.

Это выходная нода без портов результата. Она сохраняет уже закодированные значения и не создаёт изображения, подписи или модельные веса.

## Когда использовать и когда не использовать

Нода нужна, когда подготовленные latent-тензоры и conditioning следует сохранить для последующей загрузки без повторного VAE- и CLIP-кодирования. Удобнее всего направлять в неё два выхода `MakeTrainingDataset` либо согласованные результаты `ResolutionBucket`.

Не используйте существующий каталог как безопасное место «обновления набора». Реализация перезаписывает совпавшие имена, но не удаляет лишние старые shard-файлы. Для нового содержимого выбирайте новый пустой `folder_name` или заранее проверяйте каталог вне ноды.

## Короткий рецепт подключения

1. Подайте списки одинаковой длины в `latents` и `conditioning`.
2. Укажите новый относительный `folder_name`, например `nodes_wizard_training_example`.
3. Выберите `shard_size` не меньше `1`.
4. После исполнения проверьте `metadata.json` и фактический набор `shard_*.pkl`.

Рецепт «Сохранить набор в отдельный каталог» задаёт имя и размер shard, но оставляет данные внешними. Он может писать на диск, поэтому fragment не импортировался и не выполнялся. Официального workflow-примера в wheel 0.1.42 нет.

## Входы, выходы и параметры

`latents` — обязательный список `LATENT`, `conditioning` — обязательный список `CONDITIONING`. До создания каталога нода сравнивает только их внешние длины. Внутреннюю структуру элементов она не проверяет.

`folder_name` — обязательный `STRING`-виджет с default `training_dataset`. Разрешены относительные вложенные пути вроде `project/run1`; используется первый настроенный корень `datasets`. Пустое имя, выход через `..`, абсолютный путь и сам корень отклоняются.

`shard_size` — обязательный `INT`-виджет с default `1000`, минимумом `1` и максимумом `100000`. Поскольку `is_input_list = true`, реализация берёт `folder_name[0]` и `shard_size[0]`. Выходов нет, `output_node = true`.

## Типовые связки

`MakeTrainingDataset` даёт два списка одинаковой внешней длины, которые можно записать напрямую. После `ResolutionBucket` один элемент `LATENT` уже может содержать batch из нескольких образцов; `SaveTrainingDataset` считает такой словарь одной записью, потому что опирается только на длину внешнего списка.

`LoadTrainingDataset` читает сохранённые shard-файлы обратно. Он не использует `metadata.json` для проверки, поэтому наличие метаданных не гарантирует, что набор непротиворечив.

Проверенный официальный шаблон этой цепочки не найден. Связка основана на совместимых типах и коде закреплённой версии.

## Практический пример

При пяти парах и `shard_size = 2` нода создаёт три файла: два по две пары и один с последней парой. В `metadata.json` записывается ровно `{ "num_samples": 5, "num_shards": 3, "shard_size": 2 }`.

Изолированный прогон в временном корне `datasets` подтвердил вложенный путь `project/run1`, три shard-файла и эти метаданные. Путь `../outside`, абсолютный путь и пустое имя были отклонены. Это проверка метода исходника на синтетических тензорах, а не запуск fragment на холсте.

## Частые ошибки и способы проверки

**Длины списков различаются.** Нода выдаёт `ValueError` до создания целевого каталога. Сравните число внешних элементов обоих входов.

**После короткой перезаписи загрузились старые записи.** Повторная запись одного образца поверх прежних пяти обновляет `shard_0000.pkl` и метаданные, но оставляет `shard_0001.pkl` и `shard_0002.pkl`. Загрузчик затем прочитает и их. Проверяйте каталог или используйте новое имя.

**Искали данные в `output`.** Закреплённый код пишет в корень `datasets`, хотя embedded docs 0.5.9 называет output directory.

**Пустой набор считали ошибкой.** При двух пустых списках нода создаёт каталог и `metadata.json` с нулём образцов и shard-файлов. Такой каталог не загрузится через `LoadTrainingDataset`, потому что файлов `shard_*.pkl` нет.

## Производительность и внутреннее поведение

Число файлов вычисляется целочисленной формулой с округлением вверх: `(num_samples + shard_size - 1) // shard_size`. Каждый файл получает Python-словарь с двумя ключами: `latents` и `conditioning`, значения — соответствующие срезы списков. Для записи в открытый бинарный файл вызывается `torch.save`.

Больший `shard_size` означает меньше файлов, но более крупную отдельную запись. Метод пишет shard-файлы по очереди, затем метаданные. Временных файлов, атомарной замены и отката нет: прерванное исполнение может оставить частичный набор. Существующие совпадающие пути перезаписываются напрямую, остальные файлы каталога сохраняются.

## Совместимость, изменения и устаревание

Статья сверена с ComfyUI `0.32.0`, frontend `1.48.7` и модулем `comfy_extras.nodes_dataset`. Отпечаток схемы: `sha256:9ef540ad0a95b8804bcebd4cfde93cb40b82be5a4872a8051c7eb4348d141bfc`.

Runtime-флаги: `experimental = true`, `deprecated = false`, `dev_only = false`, `api_node = false`, `output_node = true`. Node Replacement API не содержит соответствия для `SaveTrainingDataset`.

Формат и поведение перезаписи не следует считать стабильным публичным протоколом: нода экспериментальная. Перед переносом набора между версиями проверьте исходник обеих сторон и загрузите копию в отдельном каталоге.

## Связанные ноды и источники
