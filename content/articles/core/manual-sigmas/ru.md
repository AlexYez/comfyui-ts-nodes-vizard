# ManualSigmas: задать расписание сигм строкой

## Что делает нода

`ManualSigmas` превращает строку с числами в объект `SIGMAS`. Сигма здесь обозначает уровень шума, на котором работает сэмплер. Соседняя пара значений задаёт один переход, поэтому последовательность из четырёх чисел описывает три шага.

Нода извлекает числа регулярным выражением, преобразует каждое через `float` и собирает одномерный `torch.FloatTensor`. Результат имеет тип `float32` и создаётся на CPU.

`ManualSigmas` не знает, какая модель и какой сэмплер будут использовать расписание. Она не сортирует значения, не добавляет конечный ноль, не проверяет диапазон и не сопоставляет сигмы со шкалой конкретной модели.

## Когда использовать и когда не использовать

Используйте ноду, когда расписание уже получено из проверенного workflow или документации к модели. В официальном пакете 0.1.42 она чаще всего задаёт короткие LTX-расписания для второго прохода после латентного апскейла.

Ручной список удобен и для воспроизводимого исследования: можно изменить одно значение, оставив модель, seed, сэмплер и conditioning прежними. Результат имеет смысл только рядом с контрольной веткой и исходным расписанием.

Не переносите числа между разными семействами моделей по одному названию `SIGMAS`. Шкала и рабочий диапазон зависят от model sampling. Для обычной генерации безопаснее выбрать штатный scheduler через `KSampler` или `BasicScheduler`.

Не используйте научную запись вроде `1e-3`: парсер понимает её не как `0.001`, а как два числа — `1` и `-3`. Значения `nan` и `inf` он вовсе не извлекает.

## Короткий рецепт подключения

1. Вставьте `ManualSigmas` и задайте `0.909375, 0.725, 0.421875, 0.0`.
2. Подайте выход `SIGMAS` в одноимённый вход `SamplerCustomAdvanced`.
3. Используйте этот список только в LTX-проходе, для которого он был проверен, или как явно помеченный эксперимент.
4. Сохраните исходное расписание рядом для сравнения.
5. Не добавляйте и не удаляйте конечный ноль без понимания того, какой результат должен оставить сэмплер.

Fragment «Короткое расписание LTX из официального workflow» содержит одну ноду с точной четырёхэлементной строкой. Остальные входы сэмплера, модели и полный workflow в рецепт не входят.

## Входы, выходы и параметры

`sigmas` — обязательный `STRING`, однострочный виджет со значением по умолчанию `1, 0.5`. Runtime search aliases: `custom noise schedule` и `define sigmas`. Выход один — `SIGMAS`, без list-семантики.

Парсер принимает знак, цифры и десятичные точки. Строки `1, +.5; -2.25 words 3.` и `1 0.5 -2.25 3` дадут один и тот же набор `[1, 0.5, -2.25, 3]`: запятая, пробел, точка с запятой и текст работают как разделители.

Ограничения регулярного выражения существенны. `1e-3` превращается в `[1, -3]`; `1,5` в русской десятичной записи — в два значения `[1, 5]`; фрагмент `1..2` проходит первичный поиск, но затем вызывает `ValueError` при преобразовании во `float`.

Если строка не содержит распознаваемых чисел, нода возвращает пустой `float32`-тензор. Отрицательные и возрастающие значения разрешены парсером, хотя следующий сэмплер может не поддерживать такое расписание.

## Типовые связки

Подтверждённая официальными шаблонами цепочка: `ManualSigmas → SamplerCustomAdvanced`. Все 30 найденных экземпляров подают выход прямо в порт `sigmas` этого сэмплера.

`SplitSigmas` делит готовый список на два перекрывающихся участка. `SetFirstSigma` меняет его первый элемент, а `FlipSigmas` разворачивает порядок. Последовательность этих операций важна: например, Set до Flip изменит последний элемент развёрнутого списка, а Set после Flip — первый.

Обычный `KSampler` не принимает внешний порт `SIGMAS`; он строит расписание по своим параметрам `steps` и `scheduler`. Для ручной последовательности нужна ветка custom sampler.

## Практический пример

Полный recursive census пакета 0.1.42 нашёл 30 `ManualSigmas` в 17 файлах. Все экземпляры находятся в `definitions.subgraphs[*].nodes`, а не в корневых графах. Чаще всего встречаются четыре строки:

- девять раз: `0.909375, 0.725, 0.421875, 0.0`;
- восемь раз: `1.0, 0.99375, 0.9875, 0.98125, 0.975, 0.909375, 0.725, 0.421875, 0.0`;
- семь раз: `0.85, 0.7250, 0.4219, 0.0`;
- шесть раз: тот же девятиэлементный список с первым числом `1.`.

Эти случаи относятся к LTX video workflow. Они показывают реальное применение ноды, но не делают значения универсальными для SDXL, Flux, Wan или других моделей.

Exact-source probe разобрал строку `1, +.5; -2.25 words 3.` как `[1, 0.5, -2.25, 3]`, подтвердил CPU/`float32`, пустой тензор для строки без чисел, результат `[1, -3]` для `1e-3` и `ValueError` для `1..2`. Модель и сэмплер в этой пробе не запускались.

## Частые ошибки и способы проверки

**Расписание не заканчивается нулём.** Нода ничего не дописывает. Проверьте последнюю сигму и требования выбранного сэмплера; ненулевой конец обычно означает остановку до полного денойза.

**Значения идут в неверном порядке.** Парсер сохраняет порядок строки. Для обычного прямого денойза ожидается спад от высокой сигмы к низкой, но точное правило определяет конкретный сэмплер.

**Строка пустая или содержит только слова.** Выход будет пустым. `SamplerCustom` обращается к первой и последней сигме, поэтому такой список нельзя считать безопасным входом.

**В списке один элемент.** Он описывает ноль переходов между уровнями шума. Некоторые функции сэмплера вернут вход почти без итераций, другие могут ожидать как минимум пару значений; проверяйте выбранный алгоритм отдельно.

**Использована запятая как десятичный разделитель.** `0,5` читается как `0` и `5`. Для дробной части нужна точка: `0.5`.

**Значения скопированы из другого семейства моделей.** Сравните штатное расписание обеих моделей и их `sigma_max`. Одинаковое число не гарантирует одинакового этапа денойза.

**Числа введены в научной записи.** Перед запуском перепишите их обычной десятичной формой и проверьте фактический тензор.

## Производительность и внутреннее поведение

Разбор строки и создание небольшого тензора почти не влияют на время workflow. Работа растёт линейно с числом символов и найденных значений; веса модели не загружаются.

`torch.FloatTensor` создаёт новый CPU-тензор `float32`. При запуске сэмплера данные могут быть перенесены на нужное устройство вместе с остальной sampling-веткой. Исходная строка после разбора не нужна вычислению.

Число переходов обычно равно длине списка минус один. Длинная последовательность почти не усложняет саму `ManualSigmas`, но увеличивает работу большинства сэмплеров с фиксированным числом шагов. Адаптивные алгоритмы могут трактовать список иначе.

Нода не кэширует разбор отдельно и не исправляет дубликаты. Две соседние одинаковые сигмы остаются в расписании; их влияние зависит от реализации сэмплера.

## Совместимость, изменения и устаревание

Статья проверена для ComfyUI `0.32.0`, frontend `1.48.7`, модуля `comfy_extras.nodes_custom_sampler`. Runtime fingerprint: `sha256:e9fd707c890cb622e82d75a36ca7edff15b838b9d35c0dd09edb9b36a7a89217`.

Нода помечена `experimental = true`, не deprecated и не API node. В Node Replacement API 0.32.0 записи для неё нет. Поведение парсера зависит от точного регулярного выражения и должно перепроверяться после изменения исходного кода.

Embedded docs 0.5.9 верно описывают извлечение чисел из строки, но не предупреждают о научной записи, нескольких точках, пустом результате, порядке сигм и конечном нуле.
