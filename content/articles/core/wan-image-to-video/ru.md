# Wan: подготовка видео по изображению

Подготавливает положительные и отрицательные условия и пустой видеолатент для локальной Wan image-to-video. Не загружает модель и не выполняет генерацию: три выхода подключаются к совместимому сэмплеру, затем результат декодируется VAE.

## Стартовые кадры и размер

Подайте `positive`, `negative`, совместимый `vae`, размеры, `length` и `batch_size`. `length` задаёт число кадров, не секунды; частота кадров определяется при сборке видео. Пустой латент имеет форму `[batch_size,16,((length-1)//4)+1,height//8,width//8]`.

`start_image` принимает последовательность кадров: они обрезаются до `length`, масштабируются с центральной обрезкой и ставятся в начало заготовки. Остальные кадры по умолчанию серые. Эта заготовка целиком кодируется VAE; условия `concat_latent_image` и `concat_mask` добавляются к обеим текстовым ветвям. Маска стартовых позиций находится в условиях, а не в `noise_mask` выходного латента.

## Новый опорный кадр

В ComfyUI 0.38.0 добавлен `ref_pad_image`. Его первый кадр заполняет оставшиеся позиции вместо серого фона и помогает поддерживать идентичность в моделях вроде ID-V2V. Маска этих позиций не обнуляется: это опора, а не жёсткая фиксация каждого будущего кадра. Без `start_image` этот вход не используется.

`clip_vision_output`, если подключён, записывается в обе ветви условий независимо от наличия стартового изображения. Его совместимость с моделью нужно проверить отдельно.

## Пример и ограничения

Начните с одного стартового кадра, размеров 832×480, 81 кадра и пакета 1. Это исходные значения для проверки соединений, не универсальная рекомендация модели. Несколько входных изображений занимают последовательные моменты времени, а не независимые элементы пакета. Большие размеры и длина требуют памяти для заготовки и её кодирования.

## Входы и настройки

Снимок ComfyUI 0.38.0. Условные поля показаны вместе с режимом, в котором они доступны; список установленных моделей зависит от вашей системы.

| Вход | Тип | Обязательный | Значения из схемы |
| --- | --- | --- | --- |
| `positive` | `CONDITIONING` | да | соединение / значение без фиксированного default |
| `negative` | `CONDITIONING` | да | соединение / значение без фиксированного default |
| `vae` | `VAE` | да | соединение / значение без фиксированного default |
| `width` | `INT` | да | по умолчанию: 832; минимум: 16; максимум: 16384; шаг: 16 |
| `height` | `INT` | да | по умолчанию: 480; минимум: 16; максимум: 16384; шаг: 16 |
| `length` | `INT` | да | по умолчанию: 81; минимум: 1; максимум: 16384; шаг: 4 |
| `batch_size` | `INT` | да | по умолчанию: 1; минимум: 1; максимум: 4096 |
| `clip_vision_output` | `CLIP_VISION_OUTPUT` | нет | соединение / значение без фиксированного default |
| `start_image` | `IMAGE` | нет | соединение / значение без фиксированного default |
| `ref_pad_image` | `IMAGE` | нет | соединение / значение без фиксированного default |

## Выходы

## Источники и границы проверки

[Реализация ComfyUI 0.38.0](https://github.com/Comfy-Org/ComfyUI/blob/6b747c0428c343e1417219641db93a4fb7cb69ae/comfy_extras/nodes_wan.py#L18-L67). Входы и выходы сверены с чистой установкой от 3 октября. Полная генерация с весами не выполнялась; человеческое утверждение ещё нужно.

## Официальные примеры подключения

`image_chrono_edit_14B.json`, подграф «Chrono Image Edit»: входы от `CLIPTextEncode`, `CLIPVisionEncode`, `SubgraphInput`, `VAELoader`; выходы к `KSampler`.

`image_to_video_wan.json`, подграф «main»: входы от `CLIPTextEncode`, `CLIPVisionEncode`, `LoadImage`, `VAELoader`; выходы к `KSampler`.

Шаблоны из [официального пакета 0.1.96](https://pypi.org/project/comfyui-workflow-templates-json/0.1.96/), закреплённого ComfyUI 0.38.0. Это сохранённые соединения, не отчёт о запуске. Внешние входы и переключатели подграфа могут менять значения и путь выполнения. `SubgraphInput` и `SubgraphOutput` обозначают границы подграфа.
