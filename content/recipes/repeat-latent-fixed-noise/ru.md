# Повторить LATENT и зафиксировать индекс шума

Fragment сначала увеличивает LATENT-батч в четыре раза, затем выставляет один `batch_index` для всего результата. Такой порядок нужен, чтобы `RepeatLatentBatch` не разнёс уже зафиксированные индексы по смещённым блокам.

## Подключение

Передайте исходный `LATENT` во вход `latent`. `RepeatLatentBatch` с `amount = 4` создаст четыре полных блока исходного порядка. Затем `LatentBatchSeedBehavior` в режиме `fixed` возьмёт первый существующий индекс либо `0` и повторит его для всей итоговой batch-оси.

Подключите выход второй ноды к sampler. Seed задаётся в sampler отдельно: fragment его не меняет и не навязывает модельные параметры.

## Что даёт fixed

Одинаковые `batch_index` заставляют стандартный путь `prepare_noise` выбирать один и тот же начальный шум для всех элементов. Это удобно для сравнения разных conditioning при общей шумовой основе. Одинаковый шум не делает финальные результаты одинаковыми, если различаются исходные latent, conditioning или маски.

## Статус проверки

Классы, точные combo/int-значения и связь `LATENT → samples` проверены по runtime 0.32.0 и исходникам. Fragment прошёл schema/runtime validation, но не исполнялся. В 512 JSON официального workflow-пакета 0.1.42 обе ноды отсутствуют, поэтому full workflow не придуман и не приложен.

При больших входных батчах учитывайте память: `amount = 4` физически создаёт четыре копии `samples`, а последующий sampler обрабатывает весь увеличенный batch.
